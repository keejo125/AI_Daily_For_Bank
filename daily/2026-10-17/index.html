AI 智能体三周重构 30 万行代码，Code Health 从 5.6 升至 10.0：代码真的变好了吗？
InfoQ
CodeScene 发布案例研究：编码智能体在三周内重构了一个 30 万行 C 语言代码库（源自《街头霸王 III》开源反编译项目），产生 2903 次提交、修改 25.2 万行，将 Code Health 从 5.6 升至 10.0，token 成本约 4000 美元。两项机制支撑：CodeHealth MCP Server 提供确定性评分作为质量信号，回放轨迹测试框架逐帧比对哈希以保正确性。团队主要用 Claude Opus 完成（较 Codex+Sol 更擅长识别与记录模式），并积累出 22 个重构方案、82 条说明。作者坦言 4000 美元与三周为实测，而缺陷减 70%、token 浪费减 45% 仅为推算。
Agent 删库频频发生，几十年前就有的数据库防呆机制不管用了？
InfoQ
针对频发的 AI Agent 删库事故，卡内基梅隆大学教授、ClickHouse 研究副总裁 Andy Pavlo 在播客中指出：这并非新问题，而是权限与管控手段几十年前就已存在却被忽视——只急着让 Agent 干活，忘了先问干错了怎么办。他建议把 Agent 当学步小孩，用权限隔离、分支沙箱防其误删生产库，而非逐个点批准。他还判断向量数据库护城河不深（一年内各家都会有）、现成 text-to-SQL 准确率仅约 60%（某大银行投入数百万美元才提到 99.5%），并认为 LLM 15 分钟能给出足够好的调参结果。
Akka 在 65 个开源项目中测试基于规格的 AI 交付
InfoQ
Akka 利用 65 个开源项目，对一种基于规格说明的 AI 辅助软件移植工作流做了实测：先用 Claude 配合 Akka Specify 分析代码、模型、模式并生成结构化规格，再实现、测试、审查，最后用通用基准运行器比对测试、代码规模与延迟。首轮耗时 99.3 小时、消耗 94.1 亿 token；65 个项目中 57 个在代码行数或性能上提升。发现：含声明、证据、类型化行为的规格能改善首次实现；Sonnet 平均每项 61 分钟、Opus 120 分钟但 token 少约 40%；较小模型更严守规范，较大模型可能即兴发挥。
Perplexity 开源 SPACE：面向 AI 智能体的隔离沙箱
MarkTechPost
Perplexity 开源了驱动 Perplexity Computer 每一任务的沙箱平台 SPACE（Sandboxed Platform for Agentic Code Execution），以 Apache 2.0 发布于 GitHub。SPACE 为每个 Agent 任务分配一个 Firecracker 微虚拟机（独立 guest 内核），凭证与出站流量由 VM 外部的网关管控，密钥从不进入 guest，为构建编码与浏览类 Agent 的团队提供可自托管的、经生产验证的隔离层。生产中沙箱创建中位延迟由 185ms 降至 60ms；在 9 个前沿模型上，108 次 VM 逃逸尝试 0 成功。
利用 AI 代码智能体优化软件架构的五种方法
InfoQ
文章总结用 AI 编码智能体改进软件架构的五条实用经验：一是梳理遗留服务，让智能体记录数据流、扫描代码并识别风险；二是发现与修复架构缺陷，须由熟悉架构的成员以具体、可衡量的质量属性需求（QAR）与权衡方案引导；三是借助智能体做安全审计，扫描漏洞并生成补丁（合并前须人工评审）；四是为开发提供架构基础，用 Markdown 固化 QAR、规范与约束；五是生成可测试的最小可行架构（MVA）。核心观点：AI 让写代码变简单，但显式定义与实测需求反而更难、更关键。
