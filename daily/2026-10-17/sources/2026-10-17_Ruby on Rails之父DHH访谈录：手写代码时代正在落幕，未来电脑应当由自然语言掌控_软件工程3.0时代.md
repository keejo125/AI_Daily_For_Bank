# Ruby on Rails之父DHH访谈录：手写代码时代正在落幕，未来电脑应当由自然语言掌控

来源：软件工程3.0时代
原文链接：https://mp.weixin.qq.com/s/7tGIhVWbt_v2wRAPf6wrSQ

（内容来源于GOSIM Shenzhen 2026 David Heinemeier Hansson（DHH）的现场访谈记录，靠豆包、DeepSeek录音整理，不足之处请指正）
David Heinemeier Hansson（业内简称DHH）：
Ruby on Rails Web开发框架创始人；
37signals联合创始人、CTO，打造Basecamp、HEY邮件等知名产品；
全新Agent原生Linux发行版
Omarchy
的创造者；
Omacom Foundation
发起人，基金会获得2370万美元认捐，用于保障Omarchy项目长期永续发展；
畅销书作家、赛车手，2026年GOSIM深圳大会重磅嘉宾，发表《Omarchy：Beautiful, Fun & Agentic Linux》主旨演讲。
DHH访谈核心观点
2026是Linux桌面元年
：过去Linux在服务器、嵌入式大获成功，但桌面长期困于5%市场份额；AI Agent补齐Linux最大短板，完全有机会超越Mac、抗衡Windows。Windows只是外挂Copilot表层AI，Agent时代需要AI深度原生嵌入操作系统。
Agent普惠计算，打破技术特权
：过往编程技术门槛高，只有技术高手才能受益；Agent只需要自然语言，普通人就可以修改系统、制作软件、修复Bug；小语种同样拥有良好效果，这是大模型的泛化能力。即便AI不再迭代升级，现有能力也会带来未来十年软件大爆发。
“放下铅笔(Pencil‑down)”新编程范式
：不再把人类手写全部生产代码作为默认；人类聚焦愿景、审美、方向、验收；Agent承担大量编码实现。可以采用多Agent同行评审：1个Agent写代码，2个Agent负责评审，极大提升产出质量。但开发者依然要掌握底层基础认知，不能完全一无所知。
Omarchy产品哲学：先成就自我，再惠及大众
：系统出厂默认配置是DHH心中的完美电脑；创作逻辑是
先做让自己满意的系统，再提供Agent工具，让每一个用户改造成属于自己的完美电脑
，而不是试图做满足所有人的万能系统。为了普通用户体验，主动放弃自己喜爱的Caps Lock自定义丹麦字符的个性化默认设置。
开源范式已经被AI彻底改变
：传统开源必须说服维护者，代码才能合并上游主线。AI时代不必强求所有修改并入上游。提交上游只是可选动作，合并不成功也没关系，社区更像互相交换礼物。用户无需任何人许可，直接修改、开发、分发软件，这是开源最大力量。批判苹果App Store的账号、年费、审核机制扼杀小众创意。
基金会解决单人开源项目短命痛点
：大量Linux个人发行版兴起快消亡快；成立Omacom基金会，持有商标、资金、基础设施，脱离个人，保障项目永续，让贡献者相信自己投入的时间不会白费。
看好中国市场
：中国是全球对Agent热情最高、投入最深的地区，站在下一代操作系统发展前沿；中国拥有顶尖硬件制造实力，不该被老旧Windows架构束缚。
Agent有明显短板，信任需要逐步建立
：会出现小题大做，修复微小边界case生成数千行冗余代码；Agent架构能力很强，但审美、细节把控依旧需要人类。对Agent的信任如同招聘新程序员，需要长期观察交付质量，循序渐进建立。
生态目标：争取商业厂商迁移
：主动联系微软CEO希望Office登陆Linux，持续游说Epic把游戏带到Linux；开放平台符合包括商业巨头在内所有人长远利益。

我们拥有机械师、工程师、车手，但是所有这些人，只有协同一体才能成事。如果只是一堆独立个体，没有清晰目标，各自往截然不同的方向使劲，这事就成不了。一支赛车队，如果工程师不清楚维修师在干什么、车手又不听指挥，那一定赢不了比赛。从这个角度来说，这本质上就是一项团队运动。团队里既有人，也有很多智能主体（agents）参与其中。
总的来说开源，我们能做成这一切，唯一的原因就是有这么多开源软件包和平台可以作为基础来搭建。就算是亿万富翁，也负担不起从零开始开发一套操作系统。我甚至不确定埃隆・马斯克能否承担 Linux 所耗费的全部人力工时。数万开发者历时三十多年的开发，四千万行代码。这样的成果，只有开源模式才能实现。但有意思的是，马斯克能用 Linux，一名普通学生也能用 Linux。我们可以使用完全一样的工具。这真的非常了不起，太震撼了。
当新进展出现、让我们感到意外时，我们完全可以改变想法，不必固守过去的观点，不必被旧思路乃至旧的工作方式困住。
最早，作为一名程序员，我非常震撼：计算机居然能写出和我水平相当的代码。没过多久，我就变得无比兴奋。我不只是企业经营者，本身也热爱开发软件，脑子里想法很多，但时间永远不够用。突然间，我反倒快要“想法不够用了”：我所有的构想都能够落地。那些原本想着或许某天才能做出来的软件，现在当天就能实现。
直到现在，这件事依然让我惊叹：每当我构思一款新应用，只需要写一段提示词，就能生成可运行的代码。它不会一开始就尽善尽美，但一直在持续变好。
这种兴奋来自方方面面。我和计算机打了四十年交道，能亲眼看见机器做到这些，实在震撼，至今感觉像魔法。理论上我明白模型权重、训练流程这些原理，但从情感上，我还是很难完全接受：我们竟然让计算机拥有了一种过去四十年从未见过的思考方式。
当然，作为经营者，这也非常了不起。并不是说我要裁减人手，而是我们开发的程序能承载更多能力，我们可以把目标定得更大，去挑战规模更大的项目。
我们眼下就在做一个项目：把我们的邮件服务 Hey.com 从网页应用改造为原生应用，一共要开发六款全新原生客户端。放在过去，这根本不可能实现。我们得招聘大量人员，这个项目根本不会启动。而现在，智能agent开始真正发挥作用了。
去年我分享过一件亲身小事：当我用 AI 帮我写代码的时候，我自身学到的东西变少了。当时我正在做操作系统，要写大量 Bash 脚本，但我在学习上有点偷懒。我只会反复问 AI “这段该怎么写”。我把 Ruby 代码丢给它，它就返回给我 Bash 脚本。
到某个节点我停下来反思：这样不对。我应该学好 Bash。如果我要制作 Linux 发行版，Bash 是你必须吃透的基础入门层。
我认为我们必须找到一种方式：就算智能agent可以帮我们写出全部代码，我们依然要弄懂它产出的东西背后的原理。就像乘法口诀：计算器能算出 5×5，但人自己心里也得算得出 5×5。
在智能agent时代，我们也必须拥有同等层级的系统认知。如果你完全不懂计算机如何运行、软件是什么、软件怎么构建，迟早会踩大坑。而且只要掌握这套底层认知，作为软件开发者，你的效率会高得多。智能agent就算没有这份理解也能产出代码，但我希望自己具备相应能力，希望弄懂背后逻辑。我不需要掌握所有细节，但必须清楚整体框架，明白各个模块之间的边界划分。
所以这套底层能力不会消失。恰恰相反，会有更多人需要建立计算机基础认知，看得懂智能agent为我们构建出来的东西。就像人人都得心算得出 5×5；当然不是所有人都要会数学证明，那只是少数人的事。在软件领域，未来大概率也会是类似的局面。
AI生成的代码性能几乎可以媲美汇编版本。这件事清晰揭示一点：智能agent几乎什么代码都能写。过去有一种误解：只要某个内容不在训练数据里，智能agent就做不好。这个看法已经过时了。依托泛化能力，现在的智能agent非常强大。AI学到的所有编写优质 Python、Rust 代码的能力，可以迁移用来写出高质量汇编代码，甚至机器码。
可移植性在过去是重中之重。这也是我们使用 C 语言、Rust 语言的根本原因：我们希望代码能跨不同 CPU 运行。但如果智能agent可以直接针对每一款 CPU 单独生成代码，那可移植性还是个问题吗？
这和我们开发 Hey 原生客户端的感受一模一样。以前，维护六套原生 App，需要一支庞大的团队。但现在，智能agent完全不介意重复做六遍相同的工作。所以，未来的编程范式或许会更贴近机器码，而不是追求可移植代码。因为针对一款新 CPU 重新写一套实现，对 AI 来说几乎没有额外成本。
我认为我们现在处在一个很奇妙的阶段：所有人都急于找到最终形态，想搞清楚未来编程究竟是什么样子。但我们反倒应该继续保持试验，再多享受一段时间这种无序探索的状态。
我想到了一个比喻，这是我对考试的记忆：你拥有固定时长，时间一到计时器就停下。考卷上还有一大堆想写完的内容，但时间已经耗尽。你显然不能继续写下去。如果铃响交卷时限到了，你还在不停填答案，大概率会被逐出考场，这么做行不通。你必须接受，这个阶段已经结束。
不知道为什么，我很快就接受了这件事。当我发现智能agent写出的代码质量和我不相上下，速度却是我的百倍、千倍时，我心甘情愿放下手中的铅笔，也就是我们所说的
Pencils down（放下铅笔）
。这点连我自己都感到意外。去年我和 Lex Fridman对话时，我还说过，我宁愿退休，也不愿放弃编程。那时候我以为，和智能agent协作，就像做传统的项目经理。
但真正开始和 Agent 一起工作后我才意识到，完全不是一回事。更像是和同事协作——是你所能遇到最聪明的一批同事，工作速度惊人。你有时会和它们意见相左，但没关系，你可以纠正它们。它们不会生气，会回应：“啊抱歉，这点您说得对”，然后修改代码，直到产出结果让你满意。
所以对我来说，能够接受“放下铅笔”，是因为我收获了另一种新体验。如果当初有人只是告诉我：以后你不用写代码了，只能做传统那种项目经理。那我会直接说：行，我退休，去种土豆，干点别的。
真正具备智能agent能力的操作系统：它该如何在强大的默认行为，和用户重塑、掌控这台设备的自主权之间找到平衡？软件开发者的使命，就是打造开箱即用、立刻就能发挥价值的系统。
说到 Ruby on Rails，我第一次接触这个框架，是看一段 15 分钟的视频，视频里搭建出了一个博客。2005 年那时候，大家根本不敢相信，只用 15 分钟就能搭建一套系统。绝大多数开发环境，你得花数小时，甚至好几天，光是做配置、搭环境，之后才能正式开工。而我完全没有耐心等这么久。我脑子里冒出想法，就希望立刻动手，马上看到成果投入使用。
所以 Ruby on Rails 的设计就是朝着这个目标优化：怎么搭建一套系统，让人 15 分钟做出博客，或是用差不多的时间就能启动自己真正的软件项目。
搭建操作系统也是同一个道理。我一直很喜欢 Linux，但 Linux 的设计初衷并不是快速上手。它把大大小小全部可调参数交给程序员，让每个人都能打造属于自己的定制系统。代价就是，你要投入几十、上百小时，逐项配置各种细节，才能得到一套美观又好用的完整系统。
看这些配置成果，不得不承认确实很漂亮。我很喜欢大家所说的 Linux Rice 文化——用户自己定制界面、设计桌面。但我无法接受一件事：每次新装一台电脑，都要耗费几十个小时做配置。
我特别喜欢电脑，每周都会买一台，家里现在就有 30 台。我一直痴迷计算机，经常重装、搭建新机器。我不想每台新机都花大量时间配置环境。
所以我想要一套系统：安装完成后，直接就是我理想状态下的电脑。最初目标是 5 分钟装好。我当时心想，如果能做到 5 分钟，那就太厉害了。等实现 5 分钟之后，我又想，能不能压缩到 2 分钟。等到实现 2 分钟，我以为这已经是极限了。现在，最快的机型完成全套安装只需要 35 秒。从填完配置信息，到安装全部结束，就是这么长时间。我们实验室正在开发的下一版本，最快只需要 9 秒。
对一部分人来说，这套默认系统就足够用了。但另一些人拿到之后会说：我想改一改，我想调整各种设置。这正是智能agent发挥作用的地方。长期以来，想要玩转 Linux，你得是资深极客才行。但有了智能agent之后，它可以操作命令行、修改配置文件、解读那些晦涩难懂的报错信息，帮你搭建出理想的系统。而你只需要用语言跟它沟通就行。
我曾经把大小写锁定键（Caps Lock）设成修饰键，用来输入丹麦语特殊字符。后来我意识到，这么做不妥——因为我把 Caps Lock 原本的功能改掉了。所有安装这套系统的用户，按下 Caps Lock，它却不会正常切换大小写。
于是我想：好吧。这套系统 99% 是我心目中理想的样子，我愿意舍弃剩下这 1%。系统出厂默认不再修改 Caps Lock，用户如果有需要，可以自己去调整。拿掉这个自定义设置，我其实有点舍不得，但这就是拥有大规模用户社区需要付出的代价。现在已经有几十万人在使用 Omarchy 这套系统。
所以我也有一份责任：系统开箱之后，不能让用户完全摸不着头脑。但我希望守住一个理念：所有伟大的作品，源头都是创作者为自己打造的。
你去看任何艺术家、音乐家、创作者，问他们的创作准则是什么：首先，做出让自己满意的作品；之后再扩展、优化，让它也适合其他人使用。
但我很清楚，我不会试图把 Omarchy 做成一个能满足所有人全部需求的万能系统。我的思路永远是：先打造
我心中完美的电脑
，再提供带智能agent能力的工具，让你把它改造成
属于你自己的完美电脑
。
对于 Linux 而言，智能agent带来最振奋人心、最强大的改变就是：
当系统出故障时，普通人也有能力解决问题。
过去一旦出现系统 bug 或者报错信息，如果你不精通 Linux 各个子系统，Linux 用起来会非常不友好。而现在有了智能agent，你无需精通底层。第一，AI 会给你解释问题；第二，它可以直接修复问题。
我们在最新版 Omarchy Quadro 中内置了这项功能：配置好默认智能agent之后，如果电脑上任意软件崩溃，就会弹出一个小窗口，问你：是否要用 AI 诊断故障？你点确认后，系统会把全部崩溃日志交给 Agent，授予它访问系统全部信息的权限，由它定位故障根源。
我自己已经用它修复过不少 bug。软件崩溃，点一下按钮，Agent 运行一段时间后，就会告诉你代码的这一部分存在错误。它之所以能做到这件事，根源就是一切都是开源的：Agent 找到出问题的软件，从互联网下载源码，定位出错代码行，然后询问你：要不要提交一个 Pull Request（合并请求）。
我已经用这种方式提交了大量 PR。很多软件我之前几乎都没听说过，AI 写代码所用的编程语言我都不认识。
我在用的一个工具叫 Herder，用来管理多个智能agent，它是用 Rust 写的。再说一次：我不写 Rust，甚至不想读 Rust 代码。我大概已经通过 Agent，向 Herder 项目提交了 15 个被合并的 PR。我只需要简单描述：我希望功能改成这样，或者我发现了一个 bug、某个功能不正常，剩下的交给 Agent 完成。
所以在我看来，
2026 年就是 Linux 桌面端普及之年
。在 Agent 出现之前，很难让大多数普通人使用 Linux。门槛太高、太硬核，部署耗时太久。有了智能agent之后，系统安装速度极快，遇到任何故障都能修复。更棒的是：只要你觉得操作系统缺某个功能，或者希望某个行为做出改动，直接跟你的智能agent说就行。
这再次体现开源独有的力量。Windows 做不到这一点。如果你不喜欢开始菜单样式，或是微软设计的设置页面操作逻辑……
自从 Omarchy 最新版本发布以来，已经诞生了超过 5000 个插件应用。绝大部分插件的创作者并不是程序员，只是普通电脑用户。几乎没有插件是程序员手动编写的，全部由智能agent生成。
这就是我对当下这个时代如此激动的原因，也是我前面所说 “窗口已经打开” 的含义。如果去年我们就去和 Windows、Mac 竞争，这套系统只会停留在小众圈子，因为我们没有足够有吸引力的亮点。但今年，我们拿出了目前最激动人心的计算机系统：你用语言和它对话，它就随之改变；你输入提示词，它就能生成全新应用。Windows 和 Mac 做不到这点。在 Windows、Mac 上你无法获得这种体验，但在 Linux 上可以实现。
但有件事让我觉得有点遗憾：一部分老牌 Linux 社区的人并不喜欢 AI。我不知道缘由，但现状就是如此。他们抵触 AI，那我的想法就是：行，没关系。你们不做，那我来做。
这就是 Omarchy 的定位：基于 Linux，充分拥抱智能爆发，把智能agent嵌入操作系统的方方面面，为我们提供协助。现在就处在这样独特奇妙的局面：四十年来，我们让计算机实现的最震撼的能力，就体现在 Omarchy 身上。它是目前市面上唯一主张 AI 智能agent应当成为操作系统原生组成部分的系统。
AI 是我见过
第一项能同时赋能所有人
的技术。以往诞生的很多技术，只有精通计算机的人，才能充分发挥它的价值。即便是 Ruby on Rails——它帮很多人开发 Web 应用，但依然有门槛：你必须掌握基础编程，懂一大堆相关知识。
在我看来，智能agent或许是计算机史上最普惠的能力放大器。它把强大的技术能力交到普通人手里，唯一的要求就是：你能用自然语言讲清楚自己想要什么。你可以用英语、中文、丹麦语和它对话。它处理丹麦语的效果相当出色。丹麦语属于小语种，使用者只有 500 万人，但智能agent理解丹麦语的水平几乎和英语差不多。这就是
泛化能力
。
这项技术不再只是发达国家少数精英才能享用的工具。过去很多技术，要么需要雄厚资金，要么要求极高专业能力，普通人接触不到。这就是为什么我对那些尚未到来的可能性满怀期待。就算我们就停在当下：保持现有的 AI 能力、维持现在的使用成本，不再做任何技术突破。如果未来十年技术就维持当前水平，我们依然会迎来一场盛大的惊喜 —— 软件会迎来爆发式增长。
很多程序员暂时不敢把安全、架构这类核心工作交给Agent，主要是实战使用经验不足。AI迭代速度极快。如果今年 2 月你问我：你敢信任智能agent直接部署代码吗？我当时一定会说，绝对不行。在部署上线之前，我必须逐行审阅全部代码，才敢投入生产环境。而现在我的想法已经发生变化。
科学界有同行评审机制。有同事审阅成果，科学研究才会更严谨，软件质量也会更高。智能agent也是同一个道理。我现在的主要工作流是：
一个 Agent 负责编写实现代码，另外两个 Agent 负责代码评审
。由三个智能agent协作产出的新软件，就算达不到完美，也已经非常接近了。
这套工作流诞生才三个月。今年夏天，Fable、Opus 5、GLM 5.3 陆续推出之后，我才建立起这套模式。尤其是安全领域，技术迭代速度快得惊人。
所以我理解程序员很难跟上变化，就连我自己也追赶得很吃力。光是持续跟进新版本、新工具、新模型，几乎就要占掉一半工作量。
但我同样清楚：如果你每天都和它们协作，你必然会慢慢建立信任。现在模型能力已经很强，就像招了一位人类同事、一名员工。我职业生涯招过很多程序员，新人入职的前三周，我不会直接允许他们合并代码到生产环境。我会查看、逐行评审他们写的代码。等三到六个月，如果持续产出高质量成果，我才会信任他。
目前，依托智能agent校验循环机制，我能够发现 Agent 写出的代码错误。但我偶尔碰到一类问题：
代码体量不成比例
。我只是想修复一个很小的边界异常场景，结果 Agent 给出了 3000 行代码。我只能连忙叫停：不行不行，太多了。
这或许有一部分只是人类的固有思维顾虑。我会想：这 3000 行代码，如果未来十年都要持续维护，想想就头大。但也许这只是我作为血肉之躯的执念。智能agent可能根本不在乎维护成本，它只管完成任务。但就我个人而言，我还是坚持：小问题，就该有小巧的解决方案。
人们总在想：智能agent还有哪些做不了？觉得那就是人类安全区。比如：架构设计它们肯定不行，架构永远得由我们人类来做。但事实并非如此，智能agent做架构的能力其实相当不错。
我发现，想要最大限度发挥 Agent 的能力，保持一点 “天真” 反而会有帮助。我会刻意克制自己脑海里那些系统构建、性能优化的固有知识，不去强行引导它。
对 Agent 干预越少，提出越开放式的问题，得到的答案往往越好。
而且 Agent 甚至在审美、界面观感，乃至命名这类事情上，都能给出很聪明的想法。编程里我最喜欢的环节之一就是命名：给类、变量命名。Agent 也非常擅长这件事，词汇储备很丰富。
所以我现在很享受这种状态：放手让 Agent 去做那些它越来越擅长的事，不再执着于死死攥住软件开发的某一块阵地，心里想着：这块交给 Agent 也没问题。
我创立了 Omacom基金会，为 Omarchy 提供一个永久稳定的归属载体。有许许多多小型 Linux 发行版，开发者周末一时兴起开发出来，到下个月就消亡了。原因往往只是：由单个人开发，只为短期满足自己的需求。
从最开始，我就希望大家明白：Omarchy 不只是又一个普通 Linux 发行版。我们志在改变整个行业。我们要推广 Linux，不只是面向现有的 Linux 用户，还要吸引 Windows、Mac 用户转过来，并且长期坚持做下去。想要吸引大家参与进来，很大程度取决于一点：让参与者相信，自己投入的时间不会白白浪费。
我可以自己开发应用。系统开源、免费，我能在任何我想用的硬件上运行它。这才是更优秀的计算机系统。
在我看来，Linux 一直有一件很吊诡的事：在嵌入式设备、服务器，几乎所有计算机领域，Linux 都已经席卷全球，唯独桌面端例外。不少 Linux 圈子里的人觉得，现状就这样了，我们无能为力，桌面端市场份额永远就维持在 5%。
这种想法完全缺乏雄心。不是这样的。我们的规模可以超越 Mac，可以和 Windows 一较高下，而且这个过程会来得很快。当下智能agent带来的变革，正在重塑整个行业。
如果你能证明一项技术正在飞速进步，就会有越来越多人加入进来，所有人都愿意参与其中。Epic Games 就能被争取过来。我甚至写信给微软 CEO 萨提亚，跟他说：你们应该把 Microsoft Office 移植到 Linux。他目前还没有承诺，但我会持续劝说，直到他同意。因为我相信，拥有一个开放、免费的优质平台来承载这些创新，最终符合所有人的利益，包括微软自身。
这也是我来到这里、计划前往中国的原因。在我看来，中国是全球对智能agent投入最深、热情最高的国家，因此也站在下一代操作系统的前沿。
Windows 在中国市场占有率很高。但在我看来 Windows 并不好，它是一套落后的操作系统。中国拥有顶尖的计算机硬件，强大的制造能力。不要预装 Windows 浪费了这么好的硬件。应该装上更优秀、契合这个时代的系统。
智能agent时代，需要全新的操作系统，而不是比尔・盖茨 1995 年设计出来的那套东西。我们现在需要更好的系统，能够匹配我们未来的发展方向。而且这不只是 Copilot。它需要真正能帮用户解决实际问题、用户真正想要的 AI。
你也能看出来，一旦聊起这个话题，我可以滔滔不绝讲五个小时。
开源操作系统最棒之处在于：
你不需要申请许可
。不用写信来问我，能不能开发某个东西、能不能修改系统，直接动手就行。
Omarchy 生态里诞生的很多精彩成果，我都是等作者发布之后才知晓。对方告诉我：我为 Omarchy 做了这个东西。我会觉得很棒，事前完全不知情，不知道他一直在做这件作品。这就是开源的力量，也是开源终将胜出的原因。开源是更高效的协作模式，也是更高产的软件开发方式。
如果你得去求苹果：请问我能不能开发一款 App？能不能上架 App Store？这种机制会压制创造力，扼杀创新。很多想法人们会直接放弃：不值得折腾。只是一个临时灵感，不确定有没有价值。不想注册开发者账号，也不想每年付给苹果 99 美元，只为发布一个免费软件。
我本身就是个硬核极客，也很喜欢极客群体。但如果我们想要真正普及这套系统，还必须说服那些并非极客的普通人。我们要打动的，只是单纯想用一台好用电脑的人。
如果你在电脑上装好 Omarchy，展示给别人看：你见过这个吗？界面体验足够惊艳，对方就会产生兴趣：我也能装上用吗？尤其是系统开箱就能正常运行；万一遇到故障，你演示如何借助智能agent修复问题。
我发现一件事：当你向普通人展示，他们自己也能制作软件——这件事他们原本觉得根本不可能。他们会连忙摆手说：不行，我做不到。我不是程序员，也不是设计师。
然后你坐下来带着他们操作：你只需要跟智能agent说你的想法，我们就能做出这个应用。当他们亲眼看到成果活生生跑起来的时候，会大为震撼，再也不想换回别的电脑。
这就是最核心的用户转化方法：让用户亲身上手 Omarchy，把系统改成专属于自己的样子，实现过去很难做到、繁琐又难看的需求。一旦他们亲手完成这件事，就再也不愿回到旧系统。
我把系统默认配置设定成我心中理想电脑的样子。这样至少能保证：这套系统对一个人来说是好用的 —— 对我而言，它就是完美电脑。
我发现，如果一个作品让我自己用着感觉很棒，那说明我并不是特例。很多人会拥有和我相近的审美与使用偏好，他们同样会喜欢这套系统。但我同样认为，有了智能agent与 AI 加持之后，开源已经变得不一样了。
对我来说，这样就足够了。我也会把代码提交到上游主分支。如果项目维护者接纳，那很好；就算不接纳，也无关紧要。我们就像是在互相赠送礼物。你想用我的修改，直接拿去；我看中你的成果，我也拿来用。但并不要求所有改动都必须合并进主线。
这样就跳出了过去的瓶颈：你必须说服某个核心维护者，代码才能并入操作系统主线。未来会诞生大量定制化软件、定制化操作系统。每个人的系统都会略有差异，大家各自添加自己的小工具，也不再有必须把所有改动推送上游的压力。
所以不必等待任何人，不用等我，也不用等其他人。不用向任何人申请许可，直接动手去做，享受你亲手打造出来的这台电脑。
世界上有很多人对软件和服务有很好的想法，但他们要么没有技能，要么没有钱。现在，一个想法可以走得更远。我以前常说，“创意者”没有立足之地，因为如果你只有想法，既没钱又没技能，那这个想法能拿来干什么？但现在不一样了。如果你有一个好想法，组建自己的 agent 集群的门槛已经大幅降低，而且还在继续降低。我们现在拿到的一些最新模型几乎便宜到“无法计量”，这意味着任何真正有好想法的人都能把这家公司做起来。
我喜欢小团队。我更愿意和一两个人、两三个人一起工作，而不是和几百个人一起工作。但过去我们那样工作时，天花板很低。我们没法那么有野心，必须非常小心地把时间花在哪里。这就是我创建 Ruby on Rails 的原因——让单个程序员尽可能高效、高产。但现在，我们得到的是那个的一千倍。
更少的软件工程师去研究内核内部的具体细节，但总体上看，软件更多了，能力也更强了。
同时我们也要思考编程语言的取舍：用一种保护程序员、防止他们犯错的编程语言，比如Rust，可以规避缓冲区溢出、不安全代码。可如果 agent 变得非常聪明，不再需要人类设置的护栏呢？Rust这套取舍还是对的吗？C语言会不会重新变得有价值？C不是一种很安全的语言，很容易制造安全漏洞，但这些风险都建立在人类写代码的前提上。如果 agent 聪明得多，我们能不能走到那一步？Elon Musk曾经提出观点：未来我们甚至不会再用 C 写任何东西。一切都会变成机器码。如果我们能直接写机器码，为什么还要经过任何中间编程语言？我做过亲身试验：一个屏保程序，最初版本人类用Python写很多年。我用AI Agent，40分钟重写为Rust，速度提升10倍；继续优化做到快30倍；再让Agent转写汇编，不到一小时得到可用汇编版本，速度比原版快100倍。
做软件能把我在脑子里的每一个想法都“涡轮增压”式放大。我意识到，这正是我真正喜欢编程的地方。我也喜欢把代码敲出来，我喜欢 Ruby。但我更喜欢的，看到自己的想法从脑子里变成能工作的软件。以前，这可能要花几个月；有几次，我们做一个系统做了好几年。所以从有想法到看到最终软件，过程非常慢。现在，几乎我做的每个东西，我都能在几小时、有时几分钟内，把脑子里那个版本摆在眼前。这更让人满足。所以我拿自己真的很喜欢的一件事——手写 Ruby 代码——换来了更喜欢的一件事：快速做出好软件。
Omarchy 的 ISO 是 6GB。所以如果我能以完整的 NVMe Gen 5 速度传输，理论上不到一秒就能装完。好吧，也许不必做到一秒，但五秒会不错。这就是我的目标。今天我们有这么快得离谱的电脑，却有人要花一个小时装 Windows，这让我觉得不可理喻。把电脑做得这么慢，是对电脑的侮辱。我最早接触的电脑是 Commodore 64，它有 1MHz 的 CPU，一开机就立刻可用，带着 BASIC，你马上就能干活。你今天买一台新的 Windows 机器，拆开包装，45 分钟、1 小时 20 分钟——而这只是在安装一个本来就已经在电脑里的操作系统。怎么会这么慢？我简直是在替这些快速处理器抱不平：我们浪费了它们太多性能。
大多数软件在 Mac 上也是同样的工作方式。事实上，在 Mac 上更糟：如果你做了一个新软件，想分享给朋友，你得先求 Apple 批准。你得注册开发者账号，给应用签名，然后也许如果你运气好，他们才会允许你分发。这完全不可接受。没有任何程序员应该接受别人对自己创造的东西有这种控制权。我们需要自由开放的系统，让任何人都能创造任何软件。你可以用 Linux 做到。事实上，在Omarchy安装完成之后打开 agent 菜单，最底下写着“做点酷东西”，有一个按钮做 app，一个按钮做插件。agent 会问：“你想做什么？”你直接告诉它就行。我们给了它技能，给了它指令，给了它可以查看的代码库。
从大局来看，AI推理成本便宜得惊人。如果你看看一些开放权重模型，推理成本已经让几乎所有人都负担得起用这种方式做软件。这在整部计算机史上都很独特。过去的第一项创新总是非常昂贵：第一台电脑非常贵，第一块硬盘非常贵。而在这里，几乎所有人都能接触到同等质量的智能。我认为，这是计算领域有史以来最具民主化效应的范式转变。
信任是随着时间建立起来的：你看到模型正确运行、按你的意愿运行，才会信任它。而一旦你设置好验证组，这是另一个非常重要的部分。我的做法主要有两件事。第一是 agentic feedback loop，也就是 agent 反馈闭环。你需要自动化测试。你需要让 agent 能够检查自己的工作，并验证它做的事情是正确的。这非常重要。
先是在代码上获得反馈，然后我给出的另一种反馈是方向。这个该不该做成一个功能？它到底应该长什么样？agent 在审美上越来越好了，但在审美上还是不如它们在代码上那么强。所以我仍然发现，我得在它应该长什么样、应该包含什么、下一步该做什么上给出很多方向。但我得说，我现在把越来越多的这类事情也交给 agent 了。我经常问 agent 开放式问题：“现在对我们最有帮助、最该修的是什么？”也许是安全，也许是性能，也许是缺失的功能。它也很擅长给出很好的建议。
Omacom基金会持有商标，现在也有全职员工，我们从阿里云、Meta Superintelligence Labs等捐赠者那里拿到了 2370 万美元的认捐。我筹这笔钱，并不是因为我有一个需要 2370 万美元的完整计划。我筹这笔钱是为了发出一个信号——最重要的是向世界发出信号：这件事是认真的。这真的是 Linux 桌面之年，在二十多年之后。几十年来，Linux 圈子里一直有个笑话：“哦，今年是 Linux 桌面之年。”然后大家就笑。我不笑。我是极其认真的。今年就是 Linux 桌面之年。我们要让它发生。
我已经缠着 Epic Games 的 Tim Sweeney 三年了，让他把 Fortnite 带到 Linux 上。现在这件事正在发生。
到手时不需要请求许可——而我对请求许可这件事很过敏。我不想问任何人我的电脑应该是什么样。我想让我的电脑完全按照我想要的方式工作，装上我想要的应用。安装 Omarchy，自己调整它，然后告诉我你发现哪里不够好。让我们改进中文翻译。让我们确保在中国使用的每一个主要应用都已经在菜单里，而且容易安装。让我们降低进入门槛，让那些不像极客那样热爱电脑的普通人也能用。
以前我可以评估每一个贡献，因为做贡献非常难，所以PR数量不会很多。现在，仅仅过去八周，我们就收到了 5000 个 pull request。我不可能审 5000 个 PR。我用 agents 帮我找围绕我关心主题的请求，然后把它们归到一起。但我们必须摆脱这种观念：在开源里，一个贡献只有被合并进上游才有价值。因为想法会太多、请求会太多——不是你做的一切都能进入上游。
我认为当下，我们很难精准预判未来软件会演化成什么形态。我有一个观点：
如果要我亲手写、亲自读 Rust 代码，我实在不喜欢它；但如果是 AI 智能agent帮我写，我不用去读源码，那我就很喜欢 Rust。
所以我们需要去思考：当智能agent写代码的能力，达到人类的数百倍、甚至数千倍时，到底什么样的编程语言、配套库和框架才是最合适的？
同时要明白，token（令牌）效率依然有它的价值。就算智能agent可以从零生成大量代码，复用共享的程序库依旧能带来收益。但软件的整体形态一定会发生改变。有一点很明显：过去所有为
人类开发者
设计、优化的库和框架，对 AI 智能agent而言，优化方向完全不一样，因为二者的约束条件截然不同。
我职业生涯大部分时间深耕 Ruby on Rails，当时核心目标就是
让每一行代码发挥最大效能
。如果我一天只能写一百行代码，凭借 Rails，就能实现很棒的功能，做出很多东西。同样一百行 Rust 或者一百行 C 代码，能干的事情非常有限。想要实现同等功能，往往要数千行 Rust、数千行 C。而用 Ruby on Rails，一百行代码就能搭建一整个 Web 应用。
但这套逻辑，在 AI 时代不再是最重要的衡量标准。我们需要重新探索新范式。其实我本身挺喜欢 Rust，但我并不认为 Rust 就是编程语言的最终形态。
