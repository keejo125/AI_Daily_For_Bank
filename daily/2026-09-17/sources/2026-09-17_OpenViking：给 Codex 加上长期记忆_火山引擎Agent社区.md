# OpenViking：给 Codex 加上长期记忆

蓝字
关注我们！
你有没有过这种感觉：Agent 在同一个对话里表现得很聪明，可聊得越久，就越容易忘事。一旦换个窗口，之前聊过的背景、做过的判断，都要重新解释一遍，而如果换一个 Agent，过去积累的内容和经验，往往又要从头开始。
先看一个普通的工作场景。小 K 是客户成功经理，正在推进一份年度续约。培训要安排，安全材料要提交，法务评审人还没完全对上。这些信息散落在会议记录、项目文档和每天的更新消息里。在当前对话中，Codex 可以帮她整理方案、写沟通要点。真正麻烦的是，过段时间换一个窗口或换了 Agent，她又要重新解释客户是谁，合同走到哪一步，哪些已经确认，哪些还只是意向。
小 K 需要的是让 Codex 能在新任务开始时快速找到相关的历史信息，接着已有进度继续工作，而不是每次都从零开始。
OpenViking 则为不同 Agent 提供了一层统一的长期记忆。它可以集中保存项目资料、历史信息、用户偏好和工作经验，并在新任务开始时，根据当前问题快速检索最相关的上下文，让跨会话、跨 Agent 的记忆不再从零开始。
01
OpenViking 能做什么
OpenViking 是面向 AI Agent 的统一上下文数据库。
它把 Agent 工作时需要的 Context 分成三类：项目材料作为 Resource 保存，个人偏好、历史经验沉淀为
Memory
，可重复使用的工作方法组织为
Skill
。这些内容被统一抽象成系统中的目录和文件，每一项都有可以定位和追溯的路径。
面对一个新任务，Codex 不需要把所有历史内容一次性塞进上下文。它可以先读取
L0 摘要
，快速判断哪些目录可能相关；再查看
L1 概览
，了解项目的关键背景和当前状态；只有真正需要核对细节时，才按需加载
L2 完整内容
。
OpenViking 还会把一次任务中的真实执行过程继续沉淀为经验。任务结束后，Session Commit 可以从对话和工具执行过程中提取值得长期保留的内容，并写回 Memory。这个过程主要处理三个对象：
Session：
包括用户提出了什么、Agent 如何回应、调用了哪些工具，以及工具返回了什么，为后续追溯提供真实依据。
Trajectory：
在 Session 的基础上，梳理这次任务的目标、关键步骤、执行选择和最终结果。
Experience：
进一步从一个或多个 Trajectory 中提炼可复用的方法，让 Agent 在遇到相似任务时，知道“哪些做法有效、哪些问题需要提前规避”。
OpenViking 保存的不仅仅是发了什么，还包括怎么做的经验和可复用的方法。

03
使用长期记忆，从这三件事开始
1. 记忆存储：同步 Codex 历史
使用建议：
在首次接入 OpenViking 后，可以将 Codex 中所有的会话和历史任务进行同步，并提炼成可复用的经验和偏好。
小 K 先新建了一个对话，让 Codex 读取当前可访问的历史记录，OpenViking 会进行逐一确认，把原始内容存入到 OpenViking ，再提炼出长期有效的偏好、重要决定和待办等。
操作示例：
在 Codex 新建任务，粘贴并发送 Prompt
读取当前可以访问的 Codex 历史任务、对话、项目和产物，将原始内容归档到 OpenViking，并提炼长期有效的偏好、目标、项目进展、重要决定和待办。自动分批、去重，不保存凭证或敏感信息。完成后告诉我同步范围、成功数量、失败项和可能遗漏的内容。
在新任务中发送历史同步指令
历史内容同步到 OpenViking
同步完成后，小 K 想检验一下是否可以看到历史任务的内容，于是她在新聊天框内，询问续约目前处于什么阶段，哪些事情不能写成已确认的结果，回答末尾明确说明“使用了 OpenViking 进行作答”，并给出了来源路径和内容摘要。
询问目前所处的阶段进展
2. 定时任务：创建今日关键推进
使用建议：
适合在第一步同步历史后使用。Codex 每天会结合 OpenViking 中存储的项目最新进展，团队角色和职责分工，判断哪些是需要你本人介入的关键事项，哪些可以交给团队内对应负责人处理。
对小 K 来说，每天早上最需要的是知道今天该找谁、推动什么。定时任务会结合她与法务、客户接口人等角色的协作关系，筛出真正需要她推动的事项，帮助其快速确认今天最需要关注的是什么，并整理出待办事项的优先级，开启一天的高效工作。
操作示例：
在 Codex 新建任务，粘贴并发送 Prompt
创建一个每天上午 9 点运行的定时任务，生成“今日关键推进与管理关注”，创建后立即试跑一次。
创建前，先从 OpenViking 读取我的角色、责任范围、当前目标、关键项目、决策权限、团队关系和工作偏好。如果信息不足以判断我的关注重点，先向我询问并完善，不要直接创建任务。
每天执行时，读取昨天的新进展、关键决定、风险、阻塞和未完成事项，并结合最近一至四周的项目状态及当前目标进行判断。昨天的记录只作为变化信号，不是待办事项的唯一来源。
根据我的角色调整关注层级：
-
执行者关注交付和依赖；
-
项目负责人关注里程碑和跨团队阻塞；
-
团队负责人关注团队结果、人员、资源和风险；
-
业务负责人关注业务目标、客户价值、关键决策和资源配置。
只保留同时满足以下条件的事项：
-
与当前目标或关键项目直接相关；
-
今天推进具有明确价值，延迟会产生实际影响；
-
确实需要我决策、推动、协调、委派或知情。
过滤日常维护、已完成且没有重要后续的事项、可由责任人独立处理的细节，以及与当前目标无关的零散记录。
每天最多输出 3 项，每项说明：
1.
需要关注或推动什么；
2.
为什么今天重要；
3.
今天希望取得什么结果；
4.
最佳介入方式：决策、推动、协调、委派或知情；
5.
判断依据和 OpenViking 来源，并区分事实与推断。
如果没有达到门槛的事项，直接说明“今天没有需要你特别介入的高优先级事项”，不要强行生成内容。
创建定时任务，了解每天需要关注的重要事项
OpenViking 对每天的事项进行存储
3. 生成个人周报
使用建议：
适合已经积累本周工作记录、准备固定时间汇报时使用。提前保存汇报对象、周报格式和表达偏好，再让 Codex 按最新状态整理成果、风险和下周计划。
到了周日，小 K 要生成个人工作周报，同步本周进展，当她打开 Codex 时，却发现本周的额度用完了，但小 K 丝毫不慌，因为所有的工作内容都已经存储在了 OpenViking 中，她将 OpenViking 接入 Trae，成功调用了本周工作内容记忆，并根据存储的周报格式进行生成。
操作示例：
在 Trae 新建任务，粘贴并发送 Prompt
创建一个每周日晚上 7 点运行的定时任务，根据 OpenViking 中保存的用户信息和本周工作记录，生成一份可以直接发送给领导、团队或合作方的周报。创建后立即试跑一次。
生成前，在后台完成以下工作：
1.
从 OpenViking 读取用户的角色、责任范围、当前目标、重点项目、协作关系和汇报对象。
2.
读取用户保存的周报模板，以及语言、语气、篇幅、关注重点和表达习惯。
3.
检索全部相关工作空间中本周的成果、状态变化、关键决定、指标变化、客户进展、风险和遗留问题，并参考最近一至四周的目标和项目背景。
4.
不得用当前对话或当前工作区限制检索范围，也不得因为某个项目记录更多就默认它更重要。
5.
根据用户实际承担的责任，判断周报应围绕单项工作、一个项目、多个项目、团队还是业务组合展开。
6.
以最新、证据最完整的记录为准，过滤归档、配置、日志、普通升级及其他不值得汇报的执行细节。
以上过程仅用于后台判断，不得写入周报正文。
优先使用 OpenViking 中保存的周报格式。如果没有明确模板，默认采用以下结构：
一、本周进展
选择最重要的 3—5 项结果，说明发生了什么实质变化、取得了什么结果或到达什么阶段，以及对目标、客户、团队或业务的意义。不要按日期罗列过程，不使用“持续推进、完成相关工作、进行了优化”等空泛表述。研究、讨论和原型必须准确标明阶段，不得包装成已经落地的成果。
二、问题与风险
只写会影响目标、进度、客户、质量、资源或协作的问题，说明问题、影响及下一步需要解决、协调或决定的事项。不要把普通维护写成业务风险，也不要只描述问题而不给出处理方向。
三、下周计划
围绕下周要取得的结果来写，不要罗列零散 Todo。每项说明预期结果、它对应的本周目标或风险，以及判断完成的标准。
根据用户角色调整表达层级：执行者关注交付；项目负责人关注里程碑和依赖；团队负责人关注团队结果、人员和资源；业务负责人关注业务目标、客户价值、关键决策和资源配置。
写作要求：
-
遵循用户保存的语言、格式、篇幅和表达偏好；
-
简洁、自然、专业，可以直接发送；
-
优先使用具体结果、数字、客户和里程碑；
-
不夸大成果，不把计划写成进展，不编造缺失信息；
-
不为覆盖全部工作而罗列没有重要变化的事项；
-
默认不展示检索过程、OpenViking 路径、事实与推断标签、偏好说明或其他系统信息；
-
只有用户明确要求时，才在末尾简要附上来源。
完成初稿后，在后台以周报接收者的视角检查：
-
能否在一分钟内看懂本周成果；
-
最大风险、影响和需要推动的事项是否清楚；
-
下周计划是否与本周目标和风险衔接；
-
是否存在空话、流水账、重复、过期状态或未经证实的成果；
-
是否符合用户保存的周报偏好。
如有任一项不通过，修改后重新检查。不要展示审查过程，只输出检查通过的最终周报。
如果记录不足以生成可信周报，不得用零碎事项填充。首次试跑时询问缺少的关键信息；后续定时执行时，简要说明信息不足及需要补充的内容。
切换到 Trae 后也能继续调用记忆
周报生成要求自动沉淀，方便下次调用
04
OpenViking 企业版：让团队经验跟着业务走
对于企业团队，OpenViking 企业版可以让多个员工和 Agent 使用同一套企业知识，它作为一个共享记忆库，让团队经验能够跟着项目继续流转；同时拥有多租户能力，员工个人记忆和未授权资料会保持隔离。不论换人还是换 Agent，业务上下文都可以继续，个人的隐私的信息则不会进行公开。
小 K 在推进年度续约时，确认了一项特殊要求：北辰制造是公司的重点客户，已经通过审核的安全材料在有效期内不需要重复提交；续约时只需补充本次新增或发生变化的部分，并由固定的客户方法务评审人统一接收。
这类信息过去很容易只留在她的聊天记录里。小 K 知道，其他同事未必知道；换了负责人，客户又要重新解释一遍。现在，小 K 可以在确认信息和来源后，将这条客户规则保存到 OpenViking。
例如：北辰制造是重点客户。已通过审核的安全材料在有效期内无需重复提交，续约时只补充新增或变更内容，并交由客户指定的法务评审人统一处理。执行前需要核对协议原文和材料有效期。
几个月后，小 A 作为团队新人，需要接手北辰制造客户。她想了解之前的客户情况，不需要先找小 K 开会，也不用再次向客户确认同一个问题。Agent 会先从 OpenViking 中找到这条长期 Memory，再读取对应的记录，并给出处理建议。
这个时候，
客户经验不再只属于某个员工，而是成为团队可以持续复用的业务知识。
Agent 会继续变化，模型也会不断升级，这些固然重要，但OpenViking 补上的，是 Agent 长期缺失的一环：让真实工作中产生的进展、决策和经验，不再随着会话结束而消失。
接入 OpenViking，让每一次对话都能成为下一次任务的起点，形成可以跨对话、跨任务、跨 Agent 可复用的工作上下文。
