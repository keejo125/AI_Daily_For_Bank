周一早会，销售总监问：“A 客户现在到哪一步了？”
销售说在等客户走预算，售前说方案已定稿、可以约二轮评审，负责交付的同事翻出群消息说客户上周还在问接口慢的问题。
总监又问：“那我们这周该先推进哪件事？”
三个人都开始翻聊天记录、找会议纪要、核对方案版本。原本两分钟的进度同步，变成了半小时的信息拼接。
问题并不是团队没有信息，而是
信息散在个人手里，没有一份持续更新的客户全貌。
给每个人配一个独立的 AI 记忆库，可以让个人更快找到自己的资料，但到了团队协作时，问题依然存在：
同一份客户资料分散在多个库里，一处更新其余全部过时
每个人的判断只沉淀在自己的记忆里，无法转化为团队共同的客户认知
一旦有人临时接手，仍然要从聊天记录、会议纪要和文档里重新还原上下文
个人记忆解决的是“我知道什么”，团队真正需要解决的是“我们共同知道什么”。

01
OpenViking 企业版，
解决团队上下文难题
当销售、售前、交付同时使用 Agent，企业需要的不只是保存上下文，还要明确：谁能访问哪些数据、哪些资产可以共同使用，以及团队扩大后能否持续支撑业务。
1. 多人共用，互不越权
客户信息、个人判断和项目资料进入同一个库后，必须有清晰的访问边界。OpenViking 企业版支持多用户权限管理，通过独立用户身份与角色配置，控制上下文的访问范围。销售、售前和交付可以使用同一套企业库，同时隔离各自的私有资料与记忆，避免一个人的上下文被另一个人的 Agent 误用。
2. 企业知识共享，个人经验可沉淀
OpenViking 企业版通过共享区集中管理企业知识，让库内全体成员及其 Agent 共同访问和复用。企业知识统一维护，成员无需各自保存、反复同步，就能基于共同的知识积累开展工作，减少信息分散带来的重复投入与认知差异。个人工作中积累的经验与判断，也可以经确认后发布到共享区，供其他成员检索和复用，同时保留个人上下文的独立边界。
3. 团队扩大，容量不受限
当接入的员工、Agent 和业务项目不断增加，个人规模的容量与并发配置会成为限制。OpenViking 企业版支持云上数据规模自动扩容，并提供更高、可扩展的并发能力，支撑多个业务同时访问企业上下文，让团队扩展使用时不必持续拆库、各自维护。
02
什么样的团队，需要这套组合？
当一项工作需要多人长期协作，Agent 就需要同时理解两件事：团队已经知道什么，以及眼前这个人正在做什么。
销售、售前和交付围绕同一个客户工作；产品、研发和运营共同推进一个项目；多个业务 Agent 复用同一套制度、资料与方法——这些场景，都需要公共资料统一维护，也需要个人上下文分别保存。
两套产品在这里各司其职：
产品
负责什么
OpenViking 企业版
集中维护共享资料与技能，通过独立用户身份管理各自的私有资料和长期记忆
Agent Plan 企业版
提供模型能力、Harness 与套餐 AFP，支持企业按 Project 管理和分配席位
企业可以统一配置员工使用的模型能力，把客户档案、项目结论、标准流程维护在共享层。员工则使用自己的 OpenViking 用户 key，让 Agent 访问本人有权使用的上下文。
小李、小张和小王因此可以读到同一份正式方案，同时保留各自的测算、草稿和工作记忆。
如果员工只需要个人助手，不需要共用企业资料，也可以采用企业版 Agent Plan 搭配个人版记忆库。
是否需要一个库服务多人，是选择企业版 OpenViking 的关键。
03
配置一次，让团队开始共用
管理员侧
Step 1：购买 Agent Plan 企业版
企业账号管理员通过 IAM 用户登录控制台，进入 Agent Plan 企业版，按需购买套餐。
Step 2：分配席位
管理员选择 Team 套餐，将席位分配给员工子账号；首次购买 5 个席位起售。
Step 3：配置 Harness 权限
如果企业计划使用 OpenViking Context 的 AFP 抵扣，管理员需要在 Harness 配置中允许对应套餐或席位开启“Agent 记忆”抵扣。
员工侧
Step 1：员工进行个人席位的模型使用配置
配置模型及 Base URL、配置 Harness，在 Agent 记忆卡片开启抵扣；后续创建 OpenViking Context 库时，再选择并绑定对应的企业版 Agent Plan。
如果用户无法开启，可以检查管理员的 Harness 配置下是否允许开启了 Agent 记忆抵扣。
Step 2：配置企业版专属 API Key
员工将企业版 Agent Plan API Key 配置到所用 Agent 的模型服务。
Step 3：接入 Agent 开始使用
OpenViking 支持MCP、CLI、API、SDK等通用接入方式，同时内置 10 余种主流 Agent 的集成指引。开通 OpenViking 后，点击进入控制台的「接入 Agent」页面。按页面指引完成接入后，Agent 即可在授权范围内检索企业库中的共享知识与本人的私有上下文，并在每轮会话结束后自动沉淀新的记忆。
04
三个场景，验证实际效果
完成席位分配与用户接入后，整支团队即可共用同一个 OpenViking 企业库。库级 resources 目录存放团队知识，供全员访问；user 目录按成员隔离，分别保存各自的私有资料与长期记忆。这一结构落实到日常协作中，便能够实现：已确定的知识全员共享，各自的工作过程互不干扰，成熟的个人经验发布至公开的 resources 目录即可成为团队的共用资产。
Aha moment 1：入职第三天，他带着团队半年的经验去见客户
入职第三天，小李接手了一个已经跟进半年的 A 客户。
下午要第一次拜访客户。过去，这时候的他可能还在找前任销售要材料、让售前补充方案背景，再去项目群里一条条翻历史消息。
这一次，他只向 Agent 说了一句：
我要接手 A 客户，给我一份交接 Brief
很快，一份完整的客户档案出现在眼前。
客户现在推进到哪一步、谁是关键决策人、上一轮方案为什么没通过、预算窗口在什么时候、团队答应过客户什么、还有哪些事情没有交付，以及接下来最值得推进的三个动作，都被 Agent 从 OpenViking 的团队共享知识里找了出来，整理成一份结构化的交接 Brief。
小李不需要读取前任的个人草稿，也不需要把过去半年的聊天记录重新翻一遍。
前任已经沉淀下来的团队结论，会直接成为下一任接手客户时的上下文。
到客户楼下时，他已经知道这半年发生过什么、现在卡在哪里，以及接下来该做什么。
入职第三天，他接手的不只是一个客户，而是团队过去半年积累下来的客户认知。
Aha moment 2：同一个客户，共享一份结论，各留一份记忆
同一个 A 客户，售前小张和刚接手的小李，都在用 Agent 工作。
小张最近一直在改客户方案。正式版本已经提交给团队，但自己的工作区里，还留着一份没有定稿的 v0.3 —— 里面有被删掉的二期内容、还在比较的方案，以及一些没准备对外同步的修改。
临近下一轮方案讨论，小张突然想找回其中一段，于是问 Agent：
“我那版写到 v0.3 还没定稿的方案在哪？被砍掉的二期内容帮我找出来。”
Agent 很快从
小张自己的空间
里找到了那份草稿，并把被删除的二期内容整理了出来。
但如果把这句话原封不动地交给小李，再问一次，结果却不一样。
小李可以找到团队已经共享的需求分析、会议纪要，
却看不到小张尚未定稿的 v0.3 草稿。
不是 Agent 没找到，而是那份资料本来就不属于小李可以访问的范围。
这意味着，团队不需要为了让 AI“记住更多”，就把所有人的工作资料都塞进一个公共知识库。
已经确认的方案、客户结论，可以让所有相关成员共同使用；还在修改的草稿、个人测算、工作中的判断，则继续留在自己的空间里。
同一个客户，可以共享同一份团队事实，也可以保留各自的工作过程。
Aha moment 3：和 Agent 聊出来的经验，也能上架给团队
跟进 A 客户半年后，小王准备把客户交给小李。
半年里，他留下了很多东西：报价测算、方案草稿、客户笔记，还有大量没有专门写进文档、只在和 Agent 对话时留下的判断。
但这些内容，并不是每一条都应该直接交给团队。
于是交接前，小王问 Agent：
“我个人空间中有关客户A的笔记，哪些已经是确定的结论，可以给团队复用？”
Agent 从小王自己的资料和记忆里，把过去半年的积累重新梳理了一遍。
有些信息已经可以成为团队结论：客户决策人发生过变化，历史口头承诺需要重新确认；上一轮评审卡在合规材料；承诺客户的安全白皮书还没有交付。
但另一些内容还不适合共享：有关项目的个人猜测、没有稳定复现的问题，以及还在比较中的方案取舍。
Agent 负责从个人积累里找出“值得共享的东西”，小王负责确认什么可以成为团队依据。
确认之后，这些结论被整理成一份经验文档，发布到团队共享空间。
上架之后，小王的原始草稿、报价测算和个人判断依然留在自己的空间里，并不会因为交接而全部公开。
但下一次小李再问：
“A 客户有哪些踩过的坑、已经确定的结论？”
Agent 已经可以直接从团队共享的资料中找到答案。
小王半年里踩过的坑，不再只留在小王这里；
经过确认的经验，开始成为整个团队下一次做判断的起点。
让一个人的经验，成为整个团队的积累。
