Cloudflare 开源面向 AI 智能体的决策模型 Clef
InfoQ
在近期“生日周”活动中，Cloudflare 开源了 Clef——一组开源权重的 AI 决策模型，用于在预设选项之间做选择而非生成文本。提供 270 亿参数（中位延迟 209.3ms）与 90 亿参数 Clef-Flash（中位延迟 38.8ms）两个版本，以及一个将其适配到特定决策任务的平台。Clef 是 270 亿参数多模态模型，以状态与带类型问题的 Schema 为输入，一次前向推理即返回各可选项概率，支持文本/JSON/图像/视频；相比 Typesafe 的 Jev，它多了视觉编码器且上下文窗口达 64k（Jev 为 32k）。它可驱动智能体做工单分配、升级或转人工等决策，已通过 Workers AI 与 Hugging Face 提供。社区对其“新品类”定位及公开基准的公正性存疑。
Google Cloud 发布 llm-d 1.0：面向 TPU 与 GPU 集群的缓存感知路由
MarkTechPost
Google 团队发布 llm-d 1.0，这是其分布式推理栈的首个稳定版本——一个 Kubernetes 原生的开源层，将 vLLM 或 SGLang 模型服务器编排为统一协同的资源池，面向自托管 Agent 与 RL 负载（这类场景下轮询负载均衡会失效）。llm-d 由 Red Hat、IBM、Google Cloud、CoreWeave 与 NVIDIA 于 2025 年创立，现已有超 500 名贡献者，是 CNCF Sandbox 项目（Apache 2.0）。1.0 新增多租户 QoS 流控、路由器高可用与零停机升级、会话感知路由等“day 2”能力，并支持 NVIDIA/AMD/Intel GPU 与 Google TPU。其核心是缓存感知路由：路由器追踪各副本持有的缓存前缀，按负载与预测延迟选节点；KV 缓存在显存/主机内存/SSD/Managed Lustre 间分层，Prefill 与 Decode 分离部署。官方基准：Ironwood TPU 上中位 TTFT 降低 85%+、吞吐 2.4x；17000 节点 GKE 跨 3 集群吞吐扩展 2.9x（99.9% 成功率）。

AI为什么越聊越容易犯错？Every评估负责人：旧的上下文，正在带偏你的 Agent
51CTO技术栈
Every 评估负责人迈克·泰勒（Mike Taylor）撰文指出，单条对话随上下文不断累积会“带偏”Agent，他把这种现象称为 Context Rot（上下文退化）。实验显示，给 ChatGPT 加入几个“i-”命名示例后，其模仿乔布斯取名中以“i-”开头的比例从21%升至100%，说明模型会从上下文寻找模式并延续；长上下文还会淹没关键信息（斯坦福“Lost in the Middle”），且早期错误假设会污染后续任务状态（如 Gemini Plays Pokémon 误将旧版道具信息带入新任务）。他建议：跨任务切换时重开对话，将稳定项目规则留在 AGENTS.md/CLAUDE.md、当前需求写进任务简报、进度通过“交接文件”延续，避免让模型继承整段试错历史。

Qoder Cloud Agents：评测Loop，让 Agent 持续可靠地变好
Qoder
文章指出 Agent 发布常靠“感觉还行”的高风险判断，因为 Agent 输出“答案+过程+产物+行为边界”，且带概率性，少量试跑无法证明其稳定或改动带来增益。Qoder Cloud Agents（QCA）主张建立持续运转的评测 Loop：以“考题=用例、考生=被评对象、考场=运行环境、解题过程=轨迹、答卷=回答与制品、阅卷老师=评估器、上次成绩=基线”对应，形成“发现问题→优化→回归验证”循环。其条件包括评测环境即真实现场、全程录像、高并发互不干扰、版本管理不影响线上；评估坚持“三看”（答案/过程/产物），客观题交代码、主观题交模型、实操题交 Agent 验货，并多次评估用 pass@k 衡量、结果封存防泄漏。优化须在克隆副本上做回归，仅改错题不算进步、整体不退步才算验证，线上真实问题再回流为评测集沉淀为业务资产。
