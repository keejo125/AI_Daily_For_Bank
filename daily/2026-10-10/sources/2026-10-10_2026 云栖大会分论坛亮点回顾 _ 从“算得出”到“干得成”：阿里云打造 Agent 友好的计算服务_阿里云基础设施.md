# 2026 云栖大会分论坛亮点回顾 | 从“算得出”到“干得成”：阿里云打造 Agent 友好的计算服务

来源：阿里云基础设施
原文链接：https://mp.weixin.qq.com/s/Q7C4st1DHh0roBY2HfJp_Q

当 AI 从模型能力的竞争走向智能体的规模化落地，计算基础设施正在迎来一次新的范式转变。模型时代，人们更关注参数规模、训练效率与推理吞吐；Agent 时代，AI 不仅要回答问题，还要理解目标、拆解任务、调用工具、读取状态、持续规划，并在真实环境中完成一次又一次行动。计算服务所承接的，也由一次请求、一次响应，变成了贯穿任务全流程的可靠执行。
在 2026 云栖大会《Agent 友好的计算服务加速企业进化》分论坛上，阿里云弹性计算围绕这一变化，系统阐述了面向 Agent 时代的产品与技术演进：以 Agent 友好的核心技术、Agent 友好的计算产品和 Agent 友好的用户界面为三层架构，一方面让 Agent 更好地运行在阿里云 ECS 之上，另一方面让弹性计算自身借助 Agent，更好地服务用户。
现场发布的智能体专用型实例、阿里云第十代企业级实例 g10a、E-HPC Agent 与阿里云弹性计算 Agent，构成了从开发者、企业规模化生产到科研计算与云上运维闭环的完整产品矩阵。同时，去年发布的 ECS g9i 也已经在阶跃星辰、海尔智慧家庭等行业实践中实现了规模化落地；九代 AMD 相关实例高效支撑了一知智能的 Voice Agent；上海科学智能研究院的“浑天绫”科研智能体平台展示了 E-HPC Agent 的科研计算闭环；云助手 OSAgent 则面向操作系统和异构集群提供全新的智能运维能力。
从模型时代走向 Agent 时代，计算服务，也从“支撑推理”走向“承接执行”
图：阿里云智能集团弹性计算资深产品专家 姬少晨
阿里云智能集团弹性计算资深产品专家姬少晨在开场分享中指出，
模型时代的核心诉求是“算得出”，而到了 Agent 时代，真正的目标是“干得成”
。这两个字的变化背后，是工作负载的全面变化。一个 Agent 要持续维护上下文，反复读取任务状态，在多轮推理中重新规划，还要频繁调用浏览器、代码环境、数据库和企业系统。它既需要高吞吐，也需要低时延；既可能长时间运行，也可能在短时间内拉起大量细粒度任务。
这意味着，Agent 所需的基础设施不再只是大模型推理服务的延伸。数据预处理、代码执行、工具调用、任务编排、强化学习 Rollout，以及运行时的状态管理，大量工作都发生在 CPU 上。随着 Agent 从 Demo 进入生产，CPU、内存、存储与网络之间需要形成更紧密的协同，
通用算力也从“模型之外的辅助资源”，逐渐成为决定智能体能否稳定落地的关键底座
。
与此同时，Agent 的普及还呈现出清晰的阶段性：最初，开发者需要一台简单易用、成本合理、能够持续升级的云服务器；进入规模化阶段后，大模型并发、任务拆解和工具调用带来了细粒度、超大规模弹性；当 Agent 深入千行百业，不同行业的软件、流程与知识差异，又要求算力平台能够沉淀专业的方法；最终，当云的使用者从“人”扩展到“Agent”，云服务还必须能够被理解、被调用、被编排，并且每一步操作都可控、可审计、可验证。
三层重构，让 Agent 跑得起、用得好、管得住
面向新的工作负载，阿里云弹性计算将十六年的全栈积累重新组织为三个层次。
第一层是 Agent 友好的核心技术
，通过高密部署、镜像预热、休眠与恢复、虚拟机等创新，承接细颗粒度、超高并发任务，让 Agent 在高峰时能够快速拉起，在等待时能够高效休眠，在长任务中能够保存状态。
第二层是 Agent 友好的计算产品
。针对 Computer Use、Mobile Use、代码智能体、浏览器智能体、数据智能体和行业智能体等不同负载，平台提供 x86、ARM 等多元算力，以及容器、原生虚拟机等不同运行形态。算力产品不再只按通用应用的平均负载设计，而是围绕 Agent 的内存占用、工具调用、网络访问、隔离需求和启动速度重新优化。
第三层是 Agent 友好的用户界面
。通过 CLI、MCP、Skills 等方式，Agent 可以理解云资源、调用云能力、编排执行流程。更重要的是，风险确认、成本预估、人工授权、结果验证和全程审计被纳入操作链路，使自然语言从一个“更方便的入口”，进一步成为安全使用云资源的新界面。
从人用云到 Agent 用云，计算服务要同时回答三个问题：Agent 能不能跑起来，业务能不能规模化，以及每一次执行能不能被信任。
基于这三层架构，阿里云将本次发布的四款新品划分为两组。智能体专用型实例与第十代企业级实例 g10a 属于“Agent on ECS”，重点解决 Agent 如何更顺畅、更高效地跑在 ECS 上；E-HPC Agent 与阿里云弹性计算 Agent 属于“Agent in ECS”，让计算平台主动理解客户目标、调度资源并完成任务。前者优化 Agent 的运行环境，后者重塑客户使用计算服务的方式。
Agent on ECS：智能体专用型实例、第十代企业级实例 g10a
姬少晨在演讲中介绍，面向开发者部署 Agent 时面临的环境配置复杂、算力与模型服务割裂、长期运行成本较高等问题，阿里云推出智能体专用型实例。该产品将 AI 应用、云服务器与模型推理服务三位一体打包，针对 Agent 长时间运行、高频工具调用等特点优化资源配比，起步内存提升 50%，同时提供固定公网 IPv4 地址、峰值公网带宽和模型额度，让开发者能够用一台云服务器、一份账单，快速完成 Agent 的部署和运行。
当 Agent 从个人尝试进入企业生产，负载会迅速从单体应用扩展为大规模工作流。生产 Pipeline、训练数据合成、代码生成与验证，需要更高的计算密度、更强的弹性和更大的内存带宽，同时对安全隔离与运行环境提出更高要求。
面向这些需求，阿里云发布第十代企业级实例 g10a，并将开启邀测。
ECS g10a 搭载 AMD 新一代处理器，内存通道由 12 通道提升至 16 通道，内存带宽提升 60% 以上；结合 Alibaba Cloud Linux 4 在操作系统层针对 Agent 任务的专项优化，以及 CIPU 对云盘、网卡等设备密度的提升，为大规模并行执行提供从硬件、系统软件到 I/O 的全栈支撑。
在业务效果上，
相比九代实例，g10a 在 Agent 编码场景中的性能提升约 30%，在搜索推荐等传统场景中的性能提升约 50%，整体性价比提升约 25%
。这意味着，第十代实例并非一次简单的 CPU 更新，而是围绕 Agent 工作流、数据和工具链进行的系统性升级。
Agent in ECS：E-HPC Agent、弹性计算Agent
E-HPC Agent 则面向高性能计算场景，用户只需定义目标和边界，Agent 就能理解任务、规划实验、调用行业 Skill，并根据结果持续优化，把专家从找工具、串流程、调算力和看结果等重复工作中释放出来。专家负责关键判断，E-HPC Agent 则将方法沉淀为可复用的能力，完成从目标理解、实验规划到执行反馈的闭环。
另一款“Agent in ECS”新品——阿里云弹性计算 Agent，则覆盖资源管理和运维全链路。姬少晨表示，它不是简单的聊天机器人，而是能够感知问题、分析根因、执行操作并确认结果的管家型 Agent；通过主 Agent、专业子 Agent 与场景化 Skill 协同，让弹性计算从“人操作云”逐步走向“Agent 驱动云”。
智能体专用型实例：开发者的第一台 Agent 友好云服务器
图：阿里云智能集团弹性计算产品专家 王存哲
阿里云智能集团弹性计算产品专家王存哲围绕“开发者需要一台什么样的 Agent 云服务器”展开分享。他指出，传统云服务器主要面向 Web 等通用应用设计，资源配比未针对 Agent 长时间运行和高频工具调用进行优化，算力、模型服务与账单相互割裂，增加了部署和运维门槛。相比本地电脑，云上环境还可以避免断电、断网和休眠对任务连续性的影响，为需要 7×24 小时工作的 Agent 提供省心、安全、稳定、普惠的执行空间。
为此，阿里云发布智能体专用型实例，将 AI 应用、云服务器和模型推理服务三位一体打包。产品针对 Agent 调整资源配比，起步内存提升50%，并提供固定公网 IPv4 地址、峰值公网带宽和模型额度；同时预置常用 Agent 应用镜像，接入千问、万相、DeepSeek、智谱、Kimi、MiniMax 等多品牌、多模态模型，让开发者能够快速部署应用，并用一份账单管理算力消耗。
智能体专用型实例还搭载面向 Agent 优化的 Agentic OS。经阿里云内部测试显示，无效 Token 消耗降低30%，主流 Benchmark 分数提升10%，内存分配效率提升200%，Agent 冷启动时长缩短20%。首款配置提供2核 CPU、6GB 内存、30GB 云盘、固定公网 IPv4 地址和模型积分，每天约2.9元；与以往主流“云服务器＋MaaS订阅”组合相比，价格约低20%，内存提升50%，Token可用量提升25%。
E-HPC Agent：加速企业科研的智能算力底座
图：阿里云智能集团弹性计算高级产品经理 邹佳航
阿里云智能集团弹性计算高级产品经理邹佳航指出，传统科研计算需要专家自行寻找工具、准备环境、提交作业并分析结果，复杂的工具链和异构资源消耗了大量时间。Agent 的目标理解、任务规划和工具调用能力，与科研计算流程天然契合。
阿里云发布 E-HPC Agent，将行业 Agent 与弹性高性能计算连接起来。用户只需定义目标、边界和验收标准，Agent 即可理解问题、规划实验、调用行业 Skill，并根据运行反馈持续优化；E-HPC 则负责 CPU、GPU、网络、存储、镜像和软件环境的调度与管理。简单来说，Agent 负责规划，E-HPC 负责稳定执行。
在完整链路中，Agent 会将自然语言目标转化为计算任务，拆解前处理、求解和验证步骤，匹配相应算力并提交作业；运行过程中持续读取日志和中间结果，判断是否需要调整参数，再将结果送回上下文，触发下一轮规划。由此，科研流程从回答问题走向执行任务，从人工串联走向自主编排，从一次计算走向持续迭代。
E-HPC Agent 可应用于生命科学、工业仿真、EDA 和量化研究等领域，帮助专家完成流程编排、环境配置、作业运行和状态巡检，但关键判断仍由专业人员负责。平台还提供开放的原子化 Skill 和 CLI，企业可以保留自己的 Agent、模型、知识库和工作流，由 E-HPC 承接异构算力调度与稳定执行，让专家方法得到沉淀、复用和持续迭代。
上智院“浑天绫”实践：五天五夜，1 万多次计算任务
图：上海科学智能研究院物质科学智能首席科学家，格物智研创始人 曹风雷
上海科学智能研究院物质科学智能首席科学家、格物智研创始人曹风雷分享了“浑天绫”科研智能体平台与 E-HPC Agent 的联合实践。
上海科学智能研究院打造的“浑天绫”科研智能体平台，面向物质发现与创制，将科研方法沉淀为 140 多个 Skill。浑天绫负责理解科研目标、规划任务并编排技能，E-HPC Agent 负责查询资源、提交作业、按需拉起计算环境，并把结果和状态自动返回智能体体系，形成“规划—计算—实验—反馈—再规划”的闭环。
在一次五天五夜的干湿实验闭环活动中，智能体向 E-HPC 提交了 867 个不同类型的计算任务，总算量 7 万多 CPU 核时，运行总时长829小时。原计划执行的102 个科研任务在约两天半内完成，团队随后又追加了 30 多个任务。面对任务时长从数秒到十几个小时、资源需求持续变化的复杂场景，E-HPC Agent 完成了环境配置、任务提交、状态监控、失败分析和结果回传。
在催化剂筛选实践中，模型预测与实验验证经过多轮闭环，第二轮方案的转化率较原始方案提升 6 倍多。更重要的变化不是单次计算更快，而是科研人员可以把精力放在提出问题和关键判断上，让 Agent 与弹性算力承接大量重复、耗时的执行工作。
ECS g9i：通用算力托住 Agent 的规模化落地
图：
阿里云智能集团弹性计算高级产品专家 武双涛
阿里云智能集团弹性计算高级产品专家武双涛在分享中指出，Agent 进入生产之后，真正决定业务能否持续运行的，不只是模型能力。多步推理和工具调用会形成突发资源需求，长任务和持续 I/O 要求算力既能快速扩容，又能保持低时延响应；Agent 具备更高权限，也让提示词诱导、第三方工具风险和敏感数据保护成为新的安全挑战。随着执行链路变长，企业还必须回答：算力不仅要“有”，能否长期以可控成本稳定使用？
ECS g9i 基于英特尔至强 6 处理器与阿里云自研 CIPU 深度协同，通过硬件卸载与软件优化，让算力、I/O、安全和稳定性全面提升。全核睿频达到 3.6GHz，缓存达到 504MB，性能较上代提升 20%；AMX 等指令集为向量检索、Embedding 生成和轻量级大模型推理提供加速，eRDMA 网络时延低至 8 微秒。
在安全方面，ECS g9i 标配支持 TDX 机密虚拟机，以虚机粒度的硬件隔离保护 Agent 运行中的敏感数据和上下文；在弹性方面，依托千万核资源规模与镜像预热、资源池和弹性调度能力，可在业务高峰快速扩容；在稳定性方面，双单路物理架构缩小故障影响范围。最终，企业能够感知到三件事：任务启动更快，高峰并发承接更稳，单会话成本更可控。
围绕 Agent 全链路，ECS g9i 还将算力与运行时协同优化。底层提供高性能 CPU、专用指令加速和低时延 I/O，中间层通过沙箱运行时、镜像预热和弹性调度缩短启动时间，上层适配代码、浏览器和数据类 Agent。QAT 等能力可以提升压缩、加解密等高频操作效率；对于浏览器密集型任务，同等规格下可承载更多并发。由此，Agent 的性能优化不再局限于单次推理，而是覆盖环境启动、工具调用、数据处理和任务恢复。
从模型训练到智慧家庭：算力价值由真实业务验证
图：阶跃星辰阶跃开放平台 Harness 产品工程师 周旭
阶跃星辰阶跃开放平台 Harness 产品工程师周旭分享，阶跃星辰的后训练和强化学习训练平台运行在 ECS g9i 之上，构建了大规模 Pod 与十万核的弹性算力闭环。通过控制面优化、镜像预热、ACS标准 K8s 兼容和临时存储空间动态扩容的能力，平台能够稳定承载数十万核规模的强化学习任务稳定运行；ECS g9i 综合性能最高提升 20%，单位算力成本最高下降 5%，为模型后训练与强化学习提供了兼顾弹性和成本的 CPU 算力底座。
周旭还从 Harness 的视角指出，Agent 编码真正消耗开发者注意力的，往往是上下文管理、模型与成本匹配、任务中断后的恢复，以及多 Agent 并行编排。基础设施与 Harness 协同的意义，在于把这些重复决策交给系统，让开发者把注意力留给目标、验收标准、效果基线和发布门槛。
图：海尔智慧家 AIoT 云平台技术负责人 王珂伟
海尔智慧家 AIoT 云平台技术负责人王珂伟则展示了通用算力如何支撑智能体进入亿级设备场景。当前，其业务已覆盖全球上百个国家，智家 App 拥有上亿注册用户，月活上千万。基于 ECS g9i 的高性能计算、网络转发和弹性扩容能力，平台能够稳定承载大规模并发请求，保持毫秒级设备交互和秒级语音操控。这里，g9i 的价值并非“创造”这些业务规模，而是为既有规模提供稳定可靠的算力支撑，让底层计算能力持续支撑上层产品创新。
九代 AMD 实例：为新型 AI 工作负载提供高性价比的通用算力底座
图：阿里云智能集团弹性计算高级产品专家 唐湘华
阿里云智能集团弹性计算高级产品专家唐湘华在分享中指出，Agent 时代的 AI 负载已从训练、推理扩展到强化学习 Rollout、数据预处理和 Agent Runtime，其中大量任务运行在 CPU 上。如果说 GPU 更多承担“想”的过程，CPU 则承担代码执行、工具调用和任务编排等“做”的过程。九代 AMD 实例基于阿里云自研 CIPU 架构，网络带宽提升至 400G，并采用一颗 vCPU 对应一个物理核的设计，整机核心密度达到 384 核，为高并发、重计算和大内存带宽负载提供稳定算力。
唐湘华从三个场景介绍了九代 AMD 实例的实际价值。首先是搜索、推荐和广告。随着大模型进入深层推荐、召回和 Query 改写等环节，Embedding、Tokenization、特征提取和稀疏数据处理对 CPU 性能、内存带宽及实时响应提出了更高要求。九代 AMD 实例通过物理核和大内存带宽，使这些 CPU 阶段的任务运行得更快、更稳定。据现场介绍，其在真实客户的搜索推荐 Benchmark 中实现了约37%的性能提升，目前已有客户基于九代 AMD 实例构建百万核级搜索推荐集群。
第二个场景是中小型语音模型。随着小模型能力提升，部分 7B、14B 模型已经能够满足垂直场景需求，为 CPU 承载语音模型提供了更多可能。语音交互对响应速度十分敏感，延迟过高会明显增强“机器人感”；但如果一台机器只能运行单路任务，即使单路成本下降，也难以形成商业价值。九代 AMD 实例依靠物理核和高核心密度，可同时承载多路任务，在兼顾响应速度的同时提升并发能力，为语音模型的规模化部署创造条件。
第三个场景是 Agent Runtime 与强化学习 Rollout。代码执行、工具调用、浏览器操作、状态管理及任务编排大量依赖 CPU；Rollout 则需要在 CPU 上并发运行大量交互路径。九代 AMD 实例的物理核、计算能力和大内存带宽，有助于提升这类任务的吞吐效率。唐湘华表示，无论是 Agent 推理还是训练，相当一部分工作都依赖 CPU，CPU 正在成为影响 Agent 系统整体效率的新约束
图：杭州一知智能科技有限公司首席技术官 姜兴华
杭州一知智能科技有限公司首席技术官姜兴华在现场分享中分享了 Voice Agent 从 Demo 走向生产的实践的经验。真实语音交互并不是 ASR、大模型和 TTS 的简单串联，还要实时判断用户是否说完、何时开始回答、何时允许打断，并在智能程度、响应延迟、系统稳定性和计算成本之间取得平衡。为此，一知智能通过 Turn-taking 模块进行实时轮次判断，并利用 Fast Thinker 将不同复杂度的问题分流至不同模型，让简单问题快速响应，复杂任务进入能力更强的模型或后台推理链路。
由于 Agent Runtime、状态管理、全双工控制、大模型生成和语音合成等模块的延迟目标与算力需求各不相同，一知智能将其部署在匹配的 CPU、通用计算实例和 GPU 资源上，构建异构计算系统。同时，针对语音业务明显的波峰波谷，平台借助阿里云弹性伸缩能力动态调整资源，使整体计算成本降低40%。姜兴华表示，Agent 从 Demo 走向生产，关键不是简单堆叠算力，而是让不同任务运行在更适合的计算资源上。
阿里云弹性计算 Agent：从人操作云到 Agent 驱动云
图：阿里云智能集团弹性计算高级产品专家 张强
阿里云智能集团弹性计算高级产品专家张强围绕“从人操作控制台走向 Agent 运维”展开分享。他指出，人与云的交互正在从控制台和 API 走向 Agentic Interface。用户不再需要预先理解复杂的产品概念和资源规格，只需表达业务目标，Agent 就能将其转化为资源方案和执行计划。
阿里云弹性计算 Agent 是覆盖资源购买、管理和运维全链路的管家型 Agent。它能够感知问题、分析根因、执行操作并验证结果，可通过控制台及钉钉、飞书、企业微信等入口使用，也能借助 Open API 和 Skill 接入企业已有的 Agent 系统或运维平台。
依托主 Agent、专业子 Agent 和场景化 Skill，弹性计算 Agent 已覆盖知识问答、辅助购买、资源管理、应用监控、诊断优化等核心场景。它可以根据业务需求生成成本、性价比或性能优先的购买方案，也能通过自然语言完成实例、云盘、安全组等资源操作和 IaC 部署。在 GPU 集群巡检中，还可将故障发现与定位从小时级缩短至分钟级，节省80%以上人工巡检工作量。
与传统自动化相比，弹性计算 Agent 不只是调用接口，而是围绕目标完成任务规划、风险与成本评估、操作执行和结果验证。执行过程中，人仍然掌握最终控制权，高风险操作需要用户确认并全程留痕。其分工可以概括为：人负责目标和授权，Agent 负责规划、执行与反馈。
云助手 OSAgent：让判断进入操作系统现场
图：阿里云智能集团弹性计算高级技术专家 陈亮
阿里云智能集团弹性计算高级技术专家陈亮将视角推进到操作系统内部。他指出，如果说弹性计算 Agent 改变了云资源的交互方式，云助手 OSAgent 则把 AI 的理解与判断带到机器现场。面对多实例、多操作系统和不同命令体系，OSAgent 能够基于每台机器的一手状态执行运维任务，降低传统逐台登录带来的交互与认知成本。
依托云助手安全触达 ECS 的原生通道，OSAgent 在 Guest OS 内构建感知、规划、行动和反馈闭环，并可通过 MCP 接入操作系统元信息，通过Skill复用专家经验和知识库。面向异构集群，各实例中的 OSAgent 根据 Ubuntu、CentOS、Red Hat、Windows 等不同的环境自适应的执行相应操作，将过去逐台处理、数十轮交互的工作收敛为一次对话，实现约10倍的运维效能提升。
面对 Linux 内核异常等复杂问题，OSAgent 可以结合现场日志、Core 文件、内核源码和社区变更记录定位根因，并在授权范围内完成修复与验证。同时，审批、白名单、最小权限、过程留痕、回滚和审计贯穿整个运维流程。目前，云助手 OSAgent 及相关运维 Skill 已开源；云助手每天承载超过4400万次任务，成功率超过99.9%，为 Agent 进入操作系统和大规模异构集群提供可靠基础。
Agent友好的计算服务，让每一家企业加速 AI 进化
“Agent 友好”的真正含义，不是给现有产品简单增加一个聊天入口，也不是只提供更多算力。而是从核心技术、计算产品到用户界面进行系统重构。底层能够承接细粒度、高并发和长任务，中层能够匹配不同 Agent 负载，上层能够被 Agent 理解和调用，同时把人的授权、风险控制和结果验证保留在闭环之中。
当 Agent 从应用走向规模化、行业化，并逐步成为云的新用户，计算服务也将从资源供给者走向智能体的执行底座。未来，阿里云弹性计算将继续围绕弹性、成本、稳定与安全持续演进，让 Agent 跑得起、跑得稳、用得省、管得住，为每一家企业的 AI 进化提供坚实算力支撑。
