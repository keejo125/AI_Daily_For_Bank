# 老黄首推引爆开源论战：Anthropic 员工催 CUDA 开源，吴恩达反击：你可以不开源，但别阻止别人

> 原文链接：https://mp.weixin.qq.com/s/DpHLznYJqzTCYasjHL4rcA
> 公众号：InfoQ

作者｜冬梅

7 月 24 日，老黄在开通个人 X 账号后的第一条推文中，分享了英伟达参与签署的公开信《开放权重与美国 AI 领导力》。他表示，AI 将改变每个行业、服务每家公司，并由每个国家建设；开放模型有助于加强安全、推动创新和技术扩散，“世界既需要前沿闭源模型，也需要前沿开放模型”。

与黄仁勋一同表态的还有微软 CEO 萨提亚·纳德拉。

纳德拉称，开放权重模型是健康 AI 生态不可或缺的一部分，有助于增强美国竞争力、扩大经济机会，同时保护国家安全。公开信的首版签署方共计 25 家，包括英伟达、微软、Meta、IBM、Hugging Face、Linux 基金会、Mistral AI、Mozilla 等，Anthropic 不在其中。

一天后，谷歌 CEO 皮查伊和谷歌 DeepMind 创始人哈萨比斯均表态支持开源。

哈萨比斯发文称：“一个强健、安全的开放生态系统，对让全世界共享 AI 红利至关重要。我们始终大力支持并深度参与开源与科学事业——从 Jax、Transformer 到 AlphaFold，再到 Gemma 开源模型，累计下载量已突破 3 亿次。而我们提出的这一标准框架，也为开源模型与专有模型的负责任部署提供了有力支撑。”

皮查伊也在 X 上写道：“非常荣幸代表谷歌支持这一举措。我们长期受益于开源生态，也是开源领域的积极贡献者；事实上，依托 @GoogleDeepMind 与 @demishassabis，我们持续推出了 Gemma 系列开源权重模型。继续向前！”

1

Anthropic 员工呛声：先开源 CUDA、Windows 和 Office

正当科技圈里大佬们纷纷发文力挺开源之际，拟进行巨额 IPO 的 AI 巨头 OpenAI CEO Altman 坐不住了，也在 X 上发文表示支持开源。

但颇具讽刺的是，另一家也走在 IPO 进程中的 Anthropic，却缺席了这封联名信。

Anthropic 技术团队成员 Julian Schrittwieser 甚至还通过个人 X 账号发布了一系列回复，嘲讽围绕“开放权重与美国人工智能领导力”这封信的庆祝氛围。他写道：

“我太激动了，黄仁勋现在居然相信开源了，期待 CUDA 和 GPU 驱动程序的开源发布！”

随后，他又揶揄了微软：

“纳德拉也开始支持开源了，迫不及待等着 Windows 和 Microsoft Office 开源！”

接着，他直接回应了网友们的反应：“看到大家这么快就得出结论说我肯定想禁止开放权重模型，真是可笑……我其实觉得开放模型非常有用！但有趣的是，一些历史上极度反对开源的公司，突然都开始支持开放了。”

这位名叫 Julian 的 X 用户的主页显示，他是 Anthropic 技术人员，曾就职于 Google DeepMind，参与过 AlphaGo、AlphaZero、MuZero、AlphaProof、Gemini RL 等项目。

从一些事实来看，Julian 的讽刺并非完全没有现实基础。CUDA 至今仍是英伟达最重要的软件壁垒之一；微软的 Windows 和 Office 也没有整体开源。不过，将两家公司概括为“完全反开源”同样并不准确。

英伟达已经公开 Linux GPU 内核模块源码，但其官方仓库明确说明，开放内核模块仍需配合相应版本的用户态英伟达驱动组件。微软近年来也开放了.NET 等大量项目，微软官方称.NET 的运行时、编译器、类库及多个开发框架均在 GitHub 上开源。

换句话说，两家公司的策略更接近“部分开放、核心商业产品继续封闭”，而不是简单的全开源或全闭源。

2

吴恩达加入争论：没人逼你开源，你也别拦着别人

随后，吴恩达在 Julian 的帖子下直接回应：

“这是一个错误类比。任何人都有权保持自己的代码私有。问题在于，有人试图阻止其他人开源。”

吴恩达把这场争论划出了两条不同的边界：一家公司可以选择不公开自己的代码、模型或商业机密，但这种选择并不能自动转化为限制竞争对手、研究人员或其他企业发布开放模型的权力。

这也是黄仁勋等人签署的公开信真正讨论的问题。

公开信并没有要求英伟达开放 CUDA，也没有要求微软公开 Windows 的完整源代码。它所反对的是，政策制定者因为开放模型可能被滥用，便对整个开放权重生态实施过于宽泛的限制；同时，它还要求监管机构区分正常的模型蒸馏、评测和改进，与通过非法手段窃取闭源模型能力之间的差别。

因此，Julian 讨论的是科技巨头在商业立场上的一致性，吴恩达讨论的则是企业选择和公共政策之间的边界。

这并不是吴恩达临时加入争论后的即兴表态。过去几年，他一直是硅谷公开支持开放模型、反对以安全为名过度限制开源的代表人物之一。

早在 2023 年 11 月，吴恩达就在 DeepLearning.AI 的公开信《让开源保持自由》中表示，政府不应禁止开源软件，也不应通过监管压制开源开发。

他认为，AI 模型是一种通用技术，监管需要区分底层技术与具体应用：使用 AI 生成非自愿色情内容、操纵用户或者制造危险产品，可以针对应用场景追责，但不能因为一种通用模型存在被滥用的可能，就限制模型本身的研究、发布和传播。

在这封信中，吴恩达还将矛头指向部分闭源模型公司。他认为，一些不愿与开源模型竞争的企业，可能夸大 AI 风险，为限制开放模型的政策提供理由。最终结果未必是让 AI 更加安全，反而可能提高技术门槛，让拥有资金、律师和游说能力的大公司进一步巩固优势，而中小团队、学术机构和个人开发者被排除在外。

一个月后，吴恩达在提交给美国参议院 AI 洞察论坛的书面陈述中，再次强调了这一判断。他警告，对开源软件或 AI 基础技术施加过重的合规要求，不仅会阻碍创新，还可能产生反竞争效果，“巩固今天大型科技公司的地位”，减缓 AI 能力向普通企业和个人扩散。相比提前限制模型，他更主张识别具体、可验证的现实伤害，并围绕应用制定规则。

吴恩达对开放生态的支持也不只停留在表态上。

2026 年 7 月，他公开发布开源桌面智能体 OpenWorker。该项目采用 MIT 许可证，代码托管在 GitHub，支持开发者自行检查和修改，也允许用户在 OpenAI、Anthropic、谷歌等商业模型、开放权重服务和本地模型之间切换，避免把智能体完全绑定在单一模型供应商上。

因此，这一次吴恩达对 Julian 的回应，更像是其长期立场的延续。在他看来，开放与封闭可以作为两种商业模式并存：Anthropic 可以不公开 Claude 的权重，英伟达也可以继续把 CUDA 作为核心护城河。真正需要警惕的是，已经选择封闭路线的企业，以安全、知识产权或者国家竞争为理由，推动政府缩小其他企业和开发者选择开放路线的空间。

Julian 质疑的是科技巨头有没有资格高谈开源，吴恩达回答的则是另一个问题：一家企业是否开源自己的产品，可以由它自己决定；但它不能把自己的封闭选择，变成所有人都必须遵守的行业规则。

3

网友吵翻：有人批评巨头双标，也有人把矛头指向 Anthropic

这场争论很快从 X 蔓延到 Reddit。

支持吴恩达的网友 votegoat 表示，没有人要求微软必须开源自己的全部代码，人们反对的是禁止开源。他还提到，微软支持 Linux，并拥有 GitHub，也没有要求政府将其他操作系统变成“非法产品”。

另一名网友 Johnwascn 的说法更加直接：企业当然可以不开源，但为什么要阻止别人开源，甚至阻止别人使用开源技术？这与吴恩达划出的边界基本一致。

还有网友将批评转向了 Anthropic。用户 rageling 表示，他没有看到 Anthropic 发布多少开放模型，反而认为这家公司是当前对开放 AI 最不友好的企业之一。这个评价带有明显主观色彩，但也反映出部分开放模型社区对 Anthropic 的不满。

不过，Julian 的批评同样获得了一部分网友认同。

Reddit 用户 mrgreatheart 提醒，人们不应忘记微软过去的历史。在史蒂夫·鲍尔默执掌微软期间，微软曾对 Linux 和开源软件采取极具攻击性的态度。虽然纳德拉时代的微软发生了明显变化，但企业立场仍然可能随着商业利益而改变。

用户 Knoll_Slayer_V 则认为，CUDA、Windows 这类从一开始就以专有软件形式开发的产品，与大量使用公共数据或他人知识产权训练出来的 AI 模型并不能简单等同。他判断，未来 AI 企业可能很难仅靠模型本身持续收费，更可能依靠模型周围的产品、服务和工作流赚钱。

在另一条讨论黄仁勋 X 首秀的帖子中，有网友把黄仁勋的立场调侃成：“世界需要所有模型，任何模型——只要它们最好都运行在我的 GPU 上。”

也有人回应称，黄仁勋当然存在商业立场，但这并不自动证明他的观点是错误的，只是在理解其发言时必须考虑英伟达的利益。

4

开放之争背后，所有人都有自己的生意

这场争论之所以迅速发酵，是因为每一方都能从对方身上找到“双标”的证据。

对英伟达来说，更多开放模型意味着更多企业可以自行部署、微调和运行 AI，也意味着更多 GPU、网络设备和推理基础设施需求。公开信本身就明确提出，开放权重模型会把竞争从模型层扩展至云计算、芯片、应用和服务层。从这一点看，黄仁勋支持开放权重既是产业立场，也符合英伟达的商业利益。

对微软来说，开放模型可以丰富 Azure 上的模型供给，避免企业客户完全依赖单一模型提供商，同时扩大云计算、开发工具和企业软件的使用场景。

对于依靠前沿闭源模型和 API 收费的公司，开放模型的快速进步则意味着更直接的竞争。能力差距一旦缩小，企业客户就可能在闭源 API 与可自行部署的开放模型之间重新计算成本、数据控制权和供应商锁定风险。

这也解释了为什么围绕“安全”“创新”和“开源精神”的争论，最终总会落到商业模式上：芯片公司希望模型层更加繁荣，云厂商希望模型供应更加多元，而闭源模型公司则希望保护能力、数据和定价权。

不过，这并不意味着任何一方的观点都可以仅凭商业动机被否定。黄仁勋从开放生态中获利，不代表开放模型没有价值；Anthropic 希望保护自身模型，也不意味着其提出的安全和知识产权问题不存在。

真正需要区分的是：企业是否有权保护自己的技术，与企业是否有权借助政策阻止其他人开放技术，并不是同一个问题。
