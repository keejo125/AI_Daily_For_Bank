Rust 给 AI 编程立新规：能帮你看，不能替你写，用多了还会“熔断”
InfoQ
Rust 项目五个团队（编译器、标准库、类型系统、rustdoc、bootstrap）正式采纳 LLM 使用准则，作者 Jynn Nelson 于 2026-08-05 在 Inside Rust 公布。核心原则：可用 LLM 思考、审查、翻译、发现 Bug，但不可“创造”代码；LLM 参与须披露，隐瞒视为违反行为准则。准则分三层：私人用途完全允许；翻译、微小修改、找 Bug、审查机器人须披露；直接生成评论/文档/编译器诊断明确禁止。新贡献者受限更严，并设“熔断”机制——任一六周窗口内 LLM 创建 PR 超半数，则全部暂停合并并冷却至少 10 天。背景是 PR 信号失效、审查资源紧张。与 Zig 彻底禁用 LLM 形成对比。

SkillFS：当 Agent 有几十个 Skill，用文件系统来治理
阿里云基础设施
阿里云基础设施团队介绍 ANOLISA 运行时组件 SkillFS：基于 FUSE 的虚拟文件系统，将物理 Skill 目录映射为 /skills/ 运行入口，按视图、安全策略和生命周期状态决定 Agent 实际可见的 Skill。通过默认运行视图、发现视图、安装候选入口及 .staging/.certified/.quarantine 等生命周期命名空间裁剪 Skill 集合，减少 Token 消耗与误选。安全上提供三态决策（current/fallback/hidden）、Active Mapping 热刷新、句柄级版本固定、.skill-meta 元数据保护。基于 38 个 Skill、27 场景实测，多数模型 Token 节省 7%~21%（kimi-2.5 省 21.37%）。已开源，独立 Rust 工程，仅支持 Linux。

企业内Agent工具落地实践：统一Harness、Skill与虚拟文件系统
腾讯云开发者

让 AI 替人写代码这件事，人类已经尝试了 70 年
CSDN
CSDN长文节选自邹欣《构建之法》第四版，系统回顾AI辅助编程70年探索史。1952年格蕾丝·霍珀提出编程自动化愿景，FORTRAN(1957)/COBOL以更高抽象提升效率；1968年“软件工程”诞生，80–90年代CASE工具试图自动化软件全生命周期却因方法论锁定、与敏捷冲突而衰落。MIT「程序员学徒」(1987)精准预言今日AI结对编程，但因识别计划等价于子图同构（NP完全）的组合爆炸失败，印证萨顿“苦涩的教训”；90年代微软西蒙尼「意图编程」主张以结构化树存储“意图”而非文本，因生态惯性与战略冲突未普及，其哲学以DSL形式传承。现代纪元以统计学习取胜：code2vec(2018)借AST捕捉结构、Transformer(2017)与BERT、CodeBERT(2020)直至大模型，标志统计方法对形式化方法的决定性胜利。结论：技术会变、问题永恒，AI增强而非取代老方法，工程师需培养判断何时用何工具的智慧。

51CTO技术栈转载华尔街科技分析师、MIT数字经济研究员Paul Kedrosky观点：AI技术真实，但泡沫也可能真实。他质疑——科技公司为支撑能力重金建数据中心、采购芯片，而Token持续降价、模型差距收窄，投入越来越重、卖出的“智能”却越来越便宜，生意能否持续存疑。Token越便宜，卖Token越难赚钱；新模型送额度、云厂商折扣多含推广成本，长期价格未必低。头部模型最佳实践趋近，换模型机会成本降低，开发者开始“货比三家”，建议业务代码别绑死单一SDK、留统一接口、准备降级路径。模型公司为获回报向应用层迁移（编程工具、Agent、办公入口）。泡沫若破，先消失的或是补贴与“套壳”产品。Kedrosky判断大模型最终会像电力退到幕后，竞争壁垒留在行业数据、工作流与交付责任，而非仅“接上了电”。
