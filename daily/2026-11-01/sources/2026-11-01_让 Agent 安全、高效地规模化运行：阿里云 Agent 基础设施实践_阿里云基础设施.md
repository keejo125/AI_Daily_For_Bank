# 让 Agent 安全、高效地规模化运行：阿里云 Agent 基础设施实践

来源：阿里云基础设施
原文链接：https://mp.weixin.qq.com/s/EIjZNyXnZLp41B6xC3jvHg

本文根据 2026 云栖大会「构建 Agent Infra - 智能体与大模型训推生产级实战与解析」分论坛上，阿里云智能集团资深解决方案架构师杨旭分享的《企业级大规模 Agent Infra 解决方案最佳实践》主题演讲。从个人“养虾”兴起，到 Harness 工程在云上大规模落地，Agent 的运行需求持续变化。阿里云在服务客户的过程中，围绕沙箱与 Agent Infra 持续演进产品，并积累了规模化实践经验。如何推动 Agent 从单机运行走向企业级大规模、安全、稳定运行，是我们需要解决的核心问题。从客户需求变化看 Agent Infra 的建设重点&nbsp;在客户实践中，Agent 基础设施需要回应的变化体现在运行方式、业务集成与运行保障等多个层面。这些需求共同指向一个目标：让 Agent 贴合企业业务，安全、稳定地持续运行。在运行方式上，桌面助手让 Agent 更易融入日常办公，也带来了端云协同需求。例如，任务尚未结束，使用者便需要携带电脑往返于不同会议室，本地设备的使用状态因此成为任务执行时必须考虑的因素。云端运行支持任务持续执行的需求；桌面客户端、Web 与 IM 等不同入口，则需要与适合业务的运行环境相衔接。在业务集成上，企业关注如何将 Agent 与自身业务及数据安全要求相结合。许多企业选择自研 Agent，但自研并不意味着需要从头开发 Harness 框架。基于 Qoder、Claude Code 等成熟框架进行扩展，可以提升研发效率。企业仍需接入和管理自身沉淀的 Skills、MCP 等业务能力，并处理用户鉴权、资源隔离等问题。在运行保障上，关注点不能仅停留在 Agent 能否运行。规模化应用既要兼顾执行环境的性能、弹性与稳定性，也要将安全要求落实到数据、身份、工具和运行过程。与此同时，Context Engineering 将关注范围从 Prompt 扩展到记忆与知识管理；Agent 的结果准确性、运行行为和 Token&nbsp;消耗，也需要持续观测与评估。这些要求共同构成了企业级 Agent 基础设施的建设重点。这些需求涉及运行环境、数据安全与持续治理，难以依靠单一产品解决。因此，阿里云 Agent Infra 围绕执行环境、上下文、工具、安全与模型组织相关能力，为不同形态的 Agent 提供基础设施支撑。以沙箱为例，其底座源于阿里云弹性计算团队十六年的积累，既支持沙箱快速启动，也能在超大规模场景下兼顾启动效率、长时间运行的稳定性与资源利用效率。在这一底座之上，阿里云 Agent Infra 聚焦 Environment、Context、Tools、Security 和 LLM 五个领域。Environment 提供沙箱隔离、高效且相互隔离的文件系统、网络控制，以及 Agent 工程的评估与观测；Context 管理 Memory 与 RAG，负责与记忆和知识相关的上下文。Tools 包括 Skills、MCP 与即开即用的工具沙箱，支撑方法封装与工具交互。Security 覆盖身份鉴权、安全防护与审计。LLM 则是整个工程的大脑；这套基础设施既支持千问模型，也支持企业自有的后训练模型。这些能力通过接入层服务于不同形态的 Agent。桌面客户端、Web、IM 通讯工具与 API 均可接入，企业可以继续使用适合自身业务的入口。执行环境沙箱、存储、网络与可观测Agent Sandbox：兼顾隔离、弹性与成本在 Agent Serving、强化学习和评估评测等场景中，客户对执行环境的要求不止于启动速度：运行过程需要建立清晰的安全隔离边界，规模扩大后需要保持启动效率与运行稳定性，负载波动时还要兼顾资源利用率与成本。这些要求共同构成了沙箱能力的建设重点。阿里云智能体沙箱 Agent Sandbox 围绕这些需求提供极速版与容器版两种产品形态，并于大会当天上午完成品牌发布。100% e2b兼容的同时，极速版面向开发者，强调易用性与启动速度；容器版围绕容器生态，团队可以沿用 Kubernetes 的管理方式管理沙箱，在选择执行环境时兼顾场景要求与原有技术体系。沙箱首先需要建立清晰的隔离边界。在客户，尤其是头部基模客户的使用场景中，沙箱攻击与逃逸是不容忽视的问题。Agent Sandbox 通过 MicroVM 技术提供 100% 环境隔离，支持存储动态挂载以及用户级文件路径隔离。网络侧支持 L4/L7 层出网管控，可按 IP 和域名进行控制；多 Region、多集群容灾则用于提升整体可靠性。弹性能力不能只看单机测试结果，还需要在规模化运行中衡量。阿里云上运行的沙箱已经超过千万。在大规模运行方面，Agent Sandbox 单 Region 支持百万级沙箱，Region 级并发创建能力达到每分钟 10 万个。在单租户启动速度指标方面，1000 实例并发创建小于 1 秒（P99）。规模化实践还需要应对百万级镜像数量带来的启动挑战，以及实例休眠、唤醒的成功率等问题。除快速启动外，成本还与负载分布相关。自建环境常面临上班与下班时段负载不匹配的问题。Agent Sandbox 通过休眠唤醒帮助客户节约成本，并结合存储介质分层、面向不同场景的存储选择和 QoS 算力选择，适配不同的性能与成本需求。在开发与管理方式上，E2B 已接近事实标准。Agent Sandbox 对 E2B 提供近 100% 兼容，并支持 Extension 扩展，提供云资源的原生配置管理能力。容器生态则延续原有管理方式，团队可以继续使用原有 Kubernetes 配置管理集群。存储动态挂载与用户级文件隔离执行环境的隔离需要进一步落实到用户文件。这里既涉及会话调度需求，也涉及文件访问边界：同一用户的不同 Session 可以指定调度到同一实例，实现会话亲和；不同用户则需要划分各自的存储目录，保持租户隔离。Agent Sandbox 通过动态挂载存储以及租户隔离技术实现用户级文件系统隔离。在满足隔离要求的基础上，存储还需要匹配数据规模与读写特征。面向海量租户隔离和小文件读写需求，AgenticFS 提供针对 Agent 场景的文件系统能力。在评估百万级目录树等大规模场景时，还需要关注 IOPS 等性能要求；与传统 NAS 的比较也应结合具体读写负载，而不能只看存储类型。当业务更关注本地读写的极低延时与超高 IOPS 时，可以选择块存储 EBS；当数据规模较大、成本控制要求较高时，对象存储 Agentic Bucket 则提供另一种选择。不同存储形态各有侧重，企业可以根据业务的性能与成本要求进行选择，并配合动态挂载机制落实文件隔离。可观测、评估与持续优化具备运行环境与文件隔离能力后，还需要了解 Agent 在沙箱中的运行情况。Agent Sandbox 集成阿里云 AgentLoop 的能力，让黑盒运行过程变得可知、可控：从沙箱启动开始接入数据，基于数据开展测试与调试，再将反馈用于模型与 Agent 优化。数据可以通过 SLS 日志接入；采用代码开发方式时，也可以集成 SDK，通过探针采集端到端数据。持续实践与反馈有助于提升推理质量、缩短故障定位时间、优化 Token 成本，并对 Agent 在沙箱中的行为进行全链路审计与观测。上下文与工具记忆、知识和外部交互Context：记忆与知识管理执行环境解决 Agent 在哪里运行的问题，上下文管理则回应 Agent 如何沉淀业务交互中的记忆，以及如何使用企业知识。记忆管理关注持续交互中反复出现的信息：人、组织、项目和工具等高频信息可以自动沉淀为画像，通过记忆图谱进行组织，并利用记忆去重处理重复内容。作为 Harness 工程的关键能力，Memory 在持续沉淀与优化的同时，也需要保持隔离边界。知识管理侧重企业知识的组织与分析，不能停留在 RAG 的 Embedding 与向量化流程。高质量知识需要结构化入库，知识库文档还需要接受自动分析，以推动知识自进化。记忆管理与知识管理的关注对象不同，但都服务于 Agent 对上下文的使用。针对这些需求，阿里云接入了各有侧重的产品能力。需要融合记忆与知识、进行结构化抽取时，ContextDB 提供相应能力；更侧重文档语义分析与文档自进化时，计算平台的企业知识引擎提供支持；主要关注存储成本时，表格存储 Agent Storage 提供低成本的存储选择。企业可以根据自身对记忆、知识和存储成本的要求，通过 Agent Sandbox 集成相应产品能力。Tools：Skills、MCP 与工具沙箱上下文提供记忆与知识，工具则支持 Agent 与外部世界交互。Skills 用于封装工作方法，MCP 则让外部工具能够被发现和调用。阿里云通过官方 Agent Skills 门户提供云产品的 SKills 托管；阿里云百炼 MCP 市场则提供多种 MCP 工具，便于集成。在工具运行环境方面，Agent Sandbox 预置了 Code、Browser 等多种工具沙箱模板，可以一键唤醒和拉起，方便开发者使用。方法封装、工具发现与工具沙箱，分别对应 Agent 使用工具过程中的不同环节。全生命周期安全身份、内容、Skills 与运行时随着 Agent 使用上下文、加载 Skills 并调用外部工具，安全防护也不能仅停留在运行环境隔离层面。Prompt 攻击与 Skills 投毒是在“养虾”热潮中被频繁讨论且较难解决的问题。阿里云围绕沙箱与 Harness 工程的生命周期，针对身份、内容、Skills 和主机等不同攻击场景提供安全能力。身份防护首先需要控制调用权限。Agent Identity 提供身份防护；沙箱获得授权，并不意味着可以不受限制地调用后端任务。沙箱访问后端时，通过临时凭证控制权限。在内容与 Skills 防护方面，AI 安全护栏通过扫描提示词，提供提示词注入防御与内容合规检测。企业将 Skills 托管到阿里云官方平台后，平台可以进行自动安全扫描。主机攻击与 VM 时代存在相似之处，也涉及 0-day 漏洞等问题，需要依托阿里云长期积累的主机安全能力进行防护。这些能力与沙箱隔离共同覆盖 Agent 运行过程中的不同安全环节。客户实践大规模镜像启动与端到端安全MiniMax 的 RL 实践体现了规模化镜像启动面临的挑战。MiniMax 在阿里云上运行了数百万个沙箱，最大的困难是百万规模镜像的拉起速度。当场景从单机扩大到百万甚至千万级规模时，需要整套基础设施协同支撑。网络与镜像加速、带宽控制，以及启动过程中的磁盘和网卡接入，都需要进行优化。这类实践体现了阿里云对超大规模强化学习的支撑能力。智谱（Z.AI）的serving场景还同时关注启动速度以及端到端安全，包括Skills 投毒防护、运行环境安全检测等。从客户需求出发持续演进 Agent 基础设施MiniMax 与智谱的不同应用场景实践呈现了对不同的基础设施要求：RL突出超大规模场景中的启动效率，serving则更关注启动速度与端到端安全。这些诉求表明，启动速度、运行稳定性与安全边界，都需要相关基础设施协同支撑。从执行环境，到记忆与知识管理、工具交互，再到身份与运行时防护，阿里云 Agent Infra 围绕这些需求组织产品与解决方案。其价值不仅在于让 Agent 运行起来，也在于帮助企业建立可隔离、可观测、可持续优化的运行体系，在适配业务的过程中兼顾效率、成本与安全。Agent 的运行需求仍在变化，基础设施建设也需要持续回到客户业务中，识别新的执行方式、规模要求与治理问题，并据此调整产品能力和方案组合。这也是阿里云围绕沙箱与 Agent Infra 持续演进的方向：以客户需求为起点，让基础设施更好地支撑业务与技术演进。
