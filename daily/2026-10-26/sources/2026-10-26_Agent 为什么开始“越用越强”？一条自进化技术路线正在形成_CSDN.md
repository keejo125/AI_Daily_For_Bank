# Agent 为什么开始“越用越强”？一条自进化技术路线正在形成

来源：CSDN
原文链接：https://mp.weixin.qq.com/s/FTwnKf9mEiDb4VJwjuH4WA

责编 | 梦依丹
出品 | CSDN（ID：CSDNnews）
上周六是 1024 程序员节，笔者在朋友圈看到不少开发者调侃：今年可能是最后一届「程序员节」了，明年是不是该改成「
1024 Agent 节
」了？
玩笑背后，是过去一年 Agent 能力的快速跃迁——从写代码、调用工具、浏览网页，到执行越来越复杂的长程任务。
当下，比“
Agent 能做多少事
”更加值得关注的是 Agent 怎样从经验中持续学习，让自己变得更强？
11 月 20—21 日，2026 奇点智能技术大会将在北京万达文华酒店召开，本次大会特设置了「大模型技术：从 Agentic Scaling 到自进化」专题，汇聚 OpenAI、小米 MiMo、腾讯 WorkBuddy、面壁智能、Frontis.AI、PenguinHarness 等一线研究者与工程团队，从强化学习、数据飞轮、Harness 到 AI Infra，集中讨论一个更具体的问题：AI 的下一步，如何从能力越来越强走向真正的持续自我改进？
从 Scaling 到自我改进，AI 的下一步是什么？
过去，大模型能力提升的主线是更大的模型、更丰富的数据、更强的计算能力。但当模型进入 Agent 阶段之后，新的 Scaling 问题开始出现。
Agent 不再只是被动接受 Prompt，它开始与环境持续交互、执行任务、调用工具，也开始积累大量真实经验。这些经验，能不能反过来让模型和 Agent 自身持续进化？
在本届大会现场，
奇点智能研究院院长、CSDN 高级副总裁李建忠
将围绕《
AI 智能体生态的研究和思考
》，从更宏观的视角讨论 Agent 生态正在发生的变化。
而在「大模型技术：从 Agentic Scaling 到自进化」专题中，这个问题还将被进一步拆开。
新浪微博首席科学家及 AI 研发部负责人张俊林
将带来《
AI 自我迭代改进（RSI）：方法、实践及其局限
》的主题分享。
RSI，也就是 Recursive Self-Improvement，递归自我改进。相比“AI 能不能自我进化”这样的宏大判断，更重要的问题其实是：
今天已经有哪些可行的方法？
哪些路径正在被实践？
真正的瓶颈又在哪里？
南京大学人工智能学院副院长、教授俞扬
将围绕
大模型强化学习
展开分享。
强化学习仍然是让模型从反馈中改善行为的重要技术基础，而当 Agent 开始进入复杂任务和真实环境，如何利用反馈持续改善模型行为，也正在成为下一阶段
能力演进的核心问题之一。
Agent 用得越多，真的能变得越聪明吗？
如果说自进化真正发生最现实的一条路径可能不是“模型突然学会修改自己”，而是先建立一个持续运转的数据飞轮。
腾讯 WorkBuddy 模型研发负责人董汉德
将带来《
LLM Agent 的模型数据飞轮——WorkBuddy 持续学习经验
》主题分享。
Agent 产品与普通模型最大的不同之一是它每天都在与真实用户、真实任务和真实环境发生交互。
这些交互过程中，会产生大量新的数据，比如 Agent 做了什么、环境发生了什么变化、用户在哪里介入、哪些步骤成功了……
这些看似普通的产品数据，实际上包含了大量高价值训练信号。
WorkBuddy 长期在尝试解决的一个问题就是如何把「
Agent—环境—用户
」的真实经验，转化为下一轮模型训练可以利用的信号。
最终形成用户 → 数据 → 模型 → 产品 → 新数据不断循环的数据飞轮。
这可能是 Agent 从被训练一次走向持续学习的关键一步。
自进化不能只靠“反思”，它还需要一套可度量的闭环
Agent 真正要做到自我改进，还必须解决怎么稳定地进化和怎么知道自己真的变好了这两个问题。
来自
PenguinHarness、LlamaFactory 作者郑耀威
将带来《
低成本、高收益的自进化 Agent 闭环构建实践：从 LlamaFactory 到 PenguinHarness 的技术演进
》分享。
从 LlamaFactory 出发，团队历时半年打造了开源智能体自进化引擎 PenguinHarness。
核心并不是简单让 Agent 反思一下，而是建立一套完整闭环，从数据生成→ 多智能体评估→ Harness 自动迭代→ 再评估。
团队还发布了 GDPevo，用于评估 Agent 在具有经济价值任务上的进化能力。
在实际测试中，平均准确率提升 18.8%，Token 成本节省 7.5%。同时还将展示“0.2 元 + 一句话生成完整 AI 应用”的实践，以及成本仅为 Claude Code + Opus 1/70 的落地数据。
自进化不能只停留在概念上，它必须可以被评测、被验证，也必须算得过成本账。这也是 Agent 真正进入生产环境之后必须面对的问题。
当 AI 不再只是被训练，而是开始参与“训练 AI”
如果再往前一步，自进化就不只是让 Agent 改善自身行为。AI 还可能开始参与 AI 系统本身的研发。
来自
衔远科技（Frontis.AI）CTO 张开颜
带来的《
元智能体驱动的 AI 训练与自进化：AI4AI 技术与产业实践
》就围绕这一主题展开。他的分享会围绕 Frontis-MA 系列元智能体模型展开。
所谓 AI4AI 核心就是让 AI 参与 AI 的研发。从任务环境构建、自主实验，到训练、评测和经验学习，元智能体开始进入整个模型研发流程。
自进化真正落地并不是让模型无限尝试，而是让 AI 在现实工程边界之内持续寻找更优解。
当 AI 开始写训练框架、算子和推理内核
如果 AI 参与研发已经足够令人兴奋，那么再往前一步，就是：AI 开始制造 AI。
面壁智能技术合伙人、智能进化首席科学家李宇轩
将分享《
AI 制造 AI：从五级演进框架到 AI Infra 的自主生成
》。团队提出了 AI 制造 AI 的五级演进框架，从辅助建议到自主探索，描述 AI 参与 AI 研发的不同阶段。
在这个过程中，他们进一步总结出一套锻造工程的方法。
当 AI 写代码的成本越来越低，工程设计未必还要优先追求一份通用实现覆盖所有场景。相反，可以让 AI 针对不同需求，自动生成更垂直、更专用的实现。
目前团队已经完成三项工程实证：
AI 自主锻造训练框架，性能超越 Megatron-LM，并承担生产级预训练；
AI 锻造算子库，在不同场景下超过公开最优实现；
AI 锻造推理内核，速度超过 SGLang 等主流引擎。
从模型研发，到算子，到推理内核，AI 正在逐渐进入 AI 系统的底层。
越强的 Agent，越需要更强的底层系统
当然，自进化并不会凭空发生。
Agent 越复杂，任务越长，模型需要处理的上下文越多，对底层推理系统的压力也就越大。
小米 AI 平台部语言模型推理负责人张晨
将带来《
小米 MiMo 长上下文推理的系统优化与生产实践
》分享。当长上下文为多轮交互、代码智能体和多模态理解提供了更大的能力空间。但真正进入生产之后，它会迅速带来一系列系统问题。
因此，小米 MiMo 在基于 SGLang 的长上下文推理实践中，围绕 KV Cache 管理、多级缓存复用、传输优化、动态分桶、缓存亲和性调度、Prefill–Decode 分离、投机解码、低精度执行进行了系统优化，并结合真实生产负载，讨论如何从瓶颈定位、方案验证走到灰度上线。
这场分享也提醒我们，当 Agentic Scaling 越往前走，模型能力和系统能力就越难分开讨论。
从“
会完成任务
”到“
会持续进化
