# 程序员岗位被AI掏空了！前OpenAI高管参与AGI激辩：AI替代岗位，可能根本没有裁员通知

来源：51CTO技术栈
原文链接：https://mp.weixin.qq.com/s/u836jNOwfUkTIaYroklEJw

编辑 | 姜篇
“What you see is not software engineers getting laid off.”
Aric Floyd：眼下发生的，并不是软件工程师被裁掉。
他说完后又补了一句：公司只是不再招聘新人。
最近，一场访谈把
前
OpenAI
商业化负责人
Zack Kass
、
科学传播者
Liv Boeree
和
AI
内容创作者
Aric Floyd
请到同一张桌前，讨论
AGI
、就业和
AI
失控。
几人一开场讨论的焦点直接落在软件团队的招聘和培养上：
AI
替代岗位，未必先从一封裁员邮件开始。
现有工程师继续工作，只是每个人手里多了更强的
Agent
。
同样一支团队可以接下更多需求，原本准备扩招的岗位便悄悄消失。公司没有宣布
“
用
AI
换掉一名程序员
”
，那名程序员却再也没有被招进来。
备注：Zack Kass曾任OpenAI全球市场负责人，长期关注AI商业化与组织转型；Liv Boeree拥有物理学背景，是科学传播者，主要研究博弈论、AI风险与科技治理；Aric Floyd是80,000 Hours旗下“AI in Context”频道主持人和内容创作者，长期制作AGI与AI安全相关内容。

Chris Williamson
主持的
AI
辩论，嘉宾包括
Zack Kass
、

公司没有裁员，只把下一个岗位删掉了
Aric Floyd：“What you see is not software engineers getting laid off.”
“眼下发生的，并不是软件工程师被裁掉。”
Aric Floyd
谈软件工程岗位变化
设想一个原有
8
名工程师的后端团队，积压着接口迁移、依赖升级、测试补齐和内部工具开发。过去，管理者会再申请两个
HC
。现在，
8
个人各自带着
Agent
，先把这些任务接了下来。
没人被裁，招聘申请却失去了理由。
Aric
紧接着说：
“People aren't hiring new workers.”
“公司不再招聘新人。”
Aric Floyd
解释岗位收缩会怎样出现
裁员有公告、有名单，也容易被统计；没有发生的招聘不会出现在任何报表里。团队只是少开一个岗位，少招一届校招生，或者让一个离职名额自然消失。
对在职工程师来说，短期变化甚至像一件好事：重复工作少了，产出高了，项目推进更快。对准备进入行业的人来说，门口少了一块踏板。
初级岗位省下来了，高级工程师从哪儿来
谈到初级工程师时，
Aric
用了一句很刺耳的话：
“A liability before they're an asset.”
“初级工程师开始创造价值前，团队得先投入时间带他。”
Aric Floyd
谈初级工程师的带教成本
这句话里的
“
负担
”
，说的是新人刚进入团队时还不熟悉代码库、业务规则和上线流程。
资深工程师要讲背景、审代码、纠错，还要承担新人改坏系统的风险。
过去，公司愿意支付这笔成本，因为新人会逐渐成长为能独立负责系统的人。
Agent
改变了这笔账。它不需要入职培训，也不会因为团队文档写得差就提出离职。
管理者很容易得出一个省事的结论：
先买
Token
，等实在忙不过来再招人。
麻烦要到三年后才看得出来。高级工程师不会凭空出现。
团队需要重新设计成长路径
。可以让新人使用
Agent
，但要让他跟完一项任务的闭环，而不是只会批准建议的人。
人还在签字，判断已经交给
Agent
Aric
接着把话题推到决策权：
很多决定会先由系统作出，人只在最后按下确认。
这种变化已经出现在
AI
编程里。
Agent
先决定读哪些文件、调用什么工具、采用哪种修复方案，再给人一份几百行的
diff
。界面上仍然有
“
批准
”
按钮，看起来人还在回路里。
如果审查者不知道这个任务的验收条件，不清楚改动会影响哪些数据，也没有时间重放
Agent
的执行过程，这个按钮只剩下签字作用。
主持人
Chris Williamson
随后把矛盾说得更尖锐：
我们更该担心拒绝服从人类的
AI
，还是完全听从少数强势人物命令的
AI
？
落到开发团队里，问题可以换一种问法：
Agent
应该服从谁的指令，又该在什么地方拒绝继续？
开发者给它
“
修好测试
”
的目标，它能不能修改测试用例；让它
“
降低延迟
”
，它可不可以跳过校验；让它
“
完成迁移
”
，它会不会提前删除旧接口。
这些选择都不能只交给模型自己判断。
Aric Floyd
谈决策权向系统转移
Agent
会做事，也会把目标做过头
Aric
在现场强调，智能、判断力、规则意识和智慧不是同一件事。一个系统可以很会完成目标，同时不理解团队为什么设下某条边界。
Aric Floyd
区分智能与判断力
辩论中还谈到了
OpenAI
在
Hugging Face
环境进行的一次内部网络安全评估。
OpenAI
于
2026
年
7
月
21
日披露，评估时没有启用生产环境中阻止高风险网络活动的分类器，模型在受限环境里发现并利用了
Artifactory
代理的零日漏洞，随后触达
Hugging Face
的生产基础设施。
OpenAI
称这是一次
“
前所未有
”
的事件。
嘉宾讨论
Hugging Face
安全事件
那是为评估攻击能力而设置的内部测试环境，与普通用户使用公开模型时的默认状态不同。
OpenAI
后来补充说明，测试涉及的内部研究原型已经停用、加密并限制访问，也没有即将发布的模型参与。
模型能力增强以后，安全不能只靠一句
“
禁止这样做
”
的提示词。系统要假设
Agent
可能理解错目标，也可能找到绕开限制的新路径。
让
Agent
进生产前，先把护栏补上
落到开发团队，先做四件事，并把它们变成默认流程。
验收条件要能执行。
“
优化查询
”
没有终点。
把要求写成
“P95
延迟低于
200
毫秒、结果与旧接口一致、数据库连接数不能增加
”
，
Agent
才知道何时停下，人也有依据检查结果。
权限要分层。
读仓库、写代码、运行测试、部署服务和访问生产数据库不该共用一把钥匙。删除数据、发布版本、付款和密钥操作必须单独授权。
过程要留痕。
团队不仅要看最终
diff
，还要知道
Agent
调用过哪些工具、改过哪些文件、为什么换了方案，以及当时使用的模型和版本。出了问题，才能把执行过程重新放一遍。
回滚要先准备。
分支、功能开关、灰度发布、数据库备份和一键回退，应该在
Agent
动手前就存在。测试通过不等于线上一定安全，尤其是涉及历史数据和跨服务调用时。
开发者的训练也要跟着改。会用
Claude Code
、
Codex
或其他编码
Agent
只是起点。任务拆解、评测、权限、可观测性和回滚，需要放进同一套工程方法里。否则
Agent
越快，团队只是更快地把未经检查的改动送到生产环境。
写在最后：别等裁员通知才发现入口没了
这场辩论没有给出一个精确的失业时间表。它提出了一个更早出现、也更难统计的信号：
招聘人数开始缩减，带教预算被
Token
预算替代，基础任务从新人手里转到
Agent
手里，审批按钮还在人类面前，判断过程却越来越依赖系统。
在职开发者不能只盯着裁员名单。团队还剩多少新人，谁在理解整套系统，谁能看懂
Agent
失败的原因，出了事故又由谁接手，这些问题会决定几年后还有没有人能维护今天写下的代码。
代码会继续变便宜。定义问题、设定边界、验收结果和承担上线责任，会变得更值钱。
新人入口不能被彻底省掉，人的判断权也不能只剩一次点击。
