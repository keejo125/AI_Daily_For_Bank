# 我给 WorkSwarm 出了 5 道难题，它用一支 AI 团队接了招

来源：CSDN
原文链接：https://mp.weixin.qq.com/s/z8o2fs31WUK0PgF811UODA

又来一个说要"颠覆办公"的。
什么“一个人顶一支团队”，什么“效率提升十倍”——这类话术，今年你已经听过不下十遍了吧？作为编辑，每周收到的"AI 办公颠覆者"通稿没有五份也有三份，套路都差不多：概念很宏大，录屏很模糊，一问细节就开始打太极。
更根本的问题在这：一年多来，AI 办公工具装了一茬又一茬，大多数人的工作方式其实没怎么变。窗口里是多了一个对话框，能问问题，也能让它写个段子，可真到干活的时候呢？任务还是得自己拆，资料还是得自己开着十个标签页查，不同软件之间来回复制粘贴，每个环节的产出也得自己核。AI 变聪明了，你却还是那个包工头，拆活、派活、验收、催进度，一样都少不了。所谓人机交互，一直停在"一问一答"。
所以当 openJiuwen（华为 2012 实验室、华为云、终端、计算多方共建的开源 AI Agent 平台）把原来的蜂群智能体升级成 WorkSwarm，宣称要让人拥有"一支 AI 团队"时，我的第一反应不是兴奋，而是老编辑的职业反应：先怀疑，再验证。不过它上了鸿蒙 PC 应用市场，Windows、Mac、Ubuntu 也都能装，声势确实不小。
那好，概念咱不聊，直接出 5 道题，全是打工人的真实难题：上手门槛、团队成色、双模式对比、一句话出应用、音乐创作加人机接力。做不做做到，录屏见。
五道题，逐一验
题目一：第一个 Hello World，门槛有多高？
出题动机
：一个工具吹得再神，第一步就把人卡死，那也白搭。这道题测的是，从"听说过"到"跑通第一个任务"，普通人得跨多高的门槛，尤其是那些连软件都懒得装的人。
我准备了两条路，都亲自走了一遍。
路线 A：在线体验，什么都不装。
从官网点"在线体验"，会跳到华为云开发者的 AI DevSpace，一键拉起一个 AI Shell 环境。安装包不用下，环境变量不用配，在浏览器里等一小会儿，命令行界面就绪。更关键的一点：
Token 免费，而且不限量
。我抱着"羊毛必然有坑"的怀疑连跑了几个任务，没撞上付费墙，也没被限次。
有一点要提醒：首次进入得登录华为云账号，没有就用手机号注册一个，很快。
第一个任务我故意挑了个最日常的：
帮我查一下 2026 年办公智能体行业的最新动态，整理成一份简报。
任务跑完，一份带来源、分要点的简报直接生成。从点开官网到拿到结果，我全程没离开浏览器，没碰安装包，也没遇到"配置环境失败"这种劝退环节，更没有先充 10 块钱才能体验的套路。对"就想先看看它到底行不行"的人来说，这条路线花的耐心，大概跟刷三条短视频差不多。
路线 B：装到本地。
官网下载页拿 Windows 安装包，双击、下一步、装完、启动，一路顺利，没碰上"依赖缺失""版本冲突"这类祖传报错。鸿蒙 PC 用户在应用市场搜一下就能装，Mac、Ubuntu 和 pip 方式也都支持，这里一句带过，不展开。
我这里用的是 Windows 11 系统做安装演示。
不过有个本地路线的真实门槛要如实记录：
首次启动后得先配模型
。WorkSwarm 本身是流程编排工具，不带模型能力，要在设置里接入一个 AI 模型才能开工。华为云 MaaS、OpenAI、DeepSeek、DashScope、SiliconFlow、OpenRouter 等 OpenAI 兼容接口都支持，本地部署的模型也行，填上 API Key 就能用。有 AI 使用经验的人一分钟搞定；纯小白可能会在"去哪申请 API Key"这一步卡一下。官方建议多配几个模型防止集群并发限流，顺手配两个，后面跑集群任务会稳很多。
判定：过关。
在线路线把"试用一个新工具"的成本压到了几乎为零，不装软件、不心疼 Token，对我这种"尝鲜五分钟、卸载两小时"的用户相当友好；本地路线安装本身无坑，唯一的小台阶是配模型 API Key。想深度用、要让它操作本地文件的，再走本地安装也不迟。两条路分工很清楚：
在线管"先看效果"，本地管"真干活"
题目二：它凭什么叫"团队"？
出题动机
：界面打开，凭什么叫"团队办公室"，而不是又一个换了皮肤的聊天窗？
装完第一次启动，我看到两个空间：
"工作"
和
"Code"
。工作空间管日常事务，写材料、做调研、整数据都在这；Code 空间面向开发，题目四会用到。这个划分本身就在表态：它把自己定位成"干活的地方"，不是"聊天的地方"。
真正的差别在模式上。系统提供三种执行模式：
性能模式
管简单任务的快速响应，
规划模式
让复杂任务分步执行、每步可确认，
集群模式
则由 Leader 编排多个专业 Agent 分工协同。前两种说到底还是"一个助手"的两种干法，集群模式才是它敢叫"Super Teams"的底气：领到任务后自动拆解、组队、分工。
我随手丢了个中等复杂度的需求进去：
调研三个桌面 AI 办公工具的优缺点，做成对比表格。
集群模式一启动，界面左侧开始冒出"成员"：有负责统筹的 Leader，有分头干活的成员，每个人有自己的角色名和任务状态。任务流转到谁手上、产出了什么文件，一条时间线看得清清楚楚。中途我能 @ 任何一个成员追加要求，也能往团队里临时塞个新角色。
这跟"聊天窗"的区别是结构性的。聊天窗里，你和 AI 一问一答，信息只在一个维度上滚动；这里你面对的是一支有组织、有分工、有交接的队伍，界面按"组织"来组织信息：谁在队里、谁在干什么、干到哪了、交付了什么，一眼扫过去全有。而你，站在队伍之上。
顺带一提，单 Agent 模式我也试了。切回去的瞬间，界面退化成熟悉的聊天窗，一个助手包办所有。这种"来回切换"的对比本身就挺有意思：
同一款产品，两种世界观。
判定：
过关。"团队"不是营销话术，界面的信息组织方式就是按"组织"而不是按"对话"设计的。第一印象成立。
题目三：单助手 vs 蜂群，真能拉开差距？
出题动机
：界面像团队，不代表干活就像团队。同一个任务跑两遍，单 Agent 一遍、集群一遍，差距是玄学还是肉眼可见？
任务我故意挑了个特别日常、人人用得上的：
做一份周末北京两日游计划
。需求就一句话：
帮我做一份周末北京两日游计划：查天气、各挑两个景点和一家餐厅，汇总成一页行程表。
别看任务小，结构却很典型：查天气、选景点、选餐厅、汇总排版，天然就是四件能并行推进的子任务，最后得有人整合。这正是"团队"和"助手"的分水岭题型。同一句话，分别喂给两种模式。
第一遍，单 Agent 模式。
它像个勤恳的全能实习生，一步步来：先查天气，查完研究景点，选完景点再找餐厅，最后排行程表。每一步都做得像样，但整个过程是串行的——它在查天气时，选景点的事八字没一撇；它在选餐厅时，我除了干等没有任何可以并行推进的事。不过有一点必须替它说句公道话：中途插话的体验比想象中好。它查天气查到一半，我想起要加一条“避开周一闭馆的景点”，不用等整条任务链跑完——它立刻停下当前动作，处理我的新要求、动态调整后续任务，然后接着干。响应是实时的，任务调整是即时的，这已经比“一条 prompt一件事、干完再派下一件”的传统玩法省心得多。但天花板也在这儿：串行就是串行，我依然是那个拆活、派活、验收的包工头，只是这个实习生手速快、还随叫随到。
第二遍，集群模式。
差别肉眼可见：
1. 并行
：任务一下去，进度面板上几个成员的状态同时从"待办"跳成"进行中"。查天气的、选景点的、找餐厅的各干各的，最后由负责汇总的成员收拢成一页行程表。上游互不阻塞，成品一次合入。这种"项目组开工"的既视感，单 Agent 模式给不了。
2. @ 成员提问
：行程表出来后，我 @ 了所有成员，让他们加快速度"它们都给出了回复逻辑！注意这个交互的差别：单 Agent 模式里插话虽然也能随时响应，但对象只有一个——它得放下手头的事来处理你；集群模式里@是定向沟通——我问的是“那位同事”，其他成员手头的活照常推进。我不是在“打断”谁，而是在指挥。两遍跑完，
同一个任务，单 Agent 给我的体验是"一个很快的执行者"，集群给我的体验是"一支带得动的项目组"。
判定：过关，而且是 5 道题里说服力最强的一道。
单 Agent 是"一个很能干的助手"，集群是"一支听指挥的项目组"。官方说的 HOTS（Human on the Swarm，人指挥 AI 团队），在 @ 成员提问那一刻具象化了：你不是在跟一个 AI 拉扯，而是在带一支队伍。开头那个问题也就有了答案：包工头终于可以只管验收，不用再管派活了。
题目四：不懂代码，能"白嫖"一个应用吗？
题动机
：办公场景测完，换个赛道。我一个写稿的，如果能靠一句人话换来一个能跑的应用，那才叫"生产力平权"。毕竟市面上"AI 做应用"的演示，十个里有九个是提前排练好的。
我进 Code 空间，需求只有一句：
"做一个热量记录小工具，能添加每天吃的食物、自动算总热量，界面清爽。"
标准的产品经理式一句话，零代码、零技术细节，连"用什么技术栈"都没提。
接下来的过程值得细说。系统没有直接开写，而是先做了份任务规划：拆出前端、后端两条分支各自并行开发，中间有测试角色给代码把关，最后由 Leader 统筹合入。每个分支的进度和提交记录我都看得见。虽然我一行代码都看不懂，但"谁在干活、干到哪了"是明白的。这种透明度对非技术用户是种安抚：黑盒在跑，可盒子是玻璃做的。
最后它编译出一个能直接在线运行的html。界面确实清爽，甚至比我提的要求还多了个每日趋势小图。从一句话到装上能用，我没写过一行代码，也没看懂过一行代码。
判定：过关，带半个保留。
应用本身能跑、体验完整，"非程序员当产品经理"这个说法成立。保留的地方在于，这类一句话生成的应用，复杂需求下的稳定性我还没验证过。拿它做内部小工具没问题，直接上生产环境，建议再等等。
题目五：一句灵感，能换来一首歌吗？
出题动机
：办公和编程都测完，我想用一个链条最长的创作任务，压一压"团队分工"的极限，选的是音乐创作。作词、作曲、编曲、演唱、试听、迭代，哪个环节掉链子整个作品就垮，而且各环节专业壁垒极高，最能检验"专业分工"是真本事还是角色扮演。顺便再验证一个更玄的命题：人能不能真正"加入"AI 团队，而不是站在外面指挥？
一项真正有价值的工作，往往不是一次生成能够完成的。写一份方案，需要调研、构思、撰写、审校和排版；制作一首音乐，需要作词、作曲、编曲、演唱与反复试听；多人共创一篇文章，还要同步进度、接续上下文并明确交接。
WorkSwarm 组起了一支很像唱片公司的团队：团队负责人、作词师、作曲师、编曲师、主唱、伴奏师、间奏师，七个角色各司其职。接下来不是"把几个 AI 的输出拼起来"，而是一场真的生产流程。先定 Epic Cinematic Dark Pop 的整体风格和歌曲结构，生成可试听的版本；然后各角色围绕同一版作品交叉评审：主唱从演唱角度挑咬字和气口，间奏师嫌 Bridge 转场拖沓，编曲师说 Chorus 的推进力不够，作词师根据旋律调整歌词密度。一轮一轮改下来，版本从 music-2.0 一路迭代到 music-2.6。
最终交付的不只是一首 MP3。歌词、作曲规划、编曲总结、演唱说明、伴奏建议、间奏评审、版本记录，连可复用的 Style Prompt 都沉淀了下来。也就是说，这次创作"为什么这样写、改了哪些地方、下次怎么复用"，全程有据可查。对比人类音乐工业：demo、编曲笔记、混音意见、版本管理，本来就是一套团队流程，WorkSwarm 做的就是把这套流程原样搬给 AI 团队。
判定：过关。
音乐创作这个链条最长的任务，证明了多角色分工加多轮迭代不是摆设，也证明"人作为团队正式成员"是能落地的交互，不只是发布会 PPT 上的概念图。
技术底细，我顺手查了
评测不能只看表面。我抱着挑刺的心态去翻了翻它的技术底子，还真翻出一些东西。
先查"
协同工程（Coordination Engineering）
"是不是现造的营销词。查下来不是：
这个概念今年 4 月就提出了
，是继 Prompt、Context、Harness 之后的新范式主张，把工程化重心从"单个 Agent 能做什么"转向"多个 Agent 如何像一支精锐团队协同"，而且有整套开源实现兜底，不是 PPT 架构。
再查底座成色。性能方面，
PinchBench 综合得分 94.2%，业界 SOTA，
平均 Token 消耗还降了 34.8%。
多 Agent 系统最怕"人多嘴杂 Token 爆炸"，它把这笔账先算平了。记忆方面，开源的自主生长记忆引擎 AutoGenetic Memory 设计了 L0-L3 四层记忆体系，让信息从原始对话逐级抽象成结构化知识；
在公开基准 LoCoMo 上
以插件形式接入后，
准确率提升 15%，Token 消耗降低超 60%。
调度方面也务实，支持按角色路由不同模型：Leader 用强模型，干粗活的用轻模型，这个成本分配很"工程"。
Skill 工程化这块也查到两个新东西。一个是 Skills Symphony 技能编排与智能分发系统，靠"技能检索+技能编排"双核心架构，让 Agent 在技能从 5 个膨胀到 50 个时，依然能又快又准地选对技能。另一个是 Skill-Omni 多模态 Skill 范式：给它一个网页或 B 站视频链接，系统自动提取关键截图和操作脉络，生成 Agent 可直接读取复用的多模态技能，让 Agent 的经验从"读得懂"升级为"看得见"。
算力层面与昇腾、鲲鹏亲和
，多 Agent 并发场景下首 Token 时延减半，推理存储峰值降约 25%。企业侧，它刚发布了
企业级分布式蜂群架构
，解决 Agent 从服务个人走向企业生产要跨的规模、成本、管理、安全四道门槛，
中国邮政储蓄银行已率先基于该架构落地生产环境。
这至少说明，这套架构经过了金融级场景的检验。
最后一点，也是很重要的：代码全部开源在 GitHub 和 AtomGit，Apache 2.0 协议。谁有疑问，都可以直接去仓库验证。在"套壳"质疑满天飞的当下，这是最硬的回应方式。
结案陈词：5 题战报
什么人现在就该入手？每周要产出汇报材料、文档、小工具的办公族和独立开发者。在线体验零成本，先用再决定装不装。什么人可以再等等？需要企业级权限管控和大规模并发的团队。好消息是它刚发布了企业级分布式蜂群架构，邮储银行已经率先落地生产环境，可以保持关注。
回到开头的靶子：从"一问一答"到"团队协同"，办公智能体走的这步棋，值得盯紧。而这步棋最有意思的地方在于，它赌的不是模型变得更聪明，而是组织变得更聪明。这盘棋，我愿意再看几步。
顺便说一句：他们在招人
体验完翻社区动态时注意到，WorkSwarm 已正式启动
开发者与布道师招募计划
。对开发者来说门槛很低：通过openJiuwen官网一键拉起在线体验，就能上手实践，
Token 免费不限量
。社区还备了一堆好玩的案例，20 分钟生成 200 页 PPT、用 JiuwenSwarm 自己造一款坦克大战游戏，灵感来了随时动手。
参与贡献，每月都有机会拿社区激励（"星星之火奖""新人奖"）。更实际的是成长路径很清楚：从 AI 开源爱好者到优秀开发者、资深开发者，再到预备布道师、布道师、资深布道师，每一级都有明确的进阶通道。优秀开发者可以申请
华为官方认证
