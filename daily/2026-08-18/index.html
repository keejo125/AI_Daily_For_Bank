AI时代对抗软件规模与复杂度的战争：救命、治病、养生（下篇）
茹炳晟聊软件研发
作者将“救命—治病—养生”三层软件治理框架迁移到 AI 时代，核心论点是治理对象从“写代码的人”扩展为“生成代码的模型+人机协同体”。救命层面提出“可解释性真空”（生成代码无设计意图、坏味道被工整格式掩盖）与“Coding Agent 配置漂移”（提示词/上下文库/模型版本变更即可引入故障，回滚对象首次扩展到模型与提示词版本）；治病层面强调让 AI 做“可验证的理解”、人做“不可验证的判断”，因 AI 理解是统计性而非因果性；养生层面提出“驾驭债”（约束AI的规则本身也会腐化）与递归治理（人→规则→AI→代码多层均会腐化）。结论：AI 让治病/救命更便宜、养生更贵，反而易诱使团队砍掉最关键的养生预算，复杂度失守往往始于“暂停养生”的决定。
Agent的命门是上下文：关键不在少给，而在给对
腾讯云开发者
作者以腾讯云轻量云 Devflow 多 Agent 工作流（开源 loopforge）实测“省 Token”：一个涉及十几个文件的需求吃掉约2480万Token、约202元，比加了两个“优化工具”前还贵。文章按“局部输出/行动路径/整体结果”三层拆解 CodeGraph（代码地图）与 RTK（终端压缩器）：CodeGraph 5轮A/B非缓存输入降35.5%但总输入仅降0.5%，完整调用链任务反而增95.8%；RTK 在12个任务48次运行中终端字符降40.19%，但总Token增4.23%、命令事件345→441、测试失败31→56。结论：上下文信息密度=当前步骤真正相关可执行信息÷进入窗口的全部上下文；应通过“何时给/给谁看/保留多久”提升密度——将交接拆成 Handoff+Artifact 路径、CodeGraph 仅在前段复用、RTK 按场景熔断、状态迁移交程序处理。GLM-5.2 与 Claude Opus 4.8 实测各阶段 Token 显著下降。

一家Collective AGI公司，要给人工智能加一层「组织」
36氪
文章介绍脱胎于中科院自动化所复杂系统国家级重点实验室的沌序科技，其目标不是做大模型，而是在大模型等智能单元与应用之间增加一层“Organization Layer（组织层）”，提出 Collective AGI（通用群体人工智能）。核心理念：模型产生个体智能，组织产生群体智能——通过合适规则组织简单个体，使其涌现出单一个体不具备的能力（论文中以亿级参数模型协同在真实欧冠数据上胜千亿级通用大模型为例）。公司已积累约50TB多模态无人机探测数据、1500万帧标注样本、2000多次实验，先在低空安全场景落地“群智大脑”（前端感知融合、中间调度、后端执行）。文章将其与 Shield AI、Anduril、Applied Intuition 等对比，认为其从群体智能范式出发，与基础模型厂商是合作而非竞争关系，难点在于“组织”能否脱离具体设备被复用。
人大高瓴、IQuest团队联手，把OpenClaw、Claude Code接进RL训练中
智东西
中国人民大学高瓴人工智能学院、至知创新研究院（IQuest）团队提出面向复杂 Agent Harness 的黑盒强化学习框架 ClawGym II，并已开源。与 Part I 用 Harness 交互数据训练模型不同，ClawGym II 直接将 Claude Code、OpenClaw 等真实 Harness 纳入 RL 闭环——无需改动其内部实现，仅通过模型服务边界（Serving Proxy）捕获调用、结合 Verifier 奖励优化底层策略。核心技术：①Sandbox 隔离执行与优化解耦；②基于前缀树的轨迹重建（合并公共前缀、保留分叉分支、过滤 dead leaves）；③GRPO/PPO 适配一对多树状轨迹 + Token-in-Token-out 与 importance-sampling 修正 off-policy 偏差；④Mix-Harness Training 让多异构 Harness 的 rollout 联合训练同一共享策略。以 Qwen3-30B-A3B 为骨干，在 ClawGym-Bench 上 OpenClaw/Claude Code 分别提升9.98/14.81分，PinchBench 提升11.71/17.28分，并迁移到 JobBench、OfficeQA。
