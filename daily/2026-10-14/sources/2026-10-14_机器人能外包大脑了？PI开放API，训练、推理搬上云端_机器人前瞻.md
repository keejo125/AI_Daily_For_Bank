# 机器人能外包大脑了？PI开放API，训练、推理搬上云端

来源：机器人前瞻
原文链接：https://mp.weixin.qq.com/s/n0DNahuhvufZsUrLAFBo3g

展现跨场景应用能力。
作者 |
钟宸
编辑 |
漠影
机器人前瞻10月14日报道，今天，机器人模型公司
Physical Intelligence
（以下简称Pi）宣布推出
Pi API测试版
（Pi API beta），向外部开发者提供模型训练和推理服务。
从技术博客来看，Pi API主要提供机器人
模型微调（Fine-tuning）和云端推理（Cloud-hosted Inference）
能力，开发者可上传自己的任务数据，在Pi托管的算力和基础设施上训练适配模型，再通过API调用模型驱动机器人执行任务，并根据实机测试结果补充数据、持续优化，从而减少自建模型训练与推理系统的工作。
在Pi披露的案例中，Almond团队使用该API迭代4天后，让双臂机器人Axol给自身装配所需的间隔件去毛刺，参与加工自己的零件。从视频来看，Axol可以将零件夹起，放到类似砂纸的工作台上对零件进行摩擦，并自行实现翻面操作。
由此在开源模型之外，Pi为机器人公司增加了一条托管服务的路径。开发者可以围绕自己的硬件和数据推进应用，把模型训练和运行所需的部分基础设施交给Pi。
01
.
让机器人整理餐具、做汉堡、装零件，
Pi API展现跨场景应用能力
Pi让少数公司提前访问了API，以测试其是否能自行提升自主性，具体来看，Pi展现的视频包含工业、商业、家庭等不同场景的应用，囊括餐饮配送、餐具整理、工厂上下货、餐食制作以及康养照护等不同任务。
在其技术博客的视频中，除Almond团队外，Argon Robotics在获得 Pi API 访问权限后35小时内，就打造出了一个经过精细调校的整理厨具的模型。
从视频来看，夹爪机器人的动作颇为流畅，面对人类的甩盘子、拿开架子的干扰，都能够持续进行任务，且花费时间较短。
robot.com致力于食品配送及其他商业场景的应用，这家公司也采用了Pi的模型托管推理，其人形机器人将货物放到到配送机器人的货箱中，由其进行配送。
Chef Robotics团队此前根据收集的33个双手演示数据，训练了首个协调双臂的模型。Pi API让他们得以把新收集的数据，直接在第二天就能用在机器人运行的模型上，而不用自行训练。
在演示视频中，机器人完成了制作汉堡、配比餐食的工作，虽然从环境来看，仍针对机器人做了适配，但机器人的动作相对流畅，制作汉堡仅用时一分钟。
Deft则在开发轮足人形机器人，用以辅助汽车制造车间的工作。Pi介绍道，Deft在使用Pi API自行训练新模型后，其机器人部件装载任务成功率在六天内翻了一倍多。
从视频来看，机器人完成了将部件举起、调整部件位置、装配的工作，虽然速度较慢，但整个过程中，并没有人类介入。
Pi还展示了医疗场景的应用。Omakase的机器人在97次演示的10次倒茶任务中，成功率达到100%，并且在其他机器人上运行时，不需要再像之前那样，针对每台机器人对摄像头进行校准。
在视频里，机器人完成了丢垃圾、分类药品、倒茶的操作，虽然仍为Pick and Place任务，但从Pi透露的成功率和机器人完成任务所需时间来看，已经具备一定落地能力。
值得注意的是，除上述提及的视频演示之外，Pi一共放出了15个演示视频，大部分为
1倍速录制
，其还同时展示该视频拍摄的地点，包括旧金山、奥克兰、苏黎世（瑞士）、东京、纽约等。
02
.
从下载模型到调用服务，
Pi接过哪些工作？
要理解API服务的价值，可以先看Pi此前提供的开源路径。2025年2月，Pi通过openpi项目开放π0的代码和模型权重，并提供微调与运行示例，开发者由此可以把模型适配到自己的机器人上。
不过，拿到模型之后，仍有不少工作要做。根据openpi官方文档，开发者需要整理数据格式、配置训练流程，在训练完成后启动策略服务器（Policy Server），再让机器人程序与之通信。
算力也有门槛。openpi列出的单GPU配置估计显示，推理需要超过
8GB
显存，全量微调则需要超过
70GB
显存。
对小团队而言，训练任务能否顺利启动、软件依赖是否兼容、模型服务如何维持运行，都可能占用开发时间。托管服务的吸引力就在这里：
把机器人模型做成API，就意味着开发者可以通过软件接口使用模型服务，不需要再为本地部署、基础设施建设等一系列工作投入大量资金。
Pi API此次公布的流程包括上传数据、在其管理的算力和基础设施上启动微调，再通过托管网关（Hosted Gateway）调用训练后的模型进行推理。Pi还计划随着底层模型更新，持续向开发者提供其最新模型。
但接入接口仍需要工程适配。摄像头图像从哪里来、机器人关节状态如何表示、模型输出如何送给控制程序，这些都与具体硬件有关。API降低的是使用模型服务的门槛，机器人与模型之间的信息对应关系仍要建立。
值得注意的是，远程调用还会带来新的时间开销。一次动作更新要经历图像处理、上传、模型计算和结果返回，单看模型本身计算得多快，无法得出整套机器人的响应速度。
这意味着，云端算力能减少机器人本地的计算负担，现场网络条件却会参与决定运行效果。对于需要快速响应的任务，开发者还得把通信耗时放进整套控制流程中评估。
Pi也称，多数展示应用采用
云端推理
，部分项目
也遇到了网络连接问题
。
并且在目前，想要接入Pi API，仍采用申请许可的方式，官网称将从小规模开始、分批接入。申请表会询问申请者的机器人形态、模型训练经验、已有遥操作数据（tele-op data）量，以及对云端或本地推理的偏好。
03
.
结语：模型服务走向云端，
机器人开发或重新分工？
Pi API带来的一个变化，是机器人团队可以将部分模型基础设施交给外部服务商，把更多精力投入自己熟悉的任务。Pi负责持续更新模型，应用公司负责硬件适配、现场数据采集和工作流程整合，两者有了更清晰的分工。
这种分工有望减少团队反复搭建模型基础设施的投入，但识别失败原因、积累有效数据、让机器人稳定完成任务，仍然需要应用公司在现场持续打磨。API能否帮助团队更快地将模型能力转化为可交付的产品，将决定它的实际价值。
与此同时，数据也是这类合作绕不开的问题。工业场景涉及生产信息和保密要求，机器人公司也需要考虑自身积累的数据如何被使用。企业是否愿意将数据上传至外部平台，既取决于模型带来的收益，也取决于数据使用边界和保密机制是否清晰。
因此，Pi API能否获得更广泛的使用，仍需在后续接入和实际部署中观察。
