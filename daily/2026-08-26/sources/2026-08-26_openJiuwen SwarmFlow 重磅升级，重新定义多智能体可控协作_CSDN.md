# openJiuwen SwarmFlow 重磅升级，重新定义多智能体可控协作

来源：CSDN

原文链接：https://mp.weixin.qq.com/s/r7YtXy3c0HSp7Stbs3jVYg

AI Agent 正在从"一个人干活"走向"一群人协作"。让多个智能体分工配合，去完成单个智能体扛不下来的复杂任务，已经是各家 Agent 平台共同的方向。
围绕这个方向，由华为 2012 实验室、华为云、终端、计算联合构建的
开源 AI Agent 平台 openJiuwen
，率先提出了
Coordination Engineering（协同工程）技术范式
，并建起了全栈技术：Agent Swarm 让智能体自主组队分工，Swarm Skills 把一次成功的协作沉淀成可复用的团队技能、并在使用中自我演进，SwarmSkill Creator 用一句话就能生成多角色团队。
今年 6 月开源的
SwarmFlow
，解决的是多智能体的"可控工作流编排"：生产任务的工作流程往往是固定的，要的是每次都稳定出结果，SwarmFlow 将
可编排的固定流程
和
Agent 的智能
结合起来，确定性的流程交给脚本、每一步怎么干交给Agent，搭好的流程也能作为Swarm Skill 反复使用。
不过，能稳定跑完只是第一层。多智能体协作在往
真实业务深处走，全行业都绕不开三道坎。
坎一：预算跑飞。
多智能体协作花多少很难预估：一个"生成 → 验证 → 再生成"的循环跑上十几轮，开销可能是普通对话的几十倍；要是模型或流程有问题，循环还会一直空转——钱照烧、事没成，预算还跑飞。
坎二：人插不上手。
复杂任务跑到一半，方向要改、判断要人拍板，可人没办法中途介入：要么让 AI 硬着头皮跑完，要么推倒重来，前面的投入全部作废。
坎三：想停停不下。
工作流一旦跑起来，中途发现输入错了想停下改、想把额度先让给更急的活，都做不到——想停，停不下。
最近，openJiuwen 对 SwarmFlow 进行了一次全新升级，回答的正是这三件事，当前已经可以在
WorkSwarm
蜂群办公智能体上直接体验。
先看效果
话不多说，先看三个真实案例。
案例一，预算管得住。
调研 Agent 技术并生成一份 PPT，五个专题逐轮"调研 → 验证"，
每轮先看预算余量
，一旦花超设定的预算线即刹车、收尾出稿；之后照着花费诊断改脚本重跑，已完成的部分直接复
用
缓存，不需要重复花钱调模型。
案例二，中途改得动。
规划一趟亲子游，三亚、大理、厦门三个城市并行调研后，流程停下来等待用户选择目的城市，用户不直接选而是追加需求"还想再看看丽江怎么样"，
系统识别出修改意图、补上丽江的调研
，已有的三个城市的调研成果原样保留，不用从头
再
来。
案例三，随时停得下。
做一份新能源汽车行业分析报告，调研跑完说声"先停一下"、翻看产物没问题就"接着跑"，已完
成的调研
全部复用；初稿发现方向偏了，用户说一句"这条别跑了"则会停止运行，及时止损。
看完效果，再看这三件
事是怎么做到的。
一套搭协作的"积木"
SwarmFlow 把协作需要的动作做成一块块标准"积木"，即算子
：并行（
parallel
）、流水线（
pipeline
）、批量处理（
map_parallel
）、日志（
log
）、
嵌套子流程（
workflow
）这些编排底子早已备齐
，这
次升级新增加四块：
budget
：管预算，随时能看还剩多少，花到上限就提前收尾
human / human_session
：让人参与进来，可以单次交互，也可以多轮讨论
agent_session
：让Agent有记忆，中途可以暂停，之后接着跑
需要什么拼什么，复杂的协作就这么搭出来。直接对话描述需求，SwarmSkill Creator 就能自动生成带工作流脚本的 Swarm Skill。
下面分别看看SwarmFlow怎么解决前面的三道坎。
一、预算：花多少看得见、到顶收得住
案例一里，流程在预算见底时主动收尾、保住已有产出，起作用的就是
budget
算子：先给工作流划一条总预算线，跑的时候随时看余量。尤其是在"生成 → 验证 → 再生成"这类需要多轮循环迭代
的场景，预算在每一轮都在起作用：
每轮开头
：先看还剩多少——还充足就继续，快见底就提前收尾。
每轮当中
：按剩余预算决定投入——宽裕就多开几条并行，紧张就走精简路径。
每轮结束
：这一轮花了多少、总共还剩多少，实时打进日志，全程可见。
二、人机介入：人能中途介入，改完不必全部重跑
案例二的看点是"改完不用全部重跑"，背后是
human
/
human_session
算子加一份执行账本。
人参与流程有
两种方式
：
human
答一次就走，适合"这个方案行不行""选 A 还是 B"这种单次拍板；
human_session
多轮对话、自带上下文，适合需求澄清、边问边改。
还有一种常见情况：人不是回复或确认，而是想修改工作流脚本，比如"这段不对，换个思路再来"。
系统会识别这种意图
，把"想改哪里"带回给 Leader，让人改完再接着跑，不必等整条流程跑完。
改完脚本、没改的部分不用重跑，靠的是一份
执行账本
：每跑完一步，账本记一笔——这一步在哪、问了什么、答了什么。再跑到同一处，系统先翻账本，没变的步骤直接用上次的结果，变了的才重新跑；上
游一旦重跑，下游自动跟着重跑。
三、暂
停、续跑、终止：长流程停得下、接得上
案例三里，流程停了再续、进度一步没丢，底座是
agent_session
：它派出的 Agent 自带记忆，跑到哪、
问了什么、定了什么都留得下来，长流程由此有了三种运行时控制：
暂停
：跟 Leader 说一声，或点暂停按钮——已记进账本的步骤留下，正在跑的这一步中止；Leader、聊天、团队都还在，停的只是这一条工作流。
续跑
：不新开工作流，同一次运行接着跑——账本里已有的步骤直接用结果，从没做完的地方继续。
终止
：这次运行永久结束，已跑完的结果留着；下次再跑同一条脚本，会新开一次运行。
