# 离开剪映后创业，她想把一支设计团队装进 AI 工作台

> 原文链接：http://www.geekpark.net/news/369395
> 来源：极客公园

头图来源：OJO 官网

极客公园获悉，前剪映中国负责人张琪智已离职创业，创办 AI 产品原型设计工作台 OJO，并于近日完成近亿元首轮融资，由顺为资本、联想创投联合投资，高鹄资本担任独家财务顾问。

这是张琪智离开字节跳动后的第一个创业项目。她于 2017 年加入脸萌担任产品经理，2018 年随团队进入字节，此后长期参与剪映相关产品与业务。

在外界看来，她在剪映的经历是理解这次创业的重要背景：经历了一款工具产品从 0 到 1、再到大规模增长后寻找新曲线的完整过程。而当 Claude Code、Codex、Cursor 等 coding agent 让「做出一个产品」越来越容易，她把注意力转向了产品生产链路中另一处尚未被充分解决的断点&mdash;&mdash;设计判断，以及这种判断如何在产品、设计与开发之间连续传递。

OJO 将自己定义为「Design Agent Team Workspace」。用户可以在一个工作台中，用自然语言完成产品思考、界面设计、迭代和代码交付。它所要回答的问题是：当 UI 生成、设计编辑和设计转代码逐渐普及后，一层连接设计与开发的工作台，为什么仍值得成为独立产品？

张琪智的答案是，模型越强，越需要系统把能力调度到具体场景。OJO 希望把产品定义、视觉设计、交互迭代与代码交付放进一条连续流程，减少判断在角色交接中被稀释。

这仍是一个等待市场验证的答案。

离开剪映，等到「自己和技术都准备好」
2025 年之前，张琪智在字节的职业路径颇为顺利。尽管长期在剪映业务线，她持续面对新的问题：从工具产品到全球化，从产品增长到收入和用户心智。变化发生在 2025 年，业务进入相对稳定期后，她第一次明显感到，自己的输入开始小于输出。

创业的想法因此出现，但她始终谨慎。大厂里已有成熟的组织网络，负责人更重要的工作是判断方向与推进速度；创业则意味着连组织本身都要从零搭起。她真正等待的是两个条件同时成熟：自己愿意建立一支新团队，模型能力也足以改写产品与设计之间的协作方式。

图片来源：OJO

剪映给了她一张关于产品规模的「地图」。在她看来，0 到 1 与 1 到 100 是两种完全不同的状态。剪映推出海外版 CapCut 和 PC 端时，许多决策都是团队捕捉到早期信号后快速试做、上线，再根据反馈判断是否加大投入。0 到 1 的关键，是让速度匹配时间窗口，同时控制试错成本。

进入 1 到 100 后，问题则不只在于快。随着业务逐渐成熟，过去有效的增长方式出现边际递减，团队需要从短期功能竞争，转向内容形态和生产方式的长期变化。

这段经历让她对时间窗口、早期信号和增长瓶颈保持敏感。真正促使她确定方向的技术节点，出现在 2025 年 9 月到 10 月。Gemini 的新一轮能力进展，让她第一次强烈感到，代码与审美之间原本稳固的边界正在松动。

代码有相对明确的正确与错误，设计却没有标准答案。同一套视觉语言放在不同文化、行业和消费场景中，可能产生完全不同的效果。过去，这种模糊性构成了设计与代码之间的一道墙。

但模型正在改变产品协作的起点。过去，产品经理通常先用需求文档描述想法，设计师再在 Figma 中完成静态页面、连接交互，通过镜像预览动态效果。一个方案是否成立，往往要等到设计甚至开发环节才能被真正验证。

现在，产品经理和设计师已经可以借助模型，快速生成一个可运行的动态原型。张琪智习惯先看动态交互；对她而言，这意味着产品经理可以先将抽象需求变成一个能够点击、体验和讨论的版本，提前验证产品结构与交互方向，再交由设计师和开发人员继续细化。

改变的不只是效率。产品经理可以用一个可操作的结果表达判断，设计师也不必完全等待上游需求。每个角色都能先把过去依赖下游完成的工作推进到及格线，再进入专业协作。

「我自己 ready 了，技术也 ready 了。」张琪智说。与剪映时期不同，这次需要从零设计的，不只有产品。

OJO 不想生成一张图，而是模拟一支设计团队
OJO 的第一个方案并不是现在的 Agent Team。

创业初期，团队曾为 Landing Page 找过两位外包设计师：一位擅长执行，却不愿花太多时间理解品牌；另一位能够讨论品牌，视觉落地又未达预期。大量工作最终重新回到团队手中。

这次经历让张琪智重新理解了设计协作：长链路任务缺的往往不是一个「全能设计师」，而是一套能将品牌、视觉、动效和系统设计按任务重新组合的协作机制。

团队也因此放弃了「一个 Agent 走完整流程」的设想。原因并不复杂：审美没有统一答案，用户也不会沿着同一条路径工作。

有人希望从产品策略、页面结构一路走到高保真原型；也有人只需要一个可讨论的动态方案，随后便会回到 Figma 或代码工具。排版、字体、动效、品牌叙事背后，又需要不同的专业能力。预先写死一条流程，反而会限制用户。

OJO 因而没有沿用单一 Agent 走完整流程的产品形态，而是将设计任务拆成可组合的 Agent Team 和 Skills。

单一 Agent 的局限在于，它很容易把设计压缩成一次提问与回答。但真实的设计并非一次生成：有人定义问题和产品目标，有人确定视觉方向，有人处理排版与动效，也有人不断检查结果是否偏离最初需求。设计结果，往往来自不同角色在连续协作中的判断与修正。

OJO 试图用 Agent Team 模拟这一过程。用户可以选择承担不同任务的 Agent，并通过 Skills 为其注入更具体的能力；主 Agent 则负责判断何时调用哪项 Skill 或工具，并在不同环节之间传递上下文。它希望 AI 不只是直接生成一个答案，而是能够组织并推进一段设计过程。

图片来源：OJO 官网

这些 Agent 被包装为乔布斯、梵高、达芬奇等易于理解的角色。角色名称降低了用户的理解门槛，但产品真正需要证明的，仍是角色背后的工作方法是否存在实质差异，以及多角色协作能否比单一通用 Agent 带来更合适、更稳定的结果。

在审美问题上，OJO 目前先通过预设 Skills 和工具规避明显失真，再将更高阶的风格判断留给用户。例如，团队会避免不加区分地使用蓝紫渐变或高饱和配色，但关键并非禁止某种风格，而是判断它是否与品牌、用户和使用场景相匹配。未来，团队计划进一步开放 Agent Team 和 Skills，让不同设计经验能够被沉淀、组合和复用。

OJO 当前瞄准的也不是专业设计师。张琪智认为，「真正有设计需求的人不是设计师」。设计师往往是产品经理、市场人员、创业者等上游角色找来解决问题的人。若从专业设计师切入，产品很容易落到效率优化；OJO 更想服务那些有强烈设计需求、却缺少完整专业团队的人。

内测中，一位没有设计经验的内容运营，用约一小时做出了带复杂动效的个人网站。另一名用户原本直接用 Codex 做前端，页面却在多轮修改中越来越偏离预期；他将已有结果导入 OJO 调整视觉，再回到 Codex 完成代码，项目目前准备上线。

这些案例体现了 OJO 想做的，是尽量减少模糊想法在设计和开发之间的折损。

问题同样存在。高频用户反馈过操作 Bug，也有人无法迅速理解 Agent Team 的主线。团队一度将过多理念放进界面，结果造成失焦，随后开始做减法，强化「有一支团队为你工作」的感受。

一个解决设计表达问题的产品，首先得让用户看懂它自己。

AI 设计工具的竞争，正在逼近同一个终点
OJO 出现时，AI 设计工具已经不再稀缺。

这个市场正沿两条路线逼近同一个终点：一条从设计平台出发，向原型、代码和交付延伸；另一条从 coding agent 出发，补上可视化编辑、设计系统和协作能力。

Figma、Google Stitch、腾讯 Ardot，以及 Lovable 等产品都在扩展边界。Figma Make 和 Stitch 已进入可交互原型；Ardot 用 MCP 连接设计稿与 Claude Code、Cursor、Codex 等工具；Lovable 则在可运行应用之外，继续增加可视化编辑、设计系统、Skills 或多 Agent 能力。

两条路线的终点越来越接近：一边把设计变成代码，另一边让代码具备设计能力。

这意味着，「能生成页面」很难成为长期壁垒。更值得比较的是，产品能否读懂既有品牌、设计系统、代码库与历史决策；能否在多个看似合理的方案中给出更贴近任务的判断；又能否在从产品定义到视觉、代码、上线的长链路中，尽量少丢失前面的决策。

这也是 AI 设计与 AI 编码的差异所在。代码的好坏更接近「对不对」，设计的好坏则更接近「合不合适」。前者更容易被基础模型直接吸收，后者更依赖场景、品牌和协作中的连续判断。

不过张琪智看并不把这一变化理解为模型「吞噬」应用。在她看来，被重构的不是某一种产品形态，而是行业原有的产业结构。以 Figma 为例，它在过去十余年里服务的是大型互联网软件公司的协作逻辑：设计位于产品、研发等环节之间，设计稿既是创作工具，也是团队传递信息、固化决策的共同语言。模型能力进入工作流后，首先改变的是这些上下游关系&mdash;&mdash;更多角色可以更早地产出原型、参与视觉判断，过去按职能划分的边界和组织方式也随之松动。

这不意味着应用会消失。张琪智把模型比作铁路：基础设施决定了速度和可达范围，但不会替人决定目的地、组织路线或完成服务。模型能力越强，用户与模型上限之间的差距反而可能更明显。它像一位知识越来越多的「博士」，但并非每个用户都知道如何提出任务、补足上下文、判断结果并让它持续工作。应用的价值，正是在具体场景里把这种调度能力交到更多人手中。

回到设计，张琪智认为，画图只是设计链路中最容易被看见的一步。真正影响结果的，是画图之前的产品决策、视觉方向和审美判断，以及之后持续发生的修改、协调和交付。让模型一次生成一个页面，并不等于完成了这些工作；把这一整段复杂链路都交给基础模型，也未必是最有效的分工。

这也是 OJO 想占据的位置：不与基础模型比单次生成，而是用 Agent、Skills 和工作流组织一段更长的任务，帮助有设计需求、却没有完整设计团队的用户，把想法推进到可以讨论、迭代和投产的结果。对它而言，设计决策、审美判断和对模型的控制都需要被产品化，而不是浓缩成一句提示词。

她将模型比作知识不断增加的「博士」：模型能力上升，并不意味着普通人自动成为更好的提问者。应用的价值不在于与基础模型争抢短暂窗口，而在于补上用户与模型能力上限之间的距离。

这个判断有现实依据。能自行配置模型、Skills、Tools 和工作流的人仍是少数；更大规模的用户需要学习成本更低、结果更稳定的产品。但模型也会持续压缩部分链路，重新划定垂直应用的边界。

OJO 面对的矛盾仍未解开：多 Agent 是否真能提高设计采纳率、减少返工，尚无公开对照数据；它强调 taste，却仍需建立比创始团队审美更可检验的评价方式；它希望建设 Skills 平台，也必须先获得足够的用户和创作者，才能形成网络效应。

更直接的竞争，则来自 Figma 等平台积累的专业用户、设计资产和协作关系，以及 Lovable 等产品已形成的开发与发布闭环。若只提供「更好看的页面」，OJO 很容易成为 coding agent 的临时前置步骤；只有持续保存设计决策、显著改善最终产品，并让这些能力通过 Skills 复用，它才可能成为独立的一层。

未来的应用是否仍是今天的形态，张琪智同样没有给出确定答案；它取决于模型能力、组织方式以及用户对审美和协作的重新分工。

张琪智把今年年底视为一个验证节点。届时，团队需要从用户那里获得更明确的需求信号，并判断 Agent Team 是否真的能把设计判断留在流程中、交付可投入生产的结果。

OJO 目前已在海外市场开放使用，团队也会将更多精力放在海外。国内用户与传播资源更容易启动；海外则需要更多线下社区、口碑和本地网络投入。她认为，真正的 Day One 全球化，需要接受在陌生市场投入两倍精力、可能只获得一半回报。

剪映诞生于短视频内容爆发的上升期，机会来自一种已经发生的内容变化；OJO 面对的，则是一种尚未定型的工作方式。

代码生成降低了做产品的门槛，但并没有自动补齐产品生产的完整链路。产品结构、审美判断、角色协作和最终交付，仍然需要被持续组织。OJO 试图切入的，正是这层尚未被充分产品化的空间：当 AI 越来越擅长生成，谁来负责判断？
