# 缓存为何成为金融智能应用的关键？

来源：金融电子化
原文链接：https://mp.weixin.qq.com/s/11Jj71OnEhN75BTY_sqdNA

本刊记者 杨昆桦金融业正处在从“系统自动化”迈向“智能实时决策”的深刻变革之中，这一转变也对底层数据能力提出了新的要求。实时风控、反欺诈、智能客服等场景，都依赖数据能够快速、稳定地送达AI计算引擎。在这一过程中，分布式缓存的作用被不断放大，正在成为支撑金融智能应用的关键一环。为此，《金融电子化》新媒体专访了北京内核科技有限公司董事长兼首席技术官（CTO）吕利，围绕分布式缓存技术的行业价值、金融核心场景落地实践，以及内核科技自主研发的Sudis分布式缓存，分享其对行业趋势的判断与企业的技术布局。北京内核科技有限公司董事长兼首席技术官 &nbsp;吕利缓存为什么越来越重要缓存，作为离AI计算引擎最近的数据层，正在从传统的“性能加速器”，演变成为AI应用的“智能数据底座”。吕利用一个比喻点明缓存的定位：“AI是大脑，缓存就是离大脑最近的数据层。”在他看来，AI算力再强，数据供给跟不上，所谓智能决策也无从谈起。缓存存取数据的速度与稳定性，会直接影响一笔交易的响应时长、一次风控的识别时延、一个智能客服的回答效率。随着金融核心系统加速AI化、规模持续扩大，金融缓存数据领域呈现出三方面显著需求：其一，实时性要求提升到前所未有的高度，早期“几分钟内取到数据”即可，如今反欺诈、智能客服等场景要求在秒级乃至毫秒级内完成识别与响应，延迟稍高就可能造成漏判、误判，直接影响业务与资金安全。其二，数据量呈爆炸式增长，且数据量和访问压力往往不均匀。部分金融机构的实时数据需求已达到100TB量级；在AI场景中，单个缓存对象也从过去的几KB增长到几十MB，对存取速度与时延提出了更高要求。而且，在业务数据变得越来越大的同时，有些数据经常被集中访问，如何不让个别热点“拖垮”整体，也成为目前的重点诉求之一。其三，长久稳定与高效运维是持续刚需。金融系统必须7×24小时稳定运行，核心系统对RTO、RPO有明确要求，甚至要求故障后秒级恢复、数据不丢失，因此打补丁、热升级、灾备恢复都必须纳入产品设计。面对这些关键需求，传统开源缓存在单线程架构、扩展能力与成本方面逐渐吃力。对金融机构而言，性能与可信赖同样重要——这也为能实现底层重构的厂商打开了空间。重构“新一代缓存架构”内核科技的选择，是以自主研发的核心架构，围绕多线程并行处理、分布式高可用、大Key与热Key优化、温热数据分层与智能运维等主线，系统解决性能、稳定与成本之间的平衡。针对自主可控芯片单核算力有限的情况，通过多核与NUMA感知等技术，与自主可控硬件生态协同优化，把硬件性能充分释放出来。吕利将一直以来团队的核心目标概括为“内存用一半、性能翻一番”，这也是产品设计的初衷。落实到产品端，内核科技自研Sudis回应了金融场景的真实需求，将能力归纳为“快、稳、宜、省、智”5个维度。快：采用多核多线程架构，充分发挥信创硬件性能，让一台服务器上的全部核心并行运行；同时通过NUMA感知优化，让数据在芯片内部“就近访问”，避免跨节点损耗。稳：根治大Key与热Key顽疾，将热点key超大key请求拆分为多线程并行处理，避免单Key阻塞整个队列，实测热点Key吞吐提升3倍以上。易：提供易用的监控与运维工具，支持可视化控制台、在线滚动升级、快速扩容。省：通过一主一从从极简架构，大幅降低硬件采购与资源冗余成本；通过温热数据分层，用高性能NVMe承载温数据，减少昂贵DRAM占用。智：面向AI原生的架构设计及缓存智能调度，实现语义缓存及KV缓存，减少重复推理、优化GPU资源利用率、降低Token调用成本，大大降低企业AI推理成本。上述能力目前在对数据访问频繁且连续性要求高的金融场景中表现十分突出。其中，反欺诈场景颇具代表性，它是实时风控的核心基础设施。每笔交易进入系统后，都需在毫秒级完成信息提取、指标聚合与实时判定，任何延迟波动都可能造成漏控、带来实际资金损失；同时交易量大、指标维度多、需保留长周期历史，使数据规模持续攀升。而传统纯内存缓存的成本几乎全部集中于内存：数据规模每增长一分，内存投入便同步增长一分。Sudis从快照机制入手解决这一问题。针对纯内存方案在快照期内存膨胀、约半数内存长期闲置的痛点，Sudis采用“写内存即返回、后台落盘”的方式免去快照冗余；或者在这之上叠加分层储存，使热数据驻留内存、冷数据转入SSD、按访问热度动态决定。以100台部署规模为例：纯内存方案约50台即可满足同等业务，内存+SSD方案约20台即可；后者内存压缩率达3:1，冷数据存储成本降低80%，可支撑2～3倍以上的数据规模。两套方案均与Redis协议完全兼容，业务零改造，可在不影响业务连续性的前提下实现系统总成本的大幅下降。此外，在核心交易系统、支付清算系统、证券交易、保险规则引擎、银行电销与智能客服等场景中，共同成效体现为：业务高峰更平稳、数据增长更易承接、运维压力明显下降、存储成本显著降低。据介绍，某银行原缓存系统因数据结构数量限制，单Key达1.8GB导致故障，切换后问题解决，交易峰值处理能力提升3倍；某大型银行风险识别响应从50ms降至5ms，存储成本降低35%；通过兼容Redis协议与Sudis Sync迁移工具实现平滑迁移，某银行迁移周期缩短80%、客户画像查询响应提升2倍……金融业关注的，不只是性能然而，基础软件一旦进入核心业务链路，金融机构的考量便不止于性能，而是覆盖部署的完整生命周期——能否稳定运行、故障能否恢复、责任如何界定、未来能否持续维护。据吕利介绍，内核科技的应对，是一套可验证、可追溯的交付流程：从对标Redis的API/SDK兼容测试，到超负荷实测与Sudis Sync无间断迁移，实现平滑接管、应用无需重启改配置。再到“双陪跑+回滚”机制，新老系统并轨运行供客户考察，出问题可随时回滚至任一节点状态，进一步降低上线风险。此外，在安全层面，相比开源缓存补丁频繁、风险暴露面相对较大，自主研发让内核科技具备深入分析与修复内核的能力；加之权限控制、加密、审计与持续维护，为金融机构提供更可控的安全保障与责任边界。由此可见，解决实质问题靠的是产品的硬核性能，但让客户真正放下顾虑的是一套完整的交付流程和专业服务能力。在相关领域内的专业沉淀，以及满足客户不同情况下的新需求，是打消客户顾虑、实现互相信任的前提。布局与判断2025年，北京内核科技作为主要起草单位，参与发布《信息技术应用创新分布式数据缓存中间件技术要求》团体标准，为行业提供了统一的技术框架与评估依据；同期，内核科技与海光信息联合发布《海光服务器Sudis分布式缓存性能白皮书》，基于海光CPU开展全场景、多维度性能验证，展现自主可控“CPU+缓存软件”软硬协同的实际表现。在参与行业标准制定、推动自主可控软硬协同的同时，内核科技对缓存这一基础设施的下一步形态，也有自己的判断与布局。吕利在采访的最后表示，缓存的职能仍在演进，随着人工智能与智能体技术大规模落地，缓存会从传统的数据访问加速演进成新的职能——降低Token的消耗，提高算力平台Token输出效率。内核科技已经发布Sudis Token Cache 1.0，支持语义缓存的落地，并且正在打造Sudis Token Cache 2.0，目标将单位时间Token产出提升40%～50%，为自主可控算力平台的落地提供端到端的解决方案。面向未来，缓存不仅服务于数据访问加速，还将在CPU、GPU乃至QPU的算力协作中发挥作用，在从数据时代、AI时代走向量子时代的持续布局中，坚持在分布式缓存这一垂直领域做专做强。上述判断与布局的更多细节，内核科技有关领导、专家将作为&nbsp;2026
