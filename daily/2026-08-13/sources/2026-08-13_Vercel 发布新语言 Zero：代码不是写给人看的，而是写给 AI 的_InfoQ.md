# Vercel 发布新语言 Zero：代码不是写给人看的，而是写给 AI 的

来源：InfoQ
原文链接：https://mp.weixin.qq.com/s/8Js-DxkB06xeoiwPn0UMSA

作者 ｜ Daniel Curtis
译者 ｜ 田橙
Vercel Labs 发布了实验性系统编程语言 Zero，其设计基于这样一个前提：编译器输出的主要阅读者不再是人类，而是 AI 智能体。Vercel 的 Chris Tate 于 2026 年 5 月 15 日发布了这门语言，将其定位为一门“速度更快、体积更小，而且更便于智能体使用和修复”的系统语言。此后，该项目快速推进，已发布 v0.3.4，并在 GitHub 上获得了超过 5200 个 Star。
Zero 使用 .0 文件扩展名，采用 Apache 2.0 许可证，并可编译为适用于 Linux、macOS 和 Windows 的原生二进制文件。早期报道主要关注其体积和速度，据称一个 Hello World 程序可在一毫秒内构建完成，大小仅为 16.2 KiB。更具特色的部分是它的工具链契约。单一 zero 二进制文件的每个子命令都支持统一的 --json 标志，并使用相同的诊断模式，因此错误会携带 NAM003 等稳定代码，以及 declare-missing-symbol 等带类型的修复元数据；同时，zero fix --plan --json 会返回一份机器可读的修复计划，智能体可以接受、编辑或拒绝，而不是盲目应用修复。
副作用同样是显式的。任何与外部世界交互的函数都必须接受一个 World 能力参数，并由编译器强制执行，因此只看函数签名就能判断代码是否可以访问网络、文件系统或标准输出。
更大的转变出现在 v0.3.0 中，该版本将图优先创作设为常规工作流。现在，二进制 zero.graph 存储是编译器的输入，.0 文件则是供人类阅读的投影，而智能体通过 zero query 和 zero patch 工作。补丁受图哈希保护，因此过期或无效的编辑会在写入存储之前失败。
对于已经使用较早版本的用户来说，这些变化确实影响不小。v0.1.4 采用了行语法，v0.2.0 将规范化的 .0 文本提升为原生源码载体，而 v0.3.0 则在编译器边界彻底拒绝源码投影输入。因此，现有的文本优先软件包需要使用 zero import 将源代码导入图中，并通过 zero export 和 zero verify-projection 完成人工审查及 CI 漂移检查。这一流程记录在入门指南和语言参考中。v0.3.2 将大型程序的 zero import 速度提升了约 12 倍，从而降低了这种转换的成本。

另一位评论者认为结构化错误早已不是什么新鲜事，并称“这样的错误消息已经存在几十年了”，而一则回复则反驳称，重点在于智能体，而不是开发者：
作为一名开发者，我知道这类错误消息已经存在几十年了，而且我同意你的看法：对于你我以及许多其他开发者来说，这并不是什么大问题。但这并不能成为不去开发一种 AI 智能体也能使用的东西的理由，而且这里关注的不是开发者，而是智能体。
其他人则对采用情况提出质疑。一位用户指出，“智能体最擅长的语言，将会是那些在预训练数据中出现最多的语言”；kandros 则回应称，Svelte 等项目中的重大 API 变更表明，训练数据的重要性可能低于预期。
与成熟语言相比，Zero 在二进制文件体积和显式分配方面更接近 Zig，而不是 Rust；它缺乏 Rust 借用检查器的成熟度和生态系统，并以 Go 的绿色线程和较大运行时为代价，换取体积小巧且不依赖外部组件的构建产物。
Zero 是由 Vercel Labs 开发的开源项目。该项目警告称，它仍处于实验阶段，预计会出现破坏性变更，并且应在隔离的工作区中运行，而不是用于生产系统或处理敏感数据。
