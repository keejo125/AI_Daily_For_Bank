# DevOps之父：发几个Claude Code账号就叫AI转型？Agent用不好是公司的锅

来源：InfoQ
原文链接：https://mp.weixin.qq.com/s/D82xAnUzwGfGYPEZHBFH_g

DevOps之父 Patrick Debois 认为：开发者需要完成一个重要的思维转变——当 Agent 没有按你的预期完成任务时，不要再去修改它生成的代码，而要去改进整个系统，而不是只改 Prompt。

核心观点：

1. 不要再修 Agent 产出的代码了，去修那个产出代码的系统。
2. 如果你团队里还有人用那种"YOLO（先跑通再说）"的野路子搞 vibe coding，你应该立刻制止。工程实践不仅对你维护系统至关重要，对 Agent 自身持续变好也至关重要。
3. 暗工厂可能不是全暗，而是保留了一点微光（dim factory），这意味着你得决定对什么功能承担多少风险，不是所有功能都适合完全自治。
4. 能极致用 AI、有扎实工程功底、愿意分享和协作，将这三点组合，才是你要找的人。
5. 你的护城河，是抓住沉淀下来的知识——那些你现在注入到 skill 里、Context 里、甚至 Harness 约束里的业务上下文。

两个真正能衡量生产力的指标：
- 人工干预次数：要让 Agent 做对一件事，你还需要多少次人工干预？这个数字应该是持续往下降的。
- 乘数效应：一次对 Agent 系统的优化能在所有人身上产生乘数效应，不是一个人变成十倍效率。

平台团队的新职责：技能注册中心、Context 评估系统、Agent 护栏与身份管理、花销可视化。

组织转型铁律："发许可证、搞培训、百花齐放"从未成功。必须明确授权，让团队 Lead 和平台团队去推动。

赢家不会是那个单打独斗的超级玩家，而是那些在多个层面上懂得如何改进组织的人。
