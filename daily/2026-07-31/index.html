JetBrains Open-Sources KotlinLLM: Smart Macros That Generate Kotlin Source Code at Runtime and Hot-Reload It Through JDI
MarkTechPost
JetBrains Research开源了KotlinLLM，这是一个为Kotlin/JVM项目设计的IntelliJ IDEA插件，引入了"Smart Macros"语言特性，允许在运行时通过LLM生成Kotlin源代码并通过JDI（Java调试接口）进行热重载。 其公共API设计精简：asLlm(from, hint)将输入转换为类型化值，mockLlm()生成接口的有状态实现。运行时循环中，插件扫描asLlm和mockLlm调用，在JDI下启动运行配置并注册断点。当生成逻辑不匹配运行时场景时，插件捕获运行时值和类型信息，LLM代理提交代码更新，编译后通过类重定义重试原始调用。 在适配的Spring Petclinic项目评估中，18个asLlm调用点的24个应用场景全部完成，热重载成功率100%，编译/重定义仅增加约1%运行时开销。该工具需要IntelliJ IDEA 2025.2.x、JDK 21和OpenAI API密钥，以Apache 2.0许可发布。 KotlinLLM定位为研究原型而非生产运行时，但其输出是可部署的——行为生成后，目标项目可独立编译运行而无需再次LLM请求。最适合拥有大量JVM/Kotlin代码库的金融科技和银行行业。

Nous Research Ships Three Integration Paths for Hermes Agent and Buzz, Block’s Open Source Nostr Workspace for Humans and Agents
MarkTechPost
Nous Research发布了Hermes Agent与Buzz的三种集成路径。Buzz是Block公司（Square母公司）推出的开源、可自托管工作空间，构建于Nostr协议之上，让人类和AI代理共享同一频道。在Nostr架构中，每条消息都是中继上的签名事件，每个参与者都是密钥对，消除了传统bot-token模型，代理拥有独立身份、频道成员资格和审计轨迹。 三种集成方式分别是：一、Buzz Desktop托管运行时，在本地启动Hermes作为预设harness，通过ACP over stdio通信；二、中继桥接，通过buzz-acp harness经WebSocket连接频道到Hermes ACP；三、原生网关平台，通过内置插件使Buzz成为Hermes的标准消息平台，支持频道、私信、mention gating、线程回复、反应、图片和定时投递。 在网关路径上，入站通过NIP-42认证的Nostr WebSocket，使用BIP-340签名，自动降级到CLI轮询（默认4秒间隔）。默认配置注重隐私：require_mention开启、allow-list强制执行、工具日志抑制。Buzz为Apache-2.0许可（18.8k stars），Hermes Agent为MIT许可，均可自托管部署。

图灵奖得主朱迪亚·珀尔：大模型会讲因果，因为人类替它解释过世界，但无法通向AGI
Solidot
图灵奖得主朱迪亚·珀尔在2026年7月27日发布的长篇播客访谈中，系统阐述了他对大语言模型与通用人工智能关系的判断。访谈涵盖其科学启蒙、贝叶斯网络、因果阶梯等核心学术思想。 珀尔认为，当前LLM表面上能够进行因果推理，但实际上只是在复述训练数据中人类已有的因果解释，并不真正理解干预和反事实推理。他提出的因果阶梯包含三个层级：观察（相关性）、干预（行动）和反事实（想象），当前LLM主要停留在第一层级。 珀尔强调，要实现AGI，需要让机器自主从观察中构建因果模型，而非仅在相关性层面做模式匹配。真正的因果推理要求机器能回答"如果当时采取不同行动会怎样"这类反事实问题，这需要内在的世界模型。他对仅靠扩大语言模型规模实现AGI持悲观态度，认为需要在因果表征和推理机制上取得根本性突破。

Agent 形态一天一个样，Infra 到底该为谁而建？| 请回答 WAIC 2026
InfoQ
在WAIC 2026 InfoQ直播间，清程极智联合创始人师天麾提出判断：Agent Infra长期看一定会变得重要，但现在还没有到真正爆发的阶段。当前AI Infra最确定的方向仍是围绕每一次模型调用，提高Token生产和交付效率。 师天麾认为Agent发展不及预期的原因并非模型能力不足，而是模型迭代过快——企业投入数月搭建的Agent系统可能被下一代模型的原生能力部分替代，工程折旧速度加快。但Agent仍有两个现实优势：稳定和成本可控。企业可选择较小开源模型叠加行业数据和微调，在特定任务上接近更大通用模型，同时显著降低推理成本。 当前Agent Infra更多以传统推理基础设施形式存在：缩短API延迟、提高吞吐量和成功率、降低单次调用成本。不同业务的输入输出比例差异明显，Coding场景可能达数十比一。企业不能只设Token上限，还需理解输入输出结构，才能有效控制成本。

Agent 成本失控背后：上下文、人工审核与维护成本正在被低估｜请回答 WAIC 2026
InfoQ
在WAIC 2026 InfoQ直播间，优刻得CTO王凯和焱融科技CTO张文涛深入讨论了Agent基础设施成本问题。他们指出，Agent任务背后包含目标理解、任务拆解、信息检索、工具调用、上下文读取、记忆存储和结果验证等多环节，任何偏差都可能导致重新规划和执行，模型单价虽不断下降，但企业调用总量和维护成本持续上涨。 从基础设施角度看，Agent系统带来四重压力：并发量提高、上下文变长、调用链变长、成本结构复杂化。其中缓存命中率是最容易被低估的成本指标——缓存命中部分输入成本仅为重新计算的约十分之一，但命中率从90%降至80%时，未命中比例从10%增至20%，实际成本增加远超数字表面。 低价Token不一定意味着更低最终成本，频繁超时和重试会带来额外开销。成熟的多模型路由系统不能只选"此刻最便宜"的服务，需同时考虑实时负载、请求成功率、模型质量和缓存亲和性，在一段时间内保持会话黏性。
