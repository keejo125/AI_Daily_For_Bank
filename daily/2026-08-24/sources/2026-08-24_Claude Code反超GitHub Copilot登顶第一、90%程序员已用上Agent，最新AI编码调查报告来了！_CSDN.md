# Claude Code反超GitHub Copilot登顶第一、90%程序员已用上Agent，最新AI编码调查报告来了！

来源：CSDN
原文链接：https://mp.weixin.qq.com/s/TroIreA6CMBgFHGJlHARFQ

AI 编程正在进入一个新的阶段。
过去几年，开发者选择 AI 工具时，关注的往往是代码补全、问答能力以及 AI IDE 的体验。但随着 Claude Code、Codex 等 AI 编程 Agent 快速普及，开发者与 AI 的协作方式正在发生变化：AI 不再只是帮忙写几行代码，而是开始直接接手完整的开发任务。
编译 | 苏宓
出品 | CSDN（ID：CSDNnews）
近日，
软件开发工具厂商 JetBrains 旗下研究团队 JetBrains Research
发布《2026 年开发者生态系统调查报告》，这也是该调查连续开展的第十年。本次调查覆盖全球超过 1.5 万名专业开发者，调查对象除了程序员和软件工程师外，还包括 AI/ML 工程师、DevOps 工程师、架构师、数据工程师和 QA 工程师等，其中约 90% 为开发者、程序员和软件工程师。
调查显示，
AI 代码智能体正在开发者的工具链中站稳脚跟，在全行业的使用率持续走高。
今年 5 月至 7 月，全球约 90% 的专业开发者已经在工作中至少每周使用一次 AI 编程 Agent，其中 68% 的开发者每天都会使用。
与此同时，AI 编程工具的竞争格局也在快速洗牌。Claude Code 半年时间使用率翻倍，超过长期占据领先位置的 GitHub Copilot。OpenAI Codex 同样实现快速增长，而曾经风头正劲的 Cursor，工作场景使用率却出现下滑。
这意味着，AI 编程市场的竞争重点，正在从“谁的 AI IDE 更好用”，转向“谁的 Agent 能真正接手开发工作”。
Claude Code 半年翻倍，直接登顶
这轮变化中最抢眼的无疑是 Claude Code。
JetBrains Research 的数据显示，
Claude Code 的增长速度前所未有，已然成为职场中使用最广泛的 AI 编码工具。
2026 年 1 月，全球只有约 18% 的专业开发者表示会在工作中使用 Claude Code；到了 5—7 月，这一比例已经飙升至 39%，短短半年多时间实现翻倍。
在美国市场，这一比例甚至达到 47%，也就是说，接近一半的美国开发者已经在工作中使用 Claude Code。
此外，它成为开发者主力 AI 编码工具的占比也大幅提升。
调查显示，31% 的开发者将 Claude Code 作为自己最常用的 AI 编码工具。也就是说，在已经使用 Claude Code 的开发者中，有相当一部分已经把它从尝鲜工具变成了日常工作的核心工具。
这也直接改变了 AI 编程工具此前的竞争格局。
GitHub Copilot 曾长期占据这一市场的领先位置。2025 年中期至 2026 年初，其工作场景使用率一度维持在约 29% 至 31%，但到了今年 5 月至 7 月，这一数字已经下降至 21%。
相比之下，
Claude Code 已经达到 39%，几乎是 GitHub Copilot 的两倍。
从开发者的认知度来看，两者目前仍然处于同一梯队。GitHub Copilot 和 Claude C
ode 的认知度均为 79%。
区别在于，Claude Code 的实际使用率正在快速追上并超过 Copilot。
除此之外，如果说 Claude Code 是这轮变化中最大的赢家，那么 OpenAI Codex 则是另一个值得关注的玩家。
今年 1 月，全球只有 3% 的专业开发者在工作中使用 Codex。到了 5—7 月，这一比例已经增长到 16%，大约增长了 5 倍。
Codex 的认知度增长甚至更加明显。今年 1 月，只有 27% 的开发者听说过 Codex，到了 5—7 月，这个数字已经达到 65%。
也就是说，OpenAI 的品牌优势开始真正转化成产品认知，而 Codex 本身的使用率也正在快速上升。
如果按照当前趋势来看，AI 编程工具的头部竞争已经不再只是 GitHub Copilot 与 Cursor 的较量，Claude Code 正在成为新的头部玩家，而 Codex 也在快速追赶。
相比之下，Cursor 的表现则有些出人意料。今年 1 月，Cursor 的工作场景使用率为 18%，到了 5 月至 7 月反而下降至 12%。但与此同时，它的开发者认知度并没有下降，反而从 69% 上升至 75%。
换句话说，Cursor 并不是没人知道，而是“知道的人更多了，实际使用的人却少了”。
中国市场的变化尤其明显。今年 1 月，约 28% 的开发者表示会在工作中使用 Cursor；到了 5 月至 7 月，这一比例已经下降至 16%。
这背后的变化，或许正好反映了 AI 编程工具正在发生的一次产品形态转变。过去几年，AI 编程的竞争很大程度上围绕 AI IDE 展开，Cursor 就是其中最典型的代表。开发者打开编辑器，通过代码补全、对话和修改功能与 AI 协作。但现在，Claude Code、Codex 等 Agent 正逐渐走出 IDE。
开发者需要的可能已经不只是一个“加入 AI 的编辑器”，而是一个能够理解代码库、修改代码、运行测试，甚至持续执行任务，直到最终把事情做完的 Agent。
90% 的开发者已经用上 Agent
如果把具体产品的排名放到一边，这份调查真正重要的信号，其实来自另一组数据：
90% 的专业开发者每周至少使用一次 AI 编程 Agent，68% 的开发者每天使用。
这意味着，AI 编程 Agent 已经很难再被视为开发者偶尔尝试的新工具。对绝大多数开发者而言，它正在成为日常开发环境的一部分。
而 JetBrains 对 Agent 的定义也比较宽泛，既包括运行在本地的 Agent，也包括运行在云端的远程 Agent。
从这个角度来看，开发者工作流正在发生一个非常明显的变化：AI 的角色正在从“辅助写代码”变成“执行开发任务”。
开源 Agent 也开始进入竞争
这场竞争也并非只有几家大型科技公司参与。JetBrains 的调查显示，开源编码
Agent OpenCode 在今年 5 月至 7 月的工作场景使用率已经达到 7%
，同时拥有 42% 的开发者认知度。
Google Antigravity 的使用率则达到 6%
，认知度从今年 1 月的 29% 快速增长至 47%。其中，印度市场的使用率尤其突出，已经达到 15%，基本与 Cursor 持平。
此外，JetBrains 自己的 AI 工具也获得了约 9% 的工作场景使用率，包括 JetBrains AI 和 Junie。
从这些数据来看，
AI 编程市场暂时还没有形成一家独大的局面。
相反，开发者正在接触越来越多的 Agent，并根据不同任务选择不同工具。
AI 编程的竞争，正在变成 Agent 的竞争
从 JetBrains 这份调查来看，Claude Code 的快速增长、Codex 的持续追赶，以及 Cursor 使用率的变化，都说明开发者的选择正在重新洗牌。
更重要的是，90% 的周使用率和 68% 的日使用率表明，Agent 已经进入大量开发者的日常工作流。
因此，这份调查真正值得关注的，或许并不是 Claude Code 能否长期保持第一，也不是 GitHub Copilot 有没有机会重新夺回榜首。
更大的变化在于，AI 编程 Agent 已经从“开发者可以尝试的新工具”，变成了越来越多开发者日常工作的一部分。
而随着开发者把越来越多的开发任务交给 Agent，接下来的竞争也将不再只是代码生成能力的较量。
谁能让 Agent 真正把事情做完，谁才更有可能赢得下一阶段的 AI 编程市场。
