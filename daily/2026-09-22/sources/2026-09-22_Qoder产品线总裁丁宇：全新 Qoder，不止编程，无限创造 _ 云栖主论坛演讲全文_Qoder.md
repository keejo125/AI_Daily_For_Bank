# Qoder产品线总裁丁宇：全新 Qoder，不止编程，无限创造 | 云栖主论坛演讲全文

来源：Qoder
原文链接：https://mp.weixin.qq.com/s/Yb-0K9vNPBFlVl2fatYFqA

9月22日，在云栖大会现场，Qoder 产品线总裁丁宇发布主题演讲《全新 Qoder，不止编程，无限创造》。
全新 Qoder 带来更简约的交互、更新颖的人机协作与更强大的 Harness，并覆盖从计划、设计、实现、测试到维护、发布的软件全生命周期。Agent Team、Qoder Project、Discussion、Qoder Security、语音与眼镜交互、Cloud Agents 及数字员工 QoderWake 一一登场，让智能体能看、能听、能说、能做。不止编程，无限创造——让每个人都能用编程解决问题，打造超级个体，成就超级组织。
以下是演讲全文：
尊敬的各位嘉宾、各位专家、各位开发者，大家下午好。很荣幸今天能在这里，和大家分享
Qoder
的全新升级。
Qoder
去年
8
月上线，一年来已服务全球超过
800
万开发者。从用户的真实行为里，我们看到了三个清晰的趋势。
第一，用户在向
"
泛开发者
"
渗透。
今天
Qoder
的用户中，已有超过
30%
不再是专业开发者。
第二，工作对象在从编程向多任务泛化。
Qoder
中的非编程任务占比已超过
50%
。
第三，编程正在从
"
手写
"
走向
"
委派
"
。
Qoder
中超过
80%
的编程任务，已经不再由开发者逐行手写，而是交给智能体完成。
这三点指向同一个判断：
AI Coding
正在走向普惠，而用户的注意力，正在持续向上迁移。基于这样的趋势，
Qoder
的产品形态升级，已经成为一种必然。
今天，我们为
Qoder
带来一个全新的定位——
An Agentic Coding Platform for Everyone
。
因为我们相信，是时候重新定义
AI Coding
了。代码，正在从一个
"
交付物
"
，变成数字世界的一种
"
通用能力
"
。越来越多的任务可以通过编程来解决，而使用它的人，无需感知编程、学习编程，甚至察觉不到编程的存在。所以，
Qoder
要服务的，是所有能够用编程解决问题的人。
全新的
Qoder
，有三个特点。
第一，更简约的交互形态。
面向专业开发者时，
Git
、
worktree
、
Browser Use
、审查工具等专业能力依然触手可及；而当用户处理通用任务时，这些工具会自动隐去，还他一个更简约的界面和极致专注的心流体验。
第二，更新颖的协作方式。
我们支持跨任务、跨工程的并行执行；并以任务为中心，让人与智能体在群组中讨论、协同，共同推进任务进度。
第三，更强大的
Harness
。
Qoder
支持多模型适配；同时，我们发挥阿里巴巴的整体优势，与通义千问模型联合设计、联合优化，把模型能力发挥到极致。
围绕这三个特点，我们做了多方面的升级，下面逐一介绍。
能力边界持续延伸
从
"
代码为中心
"
到
"
任务为中心
"
。
过去的
AI IDE
以代码为优先，人的注意力落在代码上，功能设计也都围绕代码去审查、检查、验证。全新的
Qoder
以任务为中心、任务优先，人专注于任务的计划、委派与结果确认。注意力上移之后，人可以并发地管理更多任务，并发度和吞吐量随之上升，效率自然提升。
从
"
编程
"
到
"
软件全生命周期
"
。
过去
AI IDE
覆盖的是设计、开发、测试；全新的
Qoder
可以贯穿计划、设计、实现、测试、维护到发布。任务链条越来越长，复杂度越来越高——今天我们在手机上开发一款移动
App
，从提出想法到部署上手机，不到一小时就能完成，相比过去的移动开发是一次质的飞跃。
目标驱动的多智能体协同。
我们推出了
Agent Team：
围绕一类目标定制一支智能体团队，多智能体协同推进，直至任务完成。
Agent Team
大幅提升了任务执行的确定性和人对任务的把控度。
协作方式不断进化
过去的协作，往往是一群人在会议室或
IM
里讨论，形成结论后再委托某个人整理、交给智能体执行。这种方式的挑战在于：注意力分散、上下文分散、产物碎片化。
我们推出两个新功能：
Qoder Project
和
Qoder Discussion
。
Project
让你围绕一个大目标拆解出具体事项，逐项跟进进度与阶段；每个事项都可以展开讨论，把人和智能体拉进同一个群组共同商议，形成结论后交给智能体执行，人再确认最终结果。
它的核心是：
让讨论发生在任务现场
。人与模型共享上下文，讨论历史与讨论资产都沉淀在任务上，人不必再做智能体的
"
搬运工
"
。这两个功能，大幅提升了人机协作的效率。
我们认为，一个真正好用的智能体，不应让用户去学习如何使用，而应主动理解用户、理解用户的场景。为此，我们建设了三方面能力。
第一，能力可扩展
。
我们提供了
150
多个连接器、
70
多个插件、
2
万多个精选技能。用户想做一件事，几乎都能找到现成的技能，无需从头搭建。
第二，形态可定制。
一是
自感知
——
Qoder
能读懂自己：了解自身有哪些模型、多少额度、上下文窗口多大，以及自身的功能与状态，从而在执行时充分权衡成本、时间、效果与体验，选择最优模式，
Auto
模式正体现了这样的智能。二是
自学习
——把历史任务沉淀为技能，在需要时自动发现、自动使用。三是
自适应
——定制专属工作台，模型、技能与界面都能随需而变。
第三，意识可进化。
当智能体拥有完整的长短期记忆，再加上判断力，就有了
"
意识
"
：它能自主建议、主动行动，帮助人类更好地完成任务。
有了这些能力，
Qoder
不再是一成不变的工具，而是一个随你成长、专属于你的伙伴。
Qoder Security
：代码安全的新范式
使用
AI Coding
之后，代码量将大量爆发，代码安全成为新的挑战。为此，我们推出
Qoder Security
，我认为它代表了代码安全的一种新范式。
过去的方案基于规则、基于正则扫描——把存量的经验写成规则去扫描，发现问题再由人修复。而未来会不同：既然
AI
能生成大量代码，它同样能检查代码的安全性。只要把先验的安全知识构建到
模型，问题就能从源头解决。我们基于自研大模型来应对安全问题，构建了从推理、自发现到自修复的
主动安全闭环
，做到
"
生成即审查、审查即修复
"
。
传统的安全扫描通常发生在代码提交与发布之前，而那时研发工作大多已经完成，倒回去修复的代价很大——发现越晚，代价越高。今天
AI
在每个阶段都会生成代码、变更需求、提交代码，所以我们在每一个切面都能修复安全问题：
编码时、变更时、提交前、全场扫描
，四层切面全覆盖。
基于这套方案，问题识别准确率达到
97%
，较传统方式近乎翻倍；漏洞检出率达到
83%

180

5.8

"
默认安全
"
。面向企业管理，成员零配置、管理员一键开通即可使用——既大幅降低了使用门槛，也显著提升了企业代码安全的水位。

Computer Use

。我们相信：语音正在成为操作智能体的新入口，而智能体正在成为操作电脑的新方式——这些在
Qoder

有了
