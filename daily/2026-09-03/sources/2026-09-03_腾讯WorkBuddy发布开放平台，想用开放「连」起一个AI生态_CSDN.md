# 腾讯WorkBuddy发布开放平台，想用开放「连」起一个AI生态

来源：CSDN
原文链接：https://mp.weixin.qq.com/s/JoZYes8swLH1hSKAZ4MA0g

过去一年，AI 的竞争焦点正在从模型的聪明程度，转向能力的连接广度。
一边是
大模型能力的加速迭代，
Agent 产品层出不穷，AI 硬件从眼镜、耳机到录音笔接连冒出来。另一边是企业的数据和工具散落在几十个 SaaS 里，用户桌面上的 AI 软件和硬件彼此不通，记忆不连贯、任务无法串联，每接入一个新工具，就
相当于
多一座新的孤岛。
行业也在试图回应这个问题。今年 3 月，华为发布 HarmonyOS 7，将迈向 Agent 时代作为核心战略；此后，苹果将 Siri 升级为系统级智能入口，谷歌推进 Gemini Intelligence 深度嵌入 Android，6月荣耀在 MWC 上海首次提出 Agentic OS 概念。各家路径不同，指向却高度一致：当 AI 从聊天工具变成真正能完成任务的智能体，单一产品已经不够，需要一层能把这些能力连起来、开放出去的基础设施。
9 月 2 日，
腾讯正式发布 WorkBuddy 开放平台，首批超 100 家生态伙伴接入，9 款联名智能硬件首发，30 余个行业应用覆盖 20 多个领域
。无论是应用开发者、硬件厂商，还是各类行业应用中的企业，都可以将自己的独特能力接入 WorkBuddy 平台，也可以把 Wo
r
kBuddy 的 AI 能力融入自己的产品与服务中。
腾讯将这一动作定义为开放平台，其核心逻辑并非再造一个超级 App，而是
打通软硬件、应用与用户之间的孤岛
，
把跑通的能力变成公共设施
，
让开发者、厂商和行业在同一个底座上生长。
腾讯云副总裁、腾讯 CodeBuddy & WorkBuddy 负责人刘毅表示：“
我们希望把 WorkBuddy 打造成面向 Agent 时代的开放平台——不是做一个更强的工具，而是做一个能承载所有工具的平台。
”
另外，
过去几个月，北森、微盟、科大讯飞、Plaud 等一众软硬件企业开始把自身 AI 产品的部分能力搬到 WorkBuddy 上——北森在几天之内就完成了对接，感受到的是
“
开放力度蛮好、速度很快
”
；微盟
更是直接表示
：
“
WorkBuddy 这个入口是一定要去占的，因为它有可能是未来 2B 的超级入口
”
；科大讯飞则看到了另一种连接的价值：
“
一个账号、一个数据资产，换设备不用换 Buddy。
”
这一变化背后，是 AI 生产力的诉求在企业工作流中变得越来越具体和迫切。并且，WorkBuddy 正
在成为一个 AI 的新窗口。据腾讯 2026 年 Q1 财报披露，以日活跃账户数计，WorkBuddy 已成为中国最受欢迎的效率 AI 智能体服务；易观数据显示，其在 PC 端 AI 原生办公智能体市场 6 月单月访问量突破2000 万，保持市场第一。
但在开放之外，
对于腾讯而言，还需要回答的问题是，
WorkBuddy 为什么在这个时间点
选择开放
？WorkBuddy
又是如何用开放来定义连接的？
生态开放能给这个当下 AI 办公产业链带来什么变化？
为什么需要一个“上下文的操作系统”
要回答这个问题，首先要厘清一个
容
易被混淆的概念：模型不等于 Agent，而 Agent 好不好用和模型是否“聪明”关系不大，关键在于它能否获得足够丰富、连贯且实时的上下文。
因为模型是一个根据输入产生输出的函数，它本身是无状态的。对话历史、记忆、工作进度都需要产品在模型外部维护状态，需要时再注入。模型也不感知时间、不感知你当前打开了什么文件、不感知你安装了哪些工具。
换句话说，模型只提供语言理解、推理和生成能力。但一个能真正完成工作的 Agent，需要的是持续理解上下文、拆解并形成关键记忆、跨设备任务迁移、决策、具体工具的调度与执行。这些能力无法仅靠模型本身实现，必须依赖一个能够统筹感知、记忆与执行的底层系统来支撑。
而这正是 Agent OS 要解决的核心问题。
Agent OS 的本质，不是一个更大的 AI 工具，而是一套“上下文的操作系统”。 它把记忆、任务状态、工具连接、数据沉淀这些 Agent 运行所必需的公共能力，做成标准化、可调用的底座，让所有接进来的硬件、应用、开发者都能共享同一套上下文。
打个比方。常有人说“
没有操作系统的
PC
时代”
，这其实不准确
——
有
PC
就有
OS
，
Windows
之前是
DOS
。
DOS
时代真正缺的不是操作系统，而是统一的图形界面、剪贴板、设备驱动模型和文件关联：每个应用自带打印机驱动，自己管理数据格式，程序之间无法共享状态，用户要在软件间搬运数据只能手动导出再导入。
Windows
之后，文件、剪贴板、打印机这些东西才变成公共资源，软件之间才可以互相调用。
今天的
Agent
恰好处在同一个位置：
Agent
已经有了，但共享上下文的那一层还没有。
Agent OS
要做的，就是把“
上下文”
变成
AI
时代的公共资源。
从这个层面看，腾讯
WorkBuddy
此次的产品升级，是一次早已写在路线图上的战略升级。
一方面，当前，AI 办公场景高度碎片化。今天的 Agent 虽然已经拥有了强大的执行能力，但企业的数据和工具依然散落在不同的应用中。同时，软硬件之间、不同 Agent 之间，如果记忆不连贯、任务无法串联、上下文无法传递，用户体验会非常割裂。Agent OS 的核心价值之一，就是提供跨 Agent、跨设备、跨应用的统一记忆、任务和身份层，让用户感受到“一个智能体在为我持续工作”。
因此，腾讯的判断是，
Agent 的下一步，必须要让 Agent “在场”，让能力彼此互联，并最终连成生态。
另一方面，自建 Agent 是一条高成本、低效率的重复建设路径。当 Agent 数量激增，软硬打通与多智能体协作的需求爆发，底层能力必然从“各自为战”转向“平台统一供给”。没有这个统一基础设施，软硬调度、行业 Agent 落地都会面临极高的门槛和碎片化问题。
从更深层的商业逻辑来看，
开放带来的不只是接入量，而是上下文密度
。开放得越广，平台拿到的场景和上下文越厚；上下文越厚，模型和 Agent Harness 迭代越快；迭代越快，产品体验越好；体验越好，更多伙伴和开发者愿意接入；
接入越多，上下文更厚，迁移成本也更高。这是复利结构，也是 Agent 时代健康的商业模式。
并且，这个模式已经在腾讯内部得到了验证——Hy3 与 WorkBuddy 的互相拉动，已初步验证了这一飞轮效应。但需要说清楚的是，内部飞轮验证的是机制存在，不是机制可外推：同一家公司两个产品之间的协同，交易成本、对齐成本与跨厂商生态完全不是一个量级。把飞轮的半径从
"
内部产品
"
扩展到
"
整个生态
"
，恰恰是这次发布真正要回答的问题。
这个价值在于这会形成类似 CUDA 的生态锁定——开发者在 WorkBuddy 上开发技能，硬件厂商围绕它适配终端，企业在其中沉淀流程，用户在其中积累上下文，伙伴在其中获得收入。迁移出去，不只是换一个模型，而是要迁移记忆、任务、技能、工具链、权限体系、业务流程和商业关系。
这套飞轮一旦转起来，其迁移成本和生态护城河，远比任何一个单点功能或模型能力上的领先更难被撼动。从这一点上来看，腾讯开放平台的使命是定义一套让AI 能够持续工作的规则与基础设施，让所有人都在这套规则上生长，并构建腾讯的 Agent 生态。
另外，从腾讯近期披露的财务数据来看，WorkBuddy 的商业化路径已经在产品层面得到了初步验证，而这也让“开放”从一个战略选择变成了一个必然的下一步。
据财报披露及管理层在电话会上透露的信息，2026 年 7 月，WorkBuddy 单月收入已达 1.19 亿元，付费企业超过 7300 家。7 月 MAU 达 1470 万、环比增长 71%，DAU 达 395 万、环比增长 111%——DAU 的环比增速几乎是MAU 的两倍，这说明用户粘性是非常高的，高频的深度使用，不仅验证了产品价值，更沉淀了难以复制的场景壁垒。
对腾讯而言，产品层面的商业化验证已经完成，
下一步需要回答的是：如何把这套能力变成公共基础设施，让更多人参与进来把蛋糕做大。
两条路：从系统往下做，还是从产品往上长
对比华为、苹果、谷歌、荣耀，他们的做法是：从系统往下做
——
先宣布一个
Agent
化的操作系统，再把
Agent
能力逐层填进去。这条路的优势是天然拥有系统级权限、硬件底层和终端分发；风险则是
OS
有了，
Agent
还没有：架构先行，但缺少足够密度的真实任务把它填满。
腾讯
WorkBuddy
走的是另一条：从产品往上长
——
先把一款产品做到日活第一，跑通真实场景，再把已经被验证过的能力一层层开放出去。
WorkBuddy 开放生态负责人林佐露
回答了此次开放的本质：“生态其实是不太能计划的，有没有生态是一个结果。回到源头来看，还是这个产品够不够好，设计合不合理，然后才会有一个好的生态结果。
开放是我们要去做的工作，生态是一个结果。”
这条路的代价很明显：看起来慢半拍。但它的收益同样明显：每一层开放出去的能力，都是已经在千万日活里被打磨过的能力，而不是一份规范文档。
Agent OS
与传统
OS
有一个根本差别
——
传统
OS
封装的是确定的硬件行为，写清楚就能用；
Agent OS
封装的是不确定的智能行为，它的可靠性只能靠真实任务反复冲刷出来。在这种情况下，先有场景密度再有标准，比先有标准再找场景，成功率要高得多。
有意思的是，腾讯自己对这件事的进度判断相当克制。在腾讯看来，WorkBuddy 离真正的 Agent OS，形态上已经比较接近。
所以更准确的说法或许是：
WorkBuddy
不是已经成为了
Agent OS
，而是选择了一条从产品长成
OS
的路。
腾讯云的开放平台长什么样？
9 月 2 日的发布会上，腾讯围绕 WorkBuddy 集中发布了三个模块：硬件生态矩阵、Buddy 应用体系、以及正式上线的开放平台。
●
能力开放：把 Harness 做成公共品
任何一个做 Agent 的团队，都得面对一套固定的工程清单：系统提示词怎么设计？工具调用怎么实现？文件系统怎么接入？沙箱怎么隔离？多 Agent 之间怎么协作？执行结果怎么反馈迭代？模型本身不提供这些，每一个团队都得从零开始搭。
WorkBuddy 的解法是：把过去积累的 Harness 工程能力封装成标准 API，对外开放。
硬件厂商调用 API，设备就有了理解、规划、执行、记忆的能力；开发者调用 API，就不用自己再造一遍多 Agent 协作和权限控制的轮子；行业应用调用 API，就能把 WorkBuddy 的 Agent 能力嵌入自己的产品里。
这背后的逻辑是：
Agent 基础设施会走向公共化。
就像当年移动互联网时代，操作系统把 GPS、摄像头、陀螺仪这些硬件能力封装成 SDK，开发者不需要自己写驱动；Agent 时代，Harness 这套“模型外骨骼”也会成为公共品。
●
生态开放：专业能力全开放
光有能力开放还不够。Agent OS 真正运转起来，需要有大量来自真实场景的能力注入。
于是，WorkBuddy 把专业能力按不同形态拆成了四类，覆盖了从完全不会写代码到有完整工程团队的几乎所有参与者：
技能（Skill）
——纯文本提示词，零代码。一个资深HR可以把面试方法论写成技能，Agent 就能用这套方法去面试候选人。
连接器（Connector）
——基于 MCP 协议接入，需要工程能力。适合想把自有系统接入 WorkBuddy 的 SaaS 或工具厂商。
专家（Expert）
——单体专家或多 Agent 团队，需要重经验设计。适合有完整工作方法的专业机构，把一整套业务流程沉淀为 Agent 能力。
灵感（Discover）
——可复用实践案例，几乎没有门槛。任何有“好用法”的人都可以分享。
这种分层设计，在合作伙伴身上已经得到验证。北森副总裁王瑶的体会是，助手类的  Agent 接入几天就能跑通，但"北森除了助手类的 Agent，还有专家类的Agent，可能有更深的对接才能实现这个业务场景，因为涉及大量的数据、大量的调用，还有多个 Skill 之间的复用——这也是门槛，也是机会。
●
场景开放：让 AI 能力长进真实的业务里
场景开放解决的是这些能力最终落到哪里。
WorkBuddy 的策略是从单一办公场景扩展到多行业、软硬多终端，让"每个行业都有自己的 Buddy"。
硬件端，围绕"听、看、记、聊、协"五类触点，
WorkBuddy 已经接入多个硬件品牌，覆盖智能眼镜、录音卡片、麦克风、耳机、桌面陪伴设备、键鼠、PC 与平板等十余个品类。
以智能眼镜为例。接入后，用户戴上眼镜进会议室，发言转写、会议纪要、待办跟进由 Agent 一条链路完成；外出访谈时，看到和听到的内容自动归档为可检索的记忆。账号、任务、记忆、产物在眼镜、手机 App、PC、Web 之间无缝同步。硬件厂商得到的是产品力的跃升，用户得到的是“触手可及的 Agent 能力”。
软件端，
WorkBuddy 以“模板”方式让行业应用订阅整套资产与工作模式，把通用工作台直接转化为自有品牌的 AI 工作台。
合作伙伴不用自研 AI，只需要接入行业场景和业务上下文。首批覆盖金融、SaaS、法律、医疗、教育、公益、设计领域，与通达信、广发证券、腾讯 SSV、腾讯健康、北大法宝、微盟、北森、帆软、美图工作室都建立了合作关系。
一个值得关注的细节是公益 Buddy——它深度打通了腾讯公益平台数据，按公益机构的真实工作方式收拢为 11 个场景胶囊、42 条场景能力，由 15 个智能体协同支撑。这种深度定制的模式，恰恰体现了“每个行业都有自己的 Buddy ”的产品逻辑。
而这些场景，最终都沉淀在一个载体上——开放平台。
面向开发者，平台开放 Skill、Expert、Connector 三大核心能力。开发者依托标准化协议即可快速接入平台输出专业能力，Expert 市场支持 Agent 型、Team 型两种模式；Connector 兼容 MCP、CLI 两套方案，可对接各类外部服务。平台透露，支付与分发通道正在加紧建设，未来将让开发者的专业经验实现商业价值，丰富面向普通用户的能力供给。
腾讯AI 的长期主义
WorkBuddy 升级为开放平台，表面上是产品形态的变化，背后是腾讯 AI 战略的一次实质性跃迁。
这个跃迁的起点，是腾讯对 AI 行业变化的判断：A
gent 正在从“回答问题”走向“执行任务”。而执行任务的前提，是 Agent 能够获得足够丰富、连贯且实时的上下文。
企业的数据和工具散落在不同的应用中，软硬件之间的记忆不连贯，任务无法跨端串联。开发者想做一个能真正干活的 Agent，得从零造记忆系统、工具调度、多 Agent 协作、权限控制和安全边界。这些碎片化的问题，正是WorkBuddy 试图通过开放平台解决的。把记忆、任务状态、工具连接做成标准化的公共底座，让所有接进来的硬件、应用、开发者共享同一套上下文。
但这条路并不平坦，竞争异常激烈。每家都有自己的定义和打法，不同路径之间，谁更能吸引开发者、谁更能沉淀场景、谁更能跑通商业闭环，还远没有定论。
但正是在这个时间节点上，腾讯内部发生了一个值得注意的变化。
过去一年，腾讯同时布局了元宝、WorkBuddy 等多个 AI 产品，试图从不同场景寻找 AI 应用的突破口。但过去几个月，WorkBuddy 正在成为资源倾斜最明显的那个。从小红书、抖音等社交平台，到写字楼电梯广告，再到海外社交平台X，腾讯正在持续提高 WorkBuddy 的曝光度。
与之对应的，是 AI 投入强度的陡增。2026 年第二季度，腾讯资本开支 527.8亿元，同比增长 176%，半年累计 847 亿元已超过 2025 年全年。AI 产品对当期利润的影响约 105 亿元。
从业务逻辑来看，腾讯的 AI 版图已经覆盖了模型层、Harness 层、产品层、生态层的完整链条——而且每一层都在产生实质性的商业反馈。混元 Hy3 在WorkBuddy 自选模型用户中获得 60% 的选择率，WorkBuddy 单月收入突破1.19 亿元，AI 相关云服务收入以 20% 以上的增速拉动增长。
