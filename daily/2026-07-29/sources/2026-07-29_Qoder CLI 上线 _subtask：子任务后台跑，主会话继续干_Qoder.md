# Qoder CLI 上线 /subtask：子任务后台跑，主会话继续干

> 原文链接：https://mp.weixin.qq.com/s/aZ1s4me6eB0xbhkCw1UPCQ
> 公众号：Qoder

用 AI 写代码，大部分时间其实花在等上。等它分析完依赖关系，等它跑完测试，虽然你可以开多个终端窗口，但上下文得自己复制粘贴，结果得自己手动汇总。

Qoder CLI 新加了 /subtask 命令，可以在同一个会话里把任务丢到后台跑，主会话继续干别的事，完成了自动返回结果。

怎么用

/subtask 跑一遍全量测试，把失败的用例按原因归类

一条命令，子代理带着当前会话的完整上下文到后台工作。你可以立刻接着问问题、改代码、甚至再派一个新任务，完成了自动返回结果。

什么时候用

穿插查询

——改 bug 改到一半，需要搞清楚 auth 模块的迁移历史。不用停下来等，后台去查，你继续改 bug。

/subtask 查一下 auth 模块从 v2 到 v3 的迁移历史，列出关键变更

并行对比

——想对比三种实现方案，不用串行等三次，直接开三个 /subtask 同时跑，各自带完整上下文，完成后逐个返回结果。你在主会话汇总对比。

后台耗时任务

——跑全量测试、列 lint 问题、分析最近 10 次 commit，丢给 /subtask，主会话不被卡住。

隔离实验

——想试一个不太确定的方案，又怕搞乱当前上下文。/subtask 开一个隔离的任务去试，完成时只给一个摘要，主会话干干净净。

什么时候不要用

需要跟你来回确认的任务

。子任务在后台，它问不到你。

会改同一批文件的任务

。两个进程同时写一个文件，你不会想收拾那个现场。

三秒就能答的问题

。派发本身有开销，不如直接问。
