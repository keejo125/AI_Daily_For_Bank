# ChatGPT Pro 额度翻倍：是让步，不是福利？

> 原文链接：https://www.infoq.cn/article/WpTNht7guarWEyejJFV6
> 来源：InfoQ

10月29日，OpenAI产品负责人Tibo宣布，从即日起，Pro 100、Pro 200、Pro 500以及Business Premium套餐的使用限制全面翻倍。

其中还有一项重要说明：OpenAI听取用户反馈后，决定不再削减Pro 200的使用额度，因此该套餐的ChatGPT Work和Codex使用量将维持原有水平。与此同时，Dots目前仍将继续享有扩容额度，而且其使用量与账户默认额度相互独立，不计入默认额度。

这项调整实际上回应了此前Pro订阅体系调整引发的争议。OpenAI此前推出500美元的Pro 500，并调整200美元Pro套餐的权益，原有Pro 200用户曾面临部分使用额度下调的预期。此次公告撤回了相关削减安排，意味着用户反馈确实影响了最终政策决定。

后续，有用户进一步询问，Pro 500是否意味着可以获得相当于Plus套餐50倍的使用量，Tibo直接回答“Yes”。这也体现出OpenAI正在进一步拉开不同付费层级之间的使用额度差距，为高强度AI编程和工作流用户提供更大的使用空间。

社区对此并非一边倒地叫好。部分Pro用户欢迎额度扩容，但也有200美元Pro用户指出，自己此前已经享有较高额度，此次只是撤回了原定的削减计划，并没有获得真正意义上的新增权益。

“我很高兴其他 Pro 档位以及低额度套餐的用户拿到了实打实的额度上涨，这些才是真正的优化。但把取消原定降额这件事，打包算进 28 天改进计划里，对外宣传成全面翻倍升级，这有误导之嫌。坦白说，对于一直在跟进这件事、并且依赖官方公告做规划的用户而言，这种说法实在让人难以接受。”有用户说道。

与此同时，一些Plus用户对本次调整没有覆盖低价套餐表达不满，认为OpenAI正在进一步拉大不同付费层级之间的使用体验差距。

除了提高额度，Tibo还强调，OpenAI会继续推出更好的模型和效率优化，让用户随着时间推移获得更多实际使用量。值得注意的是，这次调整属于OpenAI为期28天的产品改进计划中的第25天。Tibo随后还开玩笑称，OpenAI正在从“重置额度公司”毕业，转向“Token公司”。

OpenAI负责Codex和ChatGPT产品的Andrew Ambrosino也表示，团队已经启动一轮密集改进，重点解决应用简洁性和性能问题，并由他亲自负责。

这意味着OpenAI并不打算只依靠扩大套餐上限解决用户需求，而是希望同时提高模型能力、推理效率和单位算力的产出。对于越来越依赖Codex的开发者而言，能否获得稳定、充足的使用额度，已经成为影响订阅决策的重要因素。

除了OpenAI，过去一年，Anthropic 也频繁调整Claude Code的使用限制，甚至经历了从收紧到扩容、再到部分回收的过程。

2026年3月，Anthropic曾收紧免费、Pro和Max用户在高峰时段的5小时使用额度；5月与SpaceX达成算力合作后，又将Claude Code的5小时额度翻倍，并取消Pro和Max套餐的高峰期额度削减。与此同时，公司还曾将Claude Code周度额度临时提高50%，但在9月结束促销后，仅保留了比原始水平高25%的永久额度。

对额度调整的不满，也引发了用户对订阅权益的诉讼。

Anthropic的Max 5x和Max 20x套餐分别宣传提供Pro套餐5倍和20倍的使用量，但这一倍率实际上指每个5小时会话窗口内的使用量，而非每周累计使用量，用户同时还受到周度总量限制。今年9月，一批用户因此对Anthropic提起集体诉讼，认为相关限制没有在购买过程中得到充分、醒目的说明，导致实际使用体验与购买预期存在差距。

后台Agent在不起眼的地方吃了不少Token

AI编程工具的额度问题并非简单的套餐定价问题。随着Agent逐渐接管更多开发任务，后台自动执行、任务调度和多智能体协作也开始消耗大量算力，甚至出现用户没有直接感知到任务，却已经消耗了不少使用额度的情况。

今年6月，OpenAI的Codex就曾出现过类似问题。当时，不少用户发现，原本需要一周才能消耗完的使用额度，突然在一两天内就被用完。部分200美元Pro用户表示，过去需要连续工作一周才能用完的额度，后来一天就可能消耗殆尽。

Tibo 随后解释，问题与后台工作量异常有关：自动代码审查和辅助子智能体有时会比预期更频繁地运行，甚至重复执行任务，或者在发生错误后过度重试，导致不必要的算力消耗。此外，Codex仪表盘还曾显示一些实际上并未计入用户账单的活动，进一步加剧了用户对额度异常消耗的困惑。

为此，OpenAI组织了紧急排查，成立专项团队调查问题，部署修复并重置所有用户的使用额度，同时增加后台使用量监控，以便更早发现类似问题。Tibo还表示，团队会为用户额外补充一次额度重置，以弥补此前异常消耗造成的影响。

Anthropic的Claude Code也被发现存在类似问题，只不过消耗发生在一个更加不起眼的环节。

8月15日，一名开发者在Anthropic的Claude Code GitHub仓库提交Issue，要求官方提供一个正式开关，允许用户关闭子智能体状态摘要，而不必牺牲整个子智能体功能。

问题出在Claude Code的后台状态刷新机制。当用户启动多个子智能体时，系统会定期调用模型，为每个活跃智能体生成一条简短状态提示，例如当前正在执行什么任务。按照开发者对Claude Code内部请求的分析，这项机制默认每隔30秒触发一次，每次都会重新提交子智能体的完整对话历史及工具定义，交给模型生成摘要。最终输出通常只有几十个Token，主要用于更新界面中的状态文字，同时帮助用户和Claude Code掌握各个后台智能体的工作进展。

开发者对一次持续4小时、启动27个子智能体的会话进行了抓包分析。在1496次API请求中，有339次属于agent_summary，占全部请求的22.7%；这部分请求产生约6276万原始Token，占总原始Token的22.2%。按照Opus 5的缓存读取、缓存写入和输出价格进行加权后，其成本仍占整个会话约18%。

另一名开发者在使用4个子智能体进行1小时45分钟测试时，也发现了类似问题。其中，一个长期运行的智能体上下文规模达到约38万Token，103次状态摘要请求产生2180万缓存读取Token，占整个会话缓存读取量的26%，但最终输出仅约2100个Token。按照该开发者的测算，仅这个智能体用于生成状态提示，每小时就可能产生约4500万缓存读取Token。

更麻烦的是，这些后台请求设置了skipTranscript: true，通常不会进入常规会话转录文件。因此，依赖会话记录统计消耗的第三方工具可能低估实际Token使用量。用户看到的是智能体状态栏里不断变化的几个词，背后却可能发生了大量上下文读取。

10月28日，开发者“Flamerix AI”也公开了自己的监测结果。通过分析Claude Code的OpenTelemetry遥测数据，其发现，在一周的统计周期内，agent_summary占全部估算费用的16.4%，占API请求总量的19.7%，输入与输出Token比例约为9000:1。换句话说，系统为生成少量状态文字，需要反复读取大量上下文。

Flamerix AI随后发布了一份采用MIT许可证的开源脚本，尝试通过Bun预加载机制拦截相关定时器，在不修改Claude Code二进制文件的情况下关闭状态摘要。该脚本在Linux环境下进行了多个版本测试，关闭摘要后，后台子智能体、Forked Skills和后台会话仍然能够正常运行，只是Agents面板不再持续更新状态文字。不过，这种方式依赖Claude Code内部实现，尚不是Anthropic官方支持的解决方案，后续版本更新也可能使其失效。

随着这件事持续在社区引发讨论，一位自称Claude Code团队成员的Anthropic工程师Edwin Arbus也出面回应。

他解释称，这项机制只针对正在工作的后台智能体，空闲状态的智能体不会持续触发摘要请求。Flamerix AI测得的16.4%可能来自大量使用后台智能体的团队，并不具有普遍代表性。根据Anthropic上一周的遥测数据，在提交遥测信息的Claude Code用户中，agent_summary按照API标价计算约占总成本的2%，占请求总量略低于4%；如果只看终端环境，这一比例约为6%。

不过，Arbus也承认，即使是2%，对于一项主要用于生成状态提示的功能而言，成本仍然偏高。他透露，Anthropic已经在Claude Code 2.1.311及之后的版本中修复了最昂贵的一类情况，即摘要请求未能命中提示缓存的问题。目前团队还在开发一种更便宜的实现方式，不再每次都提交完整对话历史，而是发送简短笔记，再交由更小的模型生成摘要。

不过，这并不意味着后台摘要开销已经完全消除。10月29日，仍有开发者在Claude Code 2.1.312版本上复现了相关请求。另有开发者对30天内129次后台智能体会话进行统计，发现agent_summary约占请求量的14%、估算费用的10%，在一个包含40个智能体的会话中甚至达到24%。

这也说明，问题并非简单的后台请求数量过多，而是上下文规模、缓存命中率、模型选择和刷新频率共同决定了最终成本。对于长期运行的智能体，哪怕每次请求都能命中缓存，反复读取数十万Token的上下文，累计起来仍然是一笔不小的开销。

AI编程工具怎样才能稳定服务？

开发者愿意为AI编程投入大量预算，根本原因还是它可能带来真实的生产力提升。不过，工具使用量增加并不等于收益同比增加，如何衡量投入产出比（ROI）正在成为新的问题。

额度调整对用户产生影响的同时，也会反过来影响AI编程工具厂商自身的商业模式。

固定月费订阅与按量计费有着不同的经济逻辑。对于按Token收费的API业务，用户消耗越多，厂商通常获得越多收入；但对于Pro、Max等固定月费订阅，用户支付的价格相对固定，推理成本却可能随着使用量持续增加。尤其当Agent可以长时间自主运行、并行调用多个子智能体时，少数重度用户就可能产生远高于普通用户的算力成本。

Anthropic的基础设施投入也能说明这种压力。其IPO文件也指出，计算力是Anthropic最大的成本项目，公司未来10年对合作伙伴的算力和基础设施支出承诺超过6000亿美元，其中相当一部分合同不可取消，或不取决于实际使用量。对于这样的厂商而言，算力既是产品供给的基础，也是必须长期管理的重大成本。

因此，收紧额度能够在短期内控制单用户成本、保护订阅业务毛利；提高额度则有利于吸引重度开发者，增强产品黏性，并扩大企业客户使用规模。但如果厂商频繁改变用户已经形成预期的使用权益，就可能损害品牌信任，甚至促使企业建立多供应商策略，降低对单一产品的依赖。

AI编程工具最终卖给开发者的不只是模型能力，更是一种可以持续调用的研发生产力。如果厂商无法让用户准确预测成本，也无法保证关键工作流的持续运行，那么即使模型能力再强，开发者也可能选择限制使用、分散供应商，甚至重新评估采购计划。
