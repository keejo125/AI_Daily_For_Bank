# GitHub 26.8K Star！微信团队开源 ！一套覆盖 RAG、Agent、自动 Wiki 的企业知识底座

来源：AI开源求索
原文链接：https://mp.weixin.qq.com/s/dQucrl2On0yDS1wxzAcAQg

公司资料散落在飞书 Wiki、Notion、语雀、GitLab、本地 Word/PDF 里，到处都是副本。把文档上传到 RAG 系统，只能做到 “检索片段回答问题”。文档切片是黑盒，无法修改分块；知识杂乱无关联，没有统一维护体系；AI 只能回答问题，不能完成多步骤复杂任务；搭建完 AI 助手，还需要用户下载 App、登录网页，使用门槛极高。
现在，微信团队开源的 WeKnora（维娜拉），直接给出一套完整解决方案。它早已不是传统的 AI 文档问答工具，而是面向企业 Agent 的
一体化知识底座
。
01
WeKnora 到底是什么
WeKnora 是腾讯微信团队开源、MIT 许可证发布，基于大模型构建的企业知识管理框架。
基础能力是 RAG 检索问答，但能力边界已经扩展到 ReAct Agent、MCP 协议、Skill 技能沙箱、跨会话长期记忆、自动 Wiki、知识图谱、企业细粒度权限、多数据源同步，深度对接微信生态。
简单一句话概括：
一套系统完成文档采集、解析、知识结构化、检索问答、Agent 任务执行、知识维护，还可以对接公众号、小程序等微信生态入口
。
传统 RAG 产品的定位：上传文档，用户提问，检索片段返回答案。
WeKnora 的定位：把企业散落的海量原始资料，加工成一套可持续迭代、可被多个 Agent 调用的企业知识资产。
它三大核心能力：RAG 快速问答、ReAct Agent、Wiki Mode。
① RAG：混合检索，告别单一向量检索缺陷
底层采用
向量检索 + BM25 关键词检索
，通过 RRF 融合、Rerank 重排提升召回精度，还可以结合知识图谱扩大检索范围。
支持 PDF、Word、Excel、PPT、XMind、图片、Markdown、CSV、JSON 等几乎所有企业常用文件格式。
区别于大多数 RAG 项目切片黑盒问题：WeKnora 保留原始文件夹目录结构，可以像网盘一样浏览、移动、批量打标签。
支持直接编辑单条 Chunk 切片
，如果表格、标题被错误切分，不需要重新上传全量文档，直接修改切片，系统自动重建索引，保留版本记录、支持 diff 对比与回滚。
② ReAct Agent：从 “查资料” 升级为 “完成业务任务”
传统 RAG 只能回答单点问题，WeKnora 内置 ReAct Agent，可以自主规划步骤：判断何时检索知识库、何时调用 MCP 工具、何时联网搜索、何时进入沙箱执行脚本。
举个例子：
普通 RAG：帮我查询公司差旅报销标准。
WeKnora Agent：基于近三年差旅制度，提炼今年变更最大的 5 条规则，生成面向全员的更新说明。
项目 v0.8.0 带来重磅特性：
会话级 Skill 沙箱
。支持 Docker、E2B、Cube 三种运行后端。管理员可从 ClawHub、SkillHub、GitHub、GitLab 或 ZIP 包安装技能。Agent 在独立沙箱内执行 Shell 命令、读写文件、处理附件，生成的文件直接返回对话，不会污染宿主机环境。
同时内置跨会话长期记忆，可区分用户偏好、业务事实、任务记录等不同类型记忆，记忆需要用户确认后才持久化存储，后续对话自动召回。
③ Wiki Mode：自动把零散文档，构建可维护知识体系
企业知识库最大痛点，从来不是缺少文档，而是文档太多、结构混乱。
WeKnora 的 Wiki 模式，让 Agent 自动读取原始资料，提炼实体与关联关系，自动生成互相链接的 Markdown Wiki 页面，同步输出知识图谱。
Wiki 页面支持人工二次编辑、版本管理、回滚。
对比 Obsidian：Obsidian 图谱是人工笔记之间的链接；WeKnora 是
AI 自动从海量原始业务文档生成 Wiki 与图谱
，产出的 Wiki 同时供给 RAG 检索和 Agent 调用。
核心价值转变：从「搜索文档片段」，升级为「自动整理、持续维护一套企业知识体系」。
02
丰富数据源与多渠道分发
数据源同步
支持飞书 Wiki / 云盘、GitLab、Notion、语雀、腾讯 IMA、钉钉文档、RSS 等外部平台一键同步，持续拉取增量资料。
多渠道接入
知识能力可以输出到 Web 页面、网页挂件、CLI、SDK、MCP Server；IM 渠道覆盖微信、企业微信、飞书、钉钉、QQBot、Slack、Telegram；配套 Chrome 浏览器插件，网页文字一键保存入库；支持微信 ClawBot，微信聊天内分享的资料直接存入知识库。
最独特的一点：WeKnora 是
微信对话开放平台核心技术框架
。构建好的知识库 AI 能力，可以直接接入公众号、小程序。
这解决行业一大痛点：很多 AI 助手搭建完成后，用户需要单独注册、访问独立网站，使用门槛高。而微信生态自带成熟身份体系，用户不用额外下载 App，直接在公众号 / 小程序内使用企业 AI 能力。
03
模型与存储完全解耦
WeKnora 没有绑定腾讯混元大模型，模型层完全解耦。OpenAI、DeepSeek、通义千问、智谱、混元、Gemini、MiniMax、Ollama 本地模型全部支持。对话模型、Embedding、Rerank、视觉、语音模型可以分开配置。
存储检索组件同样可替换：
默认使用 PostgreSQL ParadeDB，同时承载业务库、BM25 检索、pgvector 向量检索，新手起步无需额外部署独立向量库。
可按需切换：Elasticsearch、OpenSearch、Milvus、Qdrant、Weaviate、Doris、腾讯云向量库；对象存储支持本地、MinIO、S3、COS、OSS。Redis 负责异步任务、限流、模型并发控制、流式消息。
企业场景价值：今年用 DeepSeek，明年切换千问；敏感业务本地私有化部署，对外服务使用云端模型，底层知识底座不用重构。
配套企业级能力：RBAC 四级权限（Owner/Admin/Contributor/Viewer）、API Key 细粒度权限管控、审计日志、任务面板、模型并发限制、Langfuse 链路追踪。
04
横向对比
市面上几款主流开源 RAG/Agent 平台功能重叠，但定位差异明显：
Dify：侧重 AI 应用编排，可视化画布快速搭建各类 AI 应用
RAGFlow：强项是复杂文档解析、高精度 RAG 检索
MaxKB：轻量化，快速交付可用企业智能问答机器人
WeKnora：聚焦
全生命周期知识管理
。文档导入、切片维护、Wiki 构建、权限审计、链路追踪，一份知识资产同时供给 RAG 问答、Agent 执行、多渠道分发，可作为多个异构 Agent 的统一底层知识层。
重要特性：WeKnora 提供 MCP Server，可作为其他 Agent 的外部知识层；官方提供 DeepSeek Harness 插件，Coding Agent 可以直接调用 WeKnora 知识库。企业内部可以同时部署 DeepSeek Harness、Claude Code 等不同 Agent，共享同一套企业私有知识。

选型参考
✅ 适合选择 WeKnora 场景
需要长期维护企业知识资产，不止一次性搭建问答 Demo
希望 AI 自动整理文档，生成结构化 Wiki 与知识图谱
私有化部署，需要细粒度权限、审计日志、可修改文档切片
多 Agent 共存，需要统一共享的企业知识底座
需要对接微信公众号 / 小程序、多 IM 渠道对外提供 AI 服务
❌ 不推荐场景
只想快速搭建简单 PDF 聊天 Demo：优先 MaxKB
核心诉求是可视化拖拽编排 AI 应用：优先 Dify
全部场景只需要处理复杂 PDF 高精度检索：优先 RAGFlow
07
结尾总结
前两年大家做企业 AI，第一选择永远是挑选大模型。但随着模型能力趋同，企业 AI 落地的瓶颈，已经从模型能力，转移到私有知识治理。
企业独有的资料、项目复盘、历史决策、客户经验，这些大模型训练数据里不存在的内容，才是核心数据资产。
WeKnora 的出现，不是简单新增一个 RAG 开源项目。微信团队把 RAG、Agent、自动 Wiki、知识图谱、技能沙箱、多渠道入口打包成一套 MIT 开源的企业知识底座。
未来企业内部会运行大量不同模型、不同框架的 Agent。而 WeKnora 可以作为统一的知识中枢，让所有 Agent 能够读取、理解企业自己的知识。
下一轮企业 AI 的竞争，比的不再是谁的模型更聪明，而是谁能把散落各处的企业知识，真正交付给 Agent 使用。
