# QCA 最佳实践：为组织协作打造一个超能Runtime

来源：Qoder
原文链接：https://mp.weixin.qq.com/s/HFlkQPyRkKZnVcwqNQLrlw

2026 年 6 月，Anthropic 发布 Claude Tag：Claude 以团队成员的身份进入 Slack。管理员为它配置频道、工具、数据和代码库，团队成员可以通过 @Claude 委派任务；它共享频道上下文、积累相关记忆，并异步推进工作。Anthropic 披露，其产品团队已有 65% 的代码由内部版本的 Claude Tag 产出。
真正打动我们的，不是“把聊天机器人接进群”，而是 AI 与组织关系的变化：它不再停留在个人对话框，而是进入团队共同工作的现场。
基于此，我们在Qoder Cloud Agent（简称QCA）的基础上，快速搭建了一套最佳实现 -- Crew。我们试图回答一个更底层的问题：AI 要在真实组织里长期工作，我们的系统应该处于什么位置，还需要解决哪些问题？
Crew的执行引擎：Qoder Cloud Agents
在展开 QCA Crew 之前，先交代它站在什么之上 -- 因为 “一个 Agent 能不能可靠干活”，已经是一个被解决的问题。
Qoder Cloud Agents 是全托管的 AI Agent 运行平台，依托 Qoder 成熟的 Agent Harness 能力，提供持久 Session、隔离 Sandbox、工具执行和实时事件流，让 Agent 能在云端持续、可靠地推进复杂任务。
了解更多：Qoder Cloud Agents 👇
https://qoder.com/zh/cloud-agents
Crew 不重复建设底层 Agent 运行时，而是在Qoder Cloud Agents提供的Identity、IM Channel、Template等基础之上抽象了团队、成员、权限、资源、协作与记忆等组织语义，把单个 Agent 的执行能力带进真实协作场景。并且所有这些天然发生在云端，用户可以完全摆脱资源、设备等运维依赖。
可以说，Crew 是 Qoder Cloud Agents 在组织协作场景中的一次最佳实践：Qoder Cloud Agents 让 Agent 在云端可靠工作；Crew 让人和 Agent 在组织中自然协作。
个人提效已经发生，组织提效还远未到来
今天的 Agent 已经能写代码、查资料、处理文件、调用工具，甚至独立运行很长时间。但把它拉进一个真实团队，问题很快就会出现：
它以什么身份进入组织、承担什么角色？
面对复杂的组织形态，它如何认识组织，以及组织里的成员与资产？
它如何识别、推进并交付组织中的任务？
安全、权限、审批的边界如何划定？
每次都从零开始，团队的历史决策、协作习惯和隐性知识如何沉淀？
这些问题并不是再换一个更大的模型就会自然消失。模型擅长判断，但组织还需要身份、边界、资源、关系和长期上下文。
未来组织的瓶颈，可能不是缺少更聪明的 Agent，而是缺少一套让人和 Agent 能够持续协作的组织机制。
那么，AI 应该从哪里进入组织？
一个关键入口：IM
在目前的现状里，组织协作并不发生在新的 AI 工作台，大家每天使用的 IM 就是一个零门槛的天然入口。
所以 Crew 没有再造一个新工作台，而是让 AI 直接进入群聊：会聊天就会用，零学习成本；讨论历史就是任务背景，上下文天然在场；群是团队边界、成员是协作关系、@ 是任务指派，组织语义现成可用。
Claude Tag 选择长在 Slack 里，也体现了同样的判断；
最自然的 AI 协作，不是让人适应新工具，而是让 AI 进入人们已经习惯的工作现场。
智能的真相，不一定要像海啸般摧枯拉朽，也可能会在我们最熟悉的地方潜移默化、润物无声。
接下来看看，Crew 如何让 AI 在团队中像伙伴一样相处。
一个核心理念：一半世界交给结构，一半世界交给智能
组织级 Agent 容易走向两个极端：每一步都预先编排成工作流，系统可控但难以应对变化；完全交给模型，表现灵活却可能失去边界。Crew 在两者之间划出清晰分工。
静态复杂度由系统结构化，动态复杂度由 AI 在授权边界内自主判断。
组织复杂度可以拆成两类，它们需要不同的解法。
这也是 Crew 最重要的设计取舍。我们不希望用越来越庞大的流程编排，把 AI 重新变成一段僵硬程序；也不会把所有事情都交给模型自由发挥。
边界越清楚，AI 越自由。
在这个数字组织，有什么不一样
1. 人与 Agent 统一为 Member：协作语义平权
Crew 不把人和 Agent 建模成两个割裂的世界。在 Team 中，双方都是 Member，拥有同样的四类协作原语：身份、访问、记忆、工具。人负责判断、授权和最终决策；Agent 擅长持续观察、处理信息和执行任务。
协作因此不再是“人问、AI 答”的单线关系：成员可以直接交办、转交和补充任务；Agent 在需要决策时请求确认，人也能随时纠正、暂停或终止执行。
2. Dialogue：把混流群聊还原成多条工作主线
同一个群里，告警排查、需求讨论和资料整理常常交错发生。Crew 不依赖平台 thread，而是用 Dialogue 模型表达一件正在推进的事。
新消息会被归入已有 Dialogue，或为新事情创建 Dialogue。每个 Dialogue 拥有独立的会话与执行上下文，避免话题串线：
话题内串行：同一 Dialogue 一次只运行一个 Turn，后续消息可选择排队归并 or 引导打断。
话题间并行：不同 Dialogue 可以同时推进，互不阻塞。
追问回到原话题：引用和后续补充进入正确的上下文。
3. 从一句话到真实交付
Crew 不是知识库问答的另一层皮肤，而是把群里的一句话接成一条可观察、可恢复的执行链路：
消息进入
：统一接入、幂等去重。
主动性判断
：结合身份、职责与近期消息，选择回应、轻量反馈或保持安静。
上下文装配
：AI 自主在数字组织内探索，按需组合当前话题、相关记忆和授权资源。
云端执行
：通过 Qoder Cloud Agents 在隔离 Sandbox 中调用工具、读写文件、运行命令和测试。
可靠出站
：结果和产物先落库再投递，失败可重试。
得益于 Qoder Cloud Agents 的强大引擎，每一个Dialogue背后都可以是一个高性能的 Agent Team 在帮你推进复杂任务，24小时随时 Standby。
4. 过程可见，方向可改
长任务最怕黑盒。Crew 用流式卡片展示 Todo 进度和关键步骤，让团队知道正在做什么、已经完成什么、还剩什么。
方向需要调整时，成员可以直接追加要求；Runtime 会把新指令带入当前任务继续推进。需要立即停止时，也可以直接取消。
自主不等于失控。可观察、可干预、可终止，才是组织敢于委派长任务的前提。
5. 记住重要的，而不是保存一切
Crew 不把聊天记录无限塞进上下文，而是把眼前的连续性与长期认知分开处理：
话题上下文（Dialogue Context）：保留当前话题的消息、引用和执行记录，保证本次协作连续。
情景信息（Episode）：提炼关键事件、结论和时间线，作为后续记忆候选。
长期记忆（Memory）：只沉淀稳定、可复用且会影响未来协作的团队事实与成员认知。
长期记忆按团队和成员分别组织。每次新协作只装配当前话题、团队记忆和相关成员记忆，不把全部历史塞进上下文。
随着协作积累，Crew 会逐渐理解团队的规则、偏好、职责和工作方式，越来越像一个真正熟悉团队的数字同事。
综合以上，这些机制最终收敛成四种可以直接感知的体验：入口自然、理解团队、能够交付、持续成长。
连接 Qoder 的个人、Agent 与组织能力
我们正在尝试形成一套从个人到组织的 Agent 能力体系：
Qoder 面向人类开发者，理解代码库、协同编码，并自主完成研发任务。
Qoder Cloud Agents 面向 Agent，提供托管运行时、持久 Session、工具和隔离 Sandbox。
QCA Crew 面向人与 Agent 协作的组织，提供身份、关系、记忆和治理边界。
可以把这条路径概括为：
Qoder 赋能人类，Qoder Cloud Agents 赋能 Agent，Crew 赋能人与 Agent 协作的组织。
想提升个人研发效率，可以从 Qoder 开始；正在构建长期运行的 Agent，可以关注 Qoder Cloud Agents；希望 AI 进入团队、参与真实协作，欢迎体验 Crew。
现在到哪了，接下来去哪
当前版本先聚焦一个可验证闭环：打通 IM 消息进入、话题理解、云端执行、过程反馈和结果回群，并提供幂等、恢复和观测等基础保障。在此之上，可寻址 Mailbox 与 Agent 任务分派、多 Dialogue 并发与公平调度、独立 Memory Worker、出入站仲裁、多发送者渲染等高级能力也已经 Ready。

结语
