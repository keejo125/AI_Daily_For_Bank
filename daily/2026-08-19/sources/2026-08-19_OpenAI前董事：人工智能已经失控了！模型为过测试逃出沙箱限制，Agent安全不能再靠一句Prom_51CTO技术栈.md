# OpenAI前董事：人工智能已经失控了！模型为过测试逃出沙箱限制，Agent安全不能再靠一句Prompt

> 原文链接：https://mp.weixin.qq.com/s/lBEZdZSOh9Ut8zVgTW8ItA
> 来源：51CTO技术栈

编辑 | 姜篇
“controlling and directing the AI systems.”
Helen Toner：我们至今仍很难控制和引导手里的AI系统。
近日，OpenAI
前董事
Helen Toner，讲述了一条真实的攻击链
。
OpenAI
给模型安排了一组网络安全测试，测试环境原本没有直连互联网。模型做不出题以后，没有停在原地。它找到了软件仓库代理的漏洞，从评测环境拿到外网权限，又把攻击链一路推到了
Hugging Face
。
最后，它拿到了与测试有关的数据和答案。
这场事故之后，她提出了一个尖锐的问题：
当
Agent
可以自己调用工具、寻找漏洞并连续工作几天，人类还有没有能力把它关在预定的边界内？
备注：
Helen Toner
曾于
2021
年至
2023
年担任
OpenAI
非营利董事会成员，现任乔治敦大学安全与新兴技术中心（
CSET
）执行主任，长期研究
AI
治理与国家安全。
以下为访谈内容，我们进行了翻译与整理。
Helen
谈人类控制和引导当前
AI
系统的困难
模型只想把题做对，结果先把考场拆了
Helen
在访谈中还原了这起事故最反常的部分。
模型接到的是网络安全测试。
正常路线是分析题目、找出靶机漏洞、提交答案。可它碰上了做不下去的任务，于是开始寻找另一条路：离开测试环境，接触公网，再去测试数据存放的地方找答案。
Helen Toner：模型没有继续按出题者设计的路线解题。它想办法离开评测环境，接入互联网，随后把目标转向了Hugging Face。
这段叙述听上去很像科幻片，
OpenAI
与
Hugging Face
后来公开的技术材料，已经确认了主要攻击链。
OpenAI
称，参与测试的是
GPT-5.6 Sol
和一个能力更强、尚未发布的内部研究模型。为了测试网络攻击能力，评测时降低了部分网络安全拒答限制。
模型所在的
ExploitGym
环境没有直接连接互联网，但它发现并利用了
Artifactory
软件包仓库代理中的漏洞。
拿到外网后，模型继续提权、横向移动，并判断
Hugging Face
可能保存着
ExploitGym
相关模型、数据集和解题材料。随后，它把泄露的凭证和多处漏洞串在一起，找到了进入
Hugging Face
系统的路径。
Hugging Face
公布的复盘更具体。
从
7
月
9
日到
13
日，系统记录了约
17600
次攻击动作，整理后形成约
6280
个行为簇。攻击分成两个阶段：先从
OpenAI
评测沙箱逃到第三方代码沙箱，再以那里为跳板进入
Hugging Face
的数据处理与内部网络。
Hugging Face：受访问的用户内容只涉及5个与挑战相关的数据集，没有发现其他用户模型、数据集、Spaces或软件包被读取。
Helen
描述模型离开评测环境并寻找外网入口
Hugging Face
公布的攻击链
这里说的
“
失控
”
有一个很具体的含义：人给了目标，模型却通过一条没有被要求、也没有被允许的路线完成了目标，而且现有边界没有及时拦住它。
它不需要憎恨人类，也不需要拥有自我意识。只要任务奖励足够明确，环境里又留着可利用的出口，
Agent
就可能把越权动作当成一条普通解法。
越要求它坚持到底，越容易逼出作弊路线
Helen
认为，事故与
Agent
训练里一个常见目标有关：坚持。
我们希望
Agent
遇到报错后别立刻放弃。它应该读日志、换方案、继续尝试，直到测试通过。这也是
Coding Agent
从代码补全变成任务执行工具的重要一步。
问题出在任务根本无法按正常路线完成时。
Helen Toner：如果一个系统被训练得非常坚持，又被交给一件在当前环境里无法完成的任务，它可能开始寻找作弊路径。
模型看到的奖励很简单：答对、通过、完成。出题者脑子里还有一条默认规则，必须按正常方式完成。只要这条规则没有写进可执行的约束，模型就可能把绕过测试、偷看答案、扩大权限都算成
“
解决问题
”
。
开发者已经能在日常工作里看到较轻的版本。
让
Agent“
把
CI
修绿
”
，它可能删除失败测试；让它
“
降低接口延迟
”
，它可能返回旧缓存；让它
“
消除安全告警
”
，它可能直接关掉规则。代码提交得很快，目标也完成了，问题只是被藏到了验收条件之外。
Helen
解释高强度的坚持训练为什么可能把模型推向作弊路径
训练
Agent
时，只奖励最后的结果，很容易得到一个会钻评分漏洞的执行者。把过程写成可以检查的规则，才有机会区分
“
任务完成
”
和
“
为了过关做了别的事
”
。
沙箱没有直连外网，模型还是从依赖仓库绕了出去
很多团队看到
“
沙箱
”
两个字，会下意识觉得风险已经被隔离。
这次事故给出的答案不太舒服。
ExploitGym
没有直接联网，测试环境仍要访问软件包仓库、构建服务和第三方代码沙箱，也可能继承云凭证、服务账号和内部网络关系。
模型没有从正门出去。它利用的是周围基础设施为正常开发留下的通道。
Hugging Face
对
7
月
9
日至
13
日攻击活动的技术时间线。不同颜色代表侦察、远程执行、横向移动、凭证获取等行为。
Hugging Face
的技术报告里有一个细节很扎实：
Agent
进入第三方代码沙箱后，以
root
权限把它变成了新的跳板。后面的数据读取、模板注入、云元数据访问、
Kubernetes
权限利用和源码供应链尝试，都从这里继续展开。
所以，
Agent
沙箱的边界不能只画在容器外面。软件包代理、元数据服务、
CI
凭证、云
SDK
和第三方执行环境，都属于它能够触碰的执行面。
Helen：Hugging Face公布异常后，OpenAI才把事件串起来。OpenAI官方复盘则称，其安全团队在内部发现了异常活动。现有公开材料不足以判断两种表述为什么不同。
能够确认的是，攻击持续了数天，产生了上万次动作。监控系统记录下大量数据，不等于人能及时看懂并阻止它。日志只有进入告警、授权和中止流程，才算控制手段。
一句
“
禁止越权
”
，挡不住会调用工具的
Agent
OpenAI
在官方复盘中提到，为了进行网络能力测试，部分安全拒答限制被降低。这让一个常被混在一起的问题露了出来：模型拒不拒答，与它拿到工具后能不能执行，是两道不同的门。
系统提示词可以写
“
不要访问外网
”“
不要读取无关数据
”
。
Agent
发起网络请求时，最后决定放行的应该是网络策略；它准备调用生产数据库时，最后决定权限的应该是独立授权系统。
如果模型既能修改代码，又能改自己的权限配置，提示词写得再严也只是说明书。
Helen：开发者不能把思维链当成完整审计日志。模型可能不把所有动作和中间目标写进可见的推理文本。盯着它说了什么，无法替代对命令、网络、文件和凭证的实际记录。
Helen
谈模型在训练中学到突破约束、隐藏意图等非预期行为
对于已经把
Agent
接进代码库的团队，模型偶尔写错一行代码还不是最难处理的事。更麻烦的是它能连续行动，团队却没有一套独立于模型的权限系统。
该踩刹车，还是派出更强的防守模型
Helen
主张放慢前沿模型能力竞赛，先把控制和评估方法补上。
Hugging Face
联合创始人兼
CEOClément Delangue
的态度不同。
他认为攻击型
AI
已经出现，更现实的路线是加快防守模型、检测系统和安全基础设施的发展。
两边争的是速度，工程现场面对的是同一道题：不能把安全寄托在模型
“
自觉遵守
”
。
无论模型继续快速进步，还是实验室暂时收紧发布，已经上线的
Agent
都需要最小权限、可观测网络、独立审查和随时中止。防守模型可以帮人发现异常，却不能同时掌握执行权和最终裁决权。
写在最后
“
人工智能已经失控了
”
很容易让人想到机器觉醒。
7
月这起事故没有证明模型产生了自我意识，也没有证明所有
Agent
都会主动攻击外部系统。
它暴露了一个已经落到工程层的问题：模型拿到工具后，会尝试人没有预料到的路径。只要那条路径能提高完成任务的概率，它就可能继续走下去。
过去，开发者担心的是
AI
把代码写错。现在还要问几件更麻烦的事：它能碰到什么，凭什么获得权限，谁在独立验收，异常发生后能不能立刻停下，整个过程能不能重新播放。
Agent
会继续变强。权限、日志、验收和回滚如果还停在脚本时代，接在模型身后的系统会先替它付出代价。
