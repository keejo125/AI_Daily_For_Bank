# 从 Jev 到 QCA：Qoder Sites 让 Web 拥有双重智能

来源：Qoder
原文链接：https://mp.weixin.qq.com/s/xc5mMBVU1TD2RUkwpIzDFA

Jev 带来了一个很有意思的启发：智能并不仅仅是语言，也可以是对情境的判断、对行动的选择，以及对变化的及时反应。
这款由 TypeSafe 推出的模型，把重点放在快速、结构化的决策上。它让人看到另一种 AI 应用方式：智能不必总以对话的形式出现，也可以藏在搜索、筛选和一次按钮点击背后。
为了把这种能力变成可体验的产品，作者用 Qoder 提供的 Web 应用创建与发布能力
Qoder Sites
，做了一个 Laya Playground：基于同样面向结构化决策的开源模型 Laya，自行部署模型服务，并在公司内部免费开放体验。
随着应用不断迭代，一个更大的问题逐渐浮现：当网页既能低成本地快速判断，又能借助云端 Agent 推理、调用工具和完成复杂任务，Web 会变成什么样？
01 Jev 的启发：把智能的单位，从一次问答缩小到一次判断
Jev 属于 TypeSafe 所称的 System One 模型。这个名字来自“快思考与慢思考”的区分：System 1 强调快速、直觉式判断，System 2 强调审慎、多步推理。
它和常见聊天模型的区别，不只是回答更短。Jev 放弃自由文本生成，由开发者预先定义问题与可能的输出，模型返回类型受约束的答案和概率，并以并行方式计算输出。它优化的是软件中的判断任务，而不是写出一篇更好的回答。
分类、评分、选择下一条处理路径，原本也能请大语言模型完成。但如果最终只需要一个标签，为此反复生成和解析文字，就可能付出不必要的时间与计算成本。
System One 路线吸引人的地方，是把这些判断做得足够轻。
当调用成本和延时降下来，AI 的使用单位就可以从“一次完整对话”，缩小到“一次局部交互”。
我们可以把判断放进更频繁、更细小的交互——输入材料时识别意图，浏览内容时调整排序，游戏进行时选择下一步动作。
这种变化对产品的意义，比“回答更快一点”大得多。过去，用户需要专门发起一次 AI 请求；沿着这条路径，智能可以在用户完成原本操作的过程中自然发生。
局部智能：用户仍在使用网页，但判断已经发生在交互之中
02 用 Qoder Sites，把模型变成一个能体验的 Web
模型能力值得讨论，但只有真正使用起来，才能看清它适合放在哪里。
Qoder 是一款 AI 编程产品。
Qoder Sites 则把 Web 应用的创建、预览和发布串成了一个流程
：用自然语言描述需求，在 Qoder 中生成并修改代码、查看效果，再发布成可以访问的站点。
需要调用模型或外部服务时，可以通过后端函数连接，让密钥留在服务端。这样，用户就能把想法逐步变成可交互的 Web 应用。
这次实践中，作者用 Sites 做的 Laya Playground，包含多语言模型工作台，以及斗地主、五子棋和 2048 等小游戏。Laya 与 Jev 的能力和评测不能直接等同，这个应用主要用于体验结构化判断如何进入交互。
工作台解决的是“怎样看懂一次判断”。左侧编辑材料与问题，右侧呈现候选项、概率或评分结果；切换中、英、日文示例，可以观察不同表达对输出的影响。
小游戏则把同一种能力放进了连续变化的环境。
Laya Playground 的真实界面局部：模型工作台与三款游戏。
在游戏里，程序负责生成合法候选、维护局面；Laya 负责选择动作。一次选择执行后，程序更新状态，再发起下一次判断。模型本身不需要包办整个游戏，仍然可以让网页获得局部智能。
这也让作者看到了一条边界：
连续调用模型，并不自动等于具备规划能力。
当前一步看起来合理，整局下来未必占优；而当用户想研究原因、收集证据、比较多种方案时，单次分类接口就不够用了。
此时网页需要另一类能力：能够围绕目标组织过程，并根据执行反馈继续工作。
03 QCA：从“给出答案”到“完成工作”
Qoder Sites 已内置对
Qoder Cloud Agents（QCA）
的接入支持。QCA 是云端全托管 Agent 平台，支持 API、SDK、MCP 等接入方式，让应用能够调用云端 Agent 执行任务。
它不是另一个与 Jev 对比大小的模型。它的核心价值，可以概括为
LLM + Harness + 云原生
。
LLM
是大语言模型，负责理解目标、分析信息、决定下一步。
Harness
是围绕模型组织任务的运行系统。它管理上下文、衔接工具调用，并把执行结果交回模型，让复杂任务能够持续推进。
云原生能力
提供托管运行环境、会话隔离和任务状态管理，减少使用方在底层资源与 Agent 运行环境上的运维工作。
LLM 决定下一步，Harness 组织工具与反馈，云端环境承载执行
这让 Sites 生成的网页能够承接更长的工作过程。用户提交一个目标后，应用可以逐步呈现进度、证据和产物，直到形成报告、文件或可继续操作的数据。
回到 Laya Playground，就可以设想一个自然的扩展：把模型测试页升级为实验助手。用户提供一组样本，要求比较不同问法的效果。QCA 负责安排步骤，调用受控的 Laya 测试工具，保存逐项结果，汇总差异，再提出值得进一步验证的方向，在设定的范围内继续验证，最终形成实验报告。
这个设想清楚地说明了两种能力的关系：Laya 完成一次次判断，QCA 围绕目标组织这些判断，并利用反馈持续工作。实验是否改善效果，仍需由测试数据验证。
如果说前面的轻量智能把使用单位缩小到“一次判断”，那么 QCA 承载的推理与执行，就让应用有机会把服务单位扩展到“一项任务”。
这就是 System 2 式能力对 Web 的加持：用更充分的推理和实际行动，让应用能够完成用户的复杂任务。
QCA 也正在加入面向 System 1 的
Decision API
，将快速、结构化的判断与云端 Agent 的推理执行汇集到同一平台。届时，开发者可以按需调用两类 AI 能力：用 Decision API 处理高频决策，用 Agent 完成复杂任务，让应用既能快速响应，也能持续推进工作。
04 “1＋2”的价值，在于知道什么时候值得多想一步
有了两类能力，下一步就要决定：怎样让它们配合？
一个直觉是，先用轻量模型处理，不行再交给 Agent。这是一种可行路径，但远远不是全部。
用户要求给一条内容分类，可能只需一次判断；用户明确要求做一份研究报告，可以直接进入 Agent 流程；Agent 执行过程中，也可以把大量重复、边界清楚的判断交给轻量模型。
真正的问题是：
在这个时刻，多投入一些推理与执行，能否带来值得的结果改善？
Russell 与 Wefald 关于“理性元推理”的研究提供了一个有用视角：计算步骤本身也可以被看作决策，应当评估继续计算的预期价值，以及时间等成本。
把这个思想放进产品设计，同样一次“多想一步”，在不同任务里的价值可能完全不同。
对一个可随时调整的内容标签，快速给出可用判断或许更重要；对一份要据此作出决定的分析报告，补充证据、核对来源和重新计算，可能更值得等待。
因此，如何分配计算，需要同时考虑任务难度、错误代价、时间预算和实际评测。模型的置信度可以提供信号，但不能独自承担这项决定。
两条能力路径按需使用，也可在同一项任务中协作
由此再看“1＋2”，它的意义就更具体了。
轻量模型让高频判断有机会做得更快、更经济；QCA 让更复杂的推理能够连接工具，转化为实际产出。Sites 则让开发者把这种分工做成用户可以理解和操作的应用。
评价它们，也要回到各自承担的工作：单次判断看准确性、校准、延时；完整任务看完成率、总耗时、人工介入，以及每个可接受结果的成本。
最后这一项尤其值得重视。成本包含模型运行，也包含人的等待、核验与返工。一次调用便宜，却把后续工作全部留给用户，整体未必更经济。
双重智能真正要优化的，是用户完成一件事所需的总代价。
05 从一次实验，看到 AI 原生 Web 的可能性
从轻量判断到云端执行，这套能力组合，与互联网上恒河沙数的 Web 站点天然契合。
第一，智能会进入更多过去不值得做的小场景。
一个需求能不能变成软件，往往要看它产生的价值，能否覆盖开发、维护、运行和纠错的成本。
一个只持续两周的项目，一次活动，一组需要反复处理的数据，可能确实需要专用工具，却很难承担从头开发和维护的投入。最后，人们往往选择用表格、文档和手动操作把流程串起来。
Sites 缩短应用创建与交付的过程，轻量模型尝试降低高频判断的开销，QCA 提供可以复用的 Agent 执行基础。它们分别作用于不同成本，却可能共同改变一个小需求是否值得实现。
这意味着，软件有机会向更具体的工作靠近：围绕一批实验样本做一个研究工作台，围绕一次活动做一个互动应用，围绕团队的固定资料做一个分析工具。
第二，Web 的交互会更多地融合“操作”与“委托”。
轻量判断适合融入即时操作，Agent 适合承接需要持续推进的目标。两者结合以后，用户与应用之间就可以形成更丰富的协作方式。
用户表达目标，Agent 开展工作；结果落在表格、图表和报告中，用户直接修改；这些修改又成为下一轮执行的输入。
这与人机交互研究中的“混合主动式界面”一脉相承：将自动化能力和用户的直接操控结合，让用户能够引导、修正和控制自动化过程。
在这样的应用里，聊天适合说明意图，表格适合逐项比较，图表适合发现变化，文件适合保存和交付。不同交互共同围绕任务组织起来。
这也让网页拥有新的价值：它可以保留工作的上下文。
用户选中了哪些样本，调整了什么条件，一张图依据哪一版结果，都可以成为人与 Agent 共享的状态。上下文越明确，用户需要反复解释的内容就越少，Agent 能够有效行动的范围也越清楚。
到了这一步，AI 原生 Web 的轮廓逐渐清晰：Sites 帮助人创建应用，轻量模型参与应用中的细小判断，QCA 支撑更长的推理与执行。用户既能亲自操作，也能把一段工作委托出去，并在同一个界面上检查和使用成果。
从 Jev 带来的启发，到 Laya Playground 的实践，再到 QCA 打开的执行空间，这条路径表明：一个网页可以很轻，背后却能有层次地组织智能。
当快速判断融入交互，当推理与执行接上反馈，Web 就有机会从“提供功能”，进一步走向“与用户共同完成工作”。
