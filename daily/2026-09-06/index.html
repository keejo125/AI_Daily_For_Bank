首次曝光！OpenAI新一代旗舰模型换上“循环深度”推理架构：用计算深度换参数规模
InfoQ
据《The Information》援引知情人士，OpenAI 即将推出的旗舰模型 Astra 采用“循环深度”（recurrent depth / 循环 Transformer）技术，在输出下一个词前将文本在同一网络层多次循环处理，用较小模型等效庞大模型性能，显著降低内存与带宽成本。研究显示，35 亿参数循环深度模型在推理时可等效最高约 500 亿参数模型的算力。该技术方向与 Latent Reasoning（潜空间推理）一致，让模型在连续数学表示空间而非人类语言中推理，但副作用是思维链不可读，加重安全担忧。奥特曼此前已因 Astra“能力过强”主动暂停训练。Astra 内部版本据称攻克 10 道悬置十年的数学与理论计算机难题，算力成本约 2000 美元，证明均形式化为 Lean 证书。
GitHub 发布 Project HydraFusion：Copilot CLI 中按任务生成工作流的运行时多模型编排
MarkTechPost
GitHub 发布 Project HydraFusion 研究预览，将模型选择从“一次性设置”升级为“按请求生成执行计划”的多模型编排：可令一个模型起草、另一个批判，或在质量门禁失败时升级到更强模型，模型来自多家供应商。当前仅集成于 GitHub Copilot CLI，按各模型标准费率按 token 计费，不开源、不可自托管。其本质是“薄编排层 + 多模型执行流”的编程智能体范式，与“薄 Agent Loop、厚 Control Plane”理念相呼应。

Perplexity 详解 GPU Embedding 服务栈：Ivy、Tulip 与 ROSE 如何支撑 pplx-embed
MarkTechPost
Perplexity 工程团队披露 pplx-embed 及其排序模型的 GPU embedding 服务架构。核心结论是：在 Hopper/Blackwell 等成熟硬件上，embedding 推理引擎已趋同，性能差异落在运行时与 harness 层——包括 CUDA graph 管理、异步结果追踪抽象与 Rust 请求路径。团队将服务拆为两类流量：构建/重建向量库的批处理（吞吐优先）与查询时在线 embedding（延迟优先），并复用同一引擎，折射出大规模检索系统“小 Transformer + 运行时优化”的工程取向。

OpenAI
OpenAI 发布内部观察文章，披露 coding agents 正在重塑其 AI 研究流程，围绕 agent 使用率、实验速度、任务复杂度与研究加速给出早期数据。文章指向一个趋势：研发组织借助编码智能体提升实验迭代与探索效率。对金融机构构建“智能研发”工作流具有方法学借鉴意义——将 agent 前置到研究探索环节，以自动化实验与代码生成加速研发闭环。
UC Berkeley 开源 CUA-Lite：统一沙箱、数据、评估与强化学习的计算机使用智能体平台
MarkTechPost
UC Berkeley 团队开源 CUA-Lite，一个面向计算机使用智能体（CUA）的统一平台，将智能体、环境、轨迹与评估框架收敛到同一动作空间、数据模式与命令，覆盖桌面/浏览器/移动端。其最具价值的部分是 Lite.OSWorld：用普通 Docker 容器内的 GNOME 桌面复现 OSWorld 任务套件与评测器，内存从 4.1GB 降至 0.9GB、免去对 /dev/kvm 嵌套虚拟化的依赖，使云主机、CI、嵌套容器均可运行，显著降低 CUA 训练与基准成本。
微软 Foundry 模型路由扩容：覆盖区域增至 28 个，更新模型池
InfoQ
微软扩展 Foundry Models 模型路由器：全球标准部署可用区域由 2 个增至 28 个、数据区域增至 21 个，模型池新增 Anthropic Claude Opus 4.8 与 GPT-5.6 系列、移除若干到达生命周期终点的旧模型。路由器提供均衡/质量优先/成本优先三种模式，默认“均衡”自动生效且可退出。需关注的是：有效上下文窗口等于池中最小窗口，新增小窗口模型会拉低整体上限；且路由决策仅基于文本，图片不影响选择、音频不受支持——对依赖长上下文与多模态的企业级编排需留意约束。
谷歌云发布 AI 智能体，简化数据库生命周期管理
InfoQ
谷歌云发布由 Gemini 驱动的数据库运维智能体，包含上线智能体（Onboarding Agent）与可观测性智能体（Observability Agent），深度集成 Gemini Cloud Assist，支持 AlloyDB、Bigtable、Spanner 等多款托管数据库。上线智能体可理解 IOPS、延迟限制、复制延迟等指标，按工作负载特征推荐数据库方案并生成部署命令；可观测性智能体面向 SRE/DevOps，自动关联 Database Insights、Cloud Monitoring、Cloud Logging、Cloud Trace 等遥测数据，数分钟内给出根因分析，并在工程师确认后执行修复。相关能力可通过 Gemini 聊天界面、云控制台、CLI 及 Antigravity 等 IDE 使用，也可经 MCP 服务器接入现有工作流。

“薄 Agent Loop，厚 Control Plane”：TiDB 用数据库思维重做 Harness
InfoQ
TiDB 团队基于数据库可靠性哲学构建面向 Agent 的基础设施 TiDB Cloud Filesystem，将 Workspace 从 Session/Sandbox 生命周期中独立，提供数据库级持久化、版本、分支、回滚与权限控制，即使 Sandbox 被回收，新 Executor 也能接管同一份状态继续任务，目前已承载数百万个 Agent Workspace。TiDB 唐刘将其设计哲学概括为“薄 Agent Loop，厚 Control Plane”：Agent Loop 变化最快、最易同质化，可基于开源项目；而状态、权限与副作用边界必须稳定。他还提出多 Agent 协作应“通过状态共享而非消息广播”，推崇 Unix 式安静协作，并强调“Fail Fast 比 Retry 更重要”，以控制错误被不断重试后放大成系统雪崩。
